### 자기소개

반복되는 불편을 발견하면, 필요한 기술을 배워 직접 개선하는 개발자입니다.

프론트엔드 업무에서 API 문서와 실제 응답을 다시 확인해야 하는 문제를 겪고, 개인 프로젝트에서 OpenAPI 기반 타입 생성을 적용했습니다. 배포 과정도 직접 이해하고 싶어 Docker와 AWS를 구성하고 GitHub Actions로 연결했습니다.

최근에는 취업 준비 과정의 공고 수집과 문서 비교를 돕는 서비스를 만들며 Cloudflare Workers와 n8n, LLM API를 사용하고 있습니다. 직접 사용하며 발견한 본문 누락과 분석 상태 표시 문제를 AI 코딩 도구와 함께 개선하고 있습니다.

### 관련 프로젝트

#### 취업 준비 관리 서비스 · Career Ops

2026.09 - 진행 중 · 개인 프로젝트, AI 코딩 도구 활용

공고 수집, 이력서·포트폴리오 관리, AI 비교와 면접 준비를 연결한 개인용 서비스입니다.

- Cloudflare Workers에 관리자 인증과 요청 검증, 실행 상태·결과 저장을 두고, n8n으로 공고 수집·PDF 처리·AI 호출·callback 흐름을 구성했습니다.
- 직접 사용하며 n8n 실행 상태와 관리자 분석 상태가 다르게 보이는 문제를 확인했습니다. AI와 함께 원인을 점검하고, 결과 검증 실패를 종료 상태로 기록하는 처리와 오래 멈춘 작업의 복구 경로를 보완했습니다.
- 공고 본문 누락·안내 문구 혼입을 발견해 파서와 회귀 테스트를 보완하고, 분석에 사용한 문서 버전과 원문 인용을 확인하는 코드를 추가했습니다.
- 타입·테스트·빌드·DB 검사를 오프라인 검증 명령으로 묶고, 장애별 확인 순서와 배포 절차를 문서화했습니다. 해당 검증은 2026.09.20 통과했으며, 최신 배포 자동화의 운영 검증은 별도로 남아 있습니다.

주요 기술: TypeScript, Next.js, Cloudflare Workers, n8n, Supabase, Docker

#### story-dict

2024.10 - 2025.01 · 개인 프로젝트 · 이후 배포·캐시 개선

단어나 표현을 질문하고 지식을 공유하는 웹 서비스입니다. 학습·기술 검증 후 유지 비용을 고려해 운영을 종료했습니다.

- Next.js와 NestJS를 Docker 이미지로 구성하고, GitHub Actions에서 ECR 업로드와 EC2 배포를 연결했습니다. RDS·S3와 네트워크·도메인 구성을 직접 다루며 배포 흐름을 익혔습니다.
- 같은 소스를 반복 빌드하는 문제를 줄이기 위해 Turborepo와 S3 캐시, 기존 ECR 이미지 재사용을 적용했습니다. 설정과 선택 이유를 블로그에 기록했습니다.
- NestJS의 OpenAPI 명세에서 프론트엔드 타입을 생성하고 API 요청 계층에 연결했습니다. 실무에서 겪은 계약 불일치를 개인 프로젝트로 검증한 뒤 팀에 도입안을 제안했습니다. 실무 적용은 우선순위상 보류됐습니다.

주요 기술: TypeScript, Next.js, NestJS, Docker, AWS, GitHub Actions, OpenAPI

#### jabaek · 자백

2026.07 - 진행 중 · 개인 프로젝트, AI 코딩 도구 활용

AI 용의자와 대화하며 증거와 진술을 비교하는 웹·모바일 추리 게임입니다.

- Next.js, Expo WebView, Supabase로 웹·모바일 서비스를 구성했습니다. AI와 기획·구현을 진행하며 게임 규칙과 사용자 흐름, 검증 범위를 정했습니다.
- AI 작업 중 같은 정책을 서로 다르게 구현하는 문제를 줄이기 위해 영역별 정책 원본을 정하고, 요구사항 ID로 관련 테스트와 구현 위치를 연결했습니다.
- 외부 AI 응답의 형식 검증과 서비스 규칙에 따른 상태 판단을 분리했습니다. 문서와 코드의 연결을 검사하는 명령을 CI에 연결했습니다.

주요 기술: TypeScript, Next.js, Expo, Supabase, Zod, LLM API

### 인물상과 증명 순서

자기소개에서 약속한 것은 “새 기술을 빨리 안다”가 아니라 “불편을 발견하고 필요한 것을 배워 개선한다”입니다.

| 보여줄 성향             | 본문에서 증명하는 내용                       |
| ----------------------- | -------------------------------------------- |
| 직접 써보며 문제를 찾음 | Career Ops의 본문 누락·상태 불일치 발견      |
| 필요한 영역까지 학습함  | story-dict의 API 명세·컨테이너·AWS 배포      |
| 같은 불일치를 줄이려 함 | OpenAPI 타입 생성, jabaek의 정책·테스트 연결 |
| 기존 환경을 고려함      | 오픈놀의 점진적 레거시 개선과 협업           |

개인 프로젝트의 사용자 수, 팀 피드백, 처리 시간 절감률은 넣지 않았습니다. 실제 받은 피드백이 없다는 사용자 설명을 반영했습니다.

### 2페이지로 옮길 때

첫 페이지는 자기소개와 Career Ops·story-dict를, 두 번째는 jabaek·경력·학력을 우선 배치합니다. 넘치면 기술 목록과 교육 설명부터 줄이고, 각 프로젝트의 문제와 해결 문장은 남깁니다. 프론트엔드 상세 구현은 기존 포트폴리오를 참고 링크로 연결합니다.

### 확인하면 더 좋아지는 부분

1. **경력 개월 수:** 기존 PDF의 “2년 4개월”은 입·퇴사 일자 확인 후 사용합니다. 현재 초안은 확인 가능한 월별 재직 기간만 유지했습니다.
2. **story-dict 기간:** PDF에는 2025.01까지, README에는 2025.09까지 후속 기록이 있습니다. 핵심 개발과 후속 개선 기간을 구분해 확정합니다.
3. **jabaek 출시:** 기존 PDF에 Google Play 출시 경험이 있으나 이 작업에서는 스토어 상태를 확인하지 않았습니다. 출시 URL·시점이 확인되면 “Google Play 출시”를 첫 항목에 추가할 수 있습니다.
4. **운영 로그 사례:** Career Ops에서 직접 본 오류와 AI가 분석한 원인을 나눠 설명합니다. 독립적인 장애 분석 경험으로 제출하려면 실행 한 건을 직접 따라 확인한 기록을 추가합니다.
5. **Cloudflare 범위:** Workers API 구현 경험으로 표현했습니다. Cloudflare 제품 전반의 운영, Terraform·Datadog·Langfuse 사용 경험은 기재하지 않았습니다.
6. **문서화:** 작성한 문서가 있다는 사실은 사용할 수 있습니다. 다른 사람이 그 문서로 운영했다는 성과는 확인 전까지 넣지 않습니다.
