# 본문과 MDX 규칙

## 문체와 정확성

- 한국어로 쓰고 기존 블로그의 친근한 `해요`체를 기본으로 한다.
- 문단을 짧게 유지하되 한 문장마다 강제로 줄을 나누지 않는다.
- 과장된 소개보다 문제, 판단 근거, 코드와 결과를 구체적으로 설명한다.
- 직접 수행하지 않은 실험, 경력, 장애 경험, 인터뷰, 인용을 지어내지 않는다.
- 라이브러리 버전, 최신 API, 보안 권고처럼 변할 수 있는 내용은 공식 문서나 1차 자료로 확인한다.
- 의견과 검증된 사실을 구분하고, 불확실한 내용은 불확실하다고 표시한다.

## 권장 구성

주제에 맞게 다음 흐름을 조합한다.

1. 글에서 다룰 내용 또는 결론 한 줄
2. 문제와 배경
3. 핵심 개념이나 해결 방법
4. 실제 코드, 설정, 이미지 또는 비교
5. 주의점과 한계
6. 정리와 다음 행동

모든 글에 같은 제목을 복사하지 않는다. 회고는 상황, 선택, 결과, 배운 점 중심으로 바꿀 수 있다.

## 제목과 TOC

- frontmatter의 제목이 페이지 제목이므로 본문에 `#`를 반복하지 않는다.
- 주요 섹션은 `##`, 하위 섹션은 `###`, 필요한 세부 단계만 `####`를 사용한다.
- TOC는 본문의 `##`~`####`를 정규식으로 수집한다. 복잡한 JSX를 제목 안에 넣지 않는다.
- 기존 스타일과 맞을 때 `## {이모지} {제목}`, `### {숫자 이모지} {제목}`을 사용할 수 있지만 모든 제목에 억지로 적용하지 않는다.

## 전역 MDX 컴포넌트

`apps/blog/mdx-components.tsx`에 등록된 다음 컴포넌트는 import 없이 사용한다.

### 안내 블록

허용 타입은 `info`, `tip`, `success`, `error`, `warning`이다.

```mdx
<Blockquote type="warning">
  운영 환경에 적용하기 전에 공식 마이그레이션 문서를 확인해 주세요.
</Blockquote>
```

일반 Markdown `>`도 커스텀 blockquote로 렌더링된다. 단순 한 줄 요약에는 `>`를, 의미별 강조가 필요할 때 `<Blockquote>`를 사용한다.

### 링크 미리보기

```mdx
<LinkPreviewCard href="https://example.com/docs" />
```

- 독자가 공식 문서나 관련 글로 이동할 가치가 있을 때 사용한다.
- 본문에서 출처가 무엇인지 먼저 설명하고 카드만 단독으로 나열하지 않는다.
- 외부 URL이 실제로 존재하는지 확인한다.

### 코드 블록

언어를 지정하고 실행에 필요한 문맥을 코드 주변에 설명한다.

````mdx
```tsx showLineNumbers {2-4}
export function Example() {
  return <div>예시</div>;
}
```
````

- 비밀값은 예시 값으로 치환한다.
- 생략으로 인해 실행할 수 없는 코드는 부분 예시임을 밝힌다.
- 오래된 API를 예시로 제시해야 하면 대상 버전을 명시한다.

## 링크와 이미지

- 내부 글은 `/posts/...` 루트 기준 경로로 연결한다.
- 외부 기술 근거는 공식 문서, 표준, 원 논문, 원 저장소를 우선한다.
- 이미지 Markdown에는 화면 내용을 설명하는 대체 텍스트를 넣는다.
- 줄바꿈은 빈 줄로 문단을 구분하고, 의미상 같은 문단 안에서만 `<br />`를 사용한다.

## 최종 점검

- 도입부가 제목과 description의 질문에 바로 연결되는지 확인한다.
- 코드와 설명의 변수명, 버전, 파일 경로가 서로 일치하는지 확인한다.
- 결론에 본문에서 다루지 않은 새 주장을 추가하지 않는다.
- TODO, placeholder, 가짜 URL, 빈 코드 블록과 닫히지 않은 JSX 태그가 없는지 검색한다.
