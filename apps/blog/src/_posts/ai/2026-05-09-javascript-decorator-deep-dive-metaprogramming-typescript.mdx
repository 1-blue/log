## 🚀 JavaScript Decorator, 왜 알아야 할까요?

### 0️⃣ 메타프로그래밍의 강력한 도구
Decorator는 클래스, 메서드, 프로퍼티, 파라미터 등에 적용하여 해당 대상의 동작을 확장하거나 수정하는 특별한 종류의 선언이에요.<br />
마치 Higher-Order Component(HOC)나 Higher-Order Function(HOF)처럼 기존 코드를 감싸서 새로운 기능을 추가하거나, 동작 방식을 변경하는 데 사용하죠.<br />
이를 통해 코드의 반복을 줄이고, 로깅, 권한 검사, 유효성 검사, 성능 측정 등 여러 관심사를 핵심 비즈니스 로직과 분리하여 관리할 수 있게 도와줘요. 이러한 기법을 **메타프로그래밍**이라고 부른답니다.

### 1️⃣ 타입스크립트에서의 활발한 사용
현재 Decorator는 JavaScript의 Stage 3 프로포절이지만, 타입스크립트에서는 이미 오랫동안 활발하게 사용되어 왔어요.<br />
특히 Angular, NestJS, MobX와 같은 인기 있는 프레임워크나 라이브러리에서 Decorator를 적극적으로 활용하여 간결하고 선언적인 API를 제공하고 있어요.<br />
만약 Decorator가 없었다면, 우리는 수많은 boilerplate 코드를 작성하거나, 복잡한 래퍼 함수를 일일이 만들어야 했을 거예요.<br />
Decorator를 이해하는 것은 이러한 프레임워크들을 더 깊이 이해하고, 나아가 자신만의 재사용 가능한 코드를 만드는 데 큰 도움이 될 거예요.

<Blockquote type="tip">
**tsconfig.json 설정 안내**<br />
타입스크립트에서 Decorator를 사용하려면 `tsconfig.json` 파일에 다음 옵션을 추가해야 해요.<br />
```json
{
  "compilerOptions": {
    "experimentalDecorators": true, // Decorator 문법 사용 활성화
    "emitDecoratorMetadata": true  // Decorator 메타데이터 방출 (reflect-metadata 사용 시 필수)
  }
}
```
</Blockquote>

## ⚙️ Decorator의 핵심 동작 원리

### 0️⃣ Decorator는 결국 함수입니다
Decorator는 사실 특별한 구문을 가진 함수일 뿐이에요.<br />
런타임에 호출되어 Decorator가 적용된 대상(클래스, 메서드 등)에 대한 정보를 인자로 받고, 그 대상을 수정하거나 새로운 대상을 반환하는 방식으로 동작해요.<br />
즉, 컴파일 시점에 또는 런타임에 코드의 구조나 동작을 동적으로 조작하는 메타프로그래밍의 한 형태라고 할 수 있어요.

### 1️⃣ 다양한 종류의 Decorator 살펴보기
Decorator는 적용되는 대상에 따라 받는 인자의 형태와 역할이 달라져요.<br />
주요 Decorator는 다음과 같아요.<br />

*   **클래스 Decorator**: 클래스 선언 바로 위에 적용되며, 클래스 생성자를 인자로 받아 클래스 자체를 확장하거나 교체할 수 있어요.<br />
*   **메서드 Decorator**: 메서드 선언 바로 위에 적용되며, 메서드가 속한 `target` 객체, 메서드 이름(`propertyKey`), 그리고 메서드의 `PropertyDescriptor`를 인자로 받아 메서드의 동작을 변경할 수 있어요.<br />
*   **프로퍼티 Decorator**: 프로퍼티 선언 바로 위에 적용되며, `target` 객체와 프로퍼티 이름(`propertyKey`)을 인자로 받아 프로퍼티의 메타데이터를 추가하거나 초기화할 수 있어요.<br />
*   **파라미터 Decorator**: 메서드 파라미터 앞에 적용되며, `target` 객체, 메서드 이름(`propertyKey`), 파라미터의 인덱스를 인자로 받아 파라미터에 대한 메타데이터를 추가할 수 있어요.<br />
*   **접근자 (Accessor) Decorator**: Getter/Setter에 적용되며, 메서드 Decorator와 유사한 인자를 받아요.

이 중에서 클래스, 메서드, 프로퍼티 Decorator가 가장 흔하게 사용된답니다.

## 🛠️ 타입스크립트 Decorator 실전 활용 예시

이제 실무에서 유용하게 사용할 수 있는 Decorator 예시들을 살펴볼게요.

### 0️⃣ 로깅 Decorator: 메서드 호출 추적
메서드가 호출될 때마다 해당 메서드의 이름과 인자, 그리고 반환 값을 자동으로 로깅하는 Decorator를 만들어볼게요.<br />
이는 디버깅이나 애플리케이션의 흐름을 파악하는 데 매우 유용해요.

```tsx showLineNumbers
// log.decorator.ts
function LogMethod(target: any, propertyKey: string, descriptor: PropertyDescriptor) {
  const originalMethod = descriptor.value; // 원본 메서드를 저장해요.

  // 원본 메서드를 새로운 함수로 교체해요.
  descriptor.value = function (...args: any[]) {
    console.log(`[Log] 호출 시작: ${propertyKey} (${JSON.stringify(args)})`);
    const result = originalMethod.apply(this, args); // 원본 메서드를 호출해요.
    console.log(`[Log] 호출 종료: ${propertyKey} (결과: ${JSON.stringify(result)})`);
    return result;
  };

  return descriptor; // 수정된 PropertyDescriptor를 반환해요.
}

// user.service.ts
class UserService {
  @LogMethod // getUser 메서드에 LogMethod Decorator를 적용했어요.
  getUser(id: number): { id: number; name: string } {
    console.log(`실제 getUser 로직 실행 (ID: ${id})`);
    return { id, name: `User-${id}` };
  }

  @LogMethod // createUser 메서드에도 적용했어요.
  createUser(name: string): { id: number; name: string } {
    console.log(`실제 createUser 로직 실행 (Name: ${name})`);
    const newId = Math.floor(Math.random() * 1000); // 간단한 ID 생성
    return { id: newId, name };
  }
}

const userService = new UserService();
console.log("--- getUser 호출 ---");
userService.getUser(1);
console.log("--- createUser 호출 ---");
userService.createUser("블루");

/* 실행 결과
--- getUser 호출 ---
[Log] 호출 시작: getUser ([1])
실제 getUser 로직 실행 (ID: 1)
[Log] 호출 종료: getUser (결과: {"id":1,"name":"User-1"})
--- createUser 호출 ---
[Log] 호출 시작: createUser (["블루"])
실제 createUser 로직 실행 (Name: 블루)
[Log] 호출 종료: createUser (결과: {"id":XXX,"name":"블루"})
*/
```

위 예시처럼 `@LogMethod` Decorator를 한 번 정의해두면, 어떤 메서드든 `@LogMethod`만 붙이면 자동으로 로깅 기능을 추가할 수 있어요.<br />
메서드 내부 로직을 수정할 필요 없이 기능을 확장하는 것이죠. 정말 편리하지 않나요?

### 1️⃣ 디바운싱 Decorator: 성능 최적화
사용자의 입력이나 특정 이벤트가 너무 자주 발생할 때, 불필요한 함수 호출을 줄여 성능을 최적화하는 기법을 디바운싱(Debouncing)이라고 해요.<br />
이 디바운싱 기능을 Decorator로 구현해볼게요.

```tsx showLineNumbers
// debounce.decorator.ts
function Debounce(delay: number) {
  // Decorator 팩토리 패턴: 인자를 받아서 실제 Decorator 함수를 반환해요.
  return function (target: any, propertyKey: string, descriptor: PropertyDescriptor) {
    const originalMethod = descriptor.value;
    let timeoutId: ReturnType<typeof setTimeout> | null = null;

    descriptor.value = function (...args: any[]) {
      clearTimeout(timeoutId!); // 이전 타이머를 초기화해요.
      timeoutId = setTimeout(() => {
        originalMethod.apply(this, args); // 지정된 delay 후에 원본 메서드를 호출해요.
      }, delay);
    };

    return descriptor;
  };
}

// search.service.ts
class SearchService {
  @Debounce(500) // 500ms 동안 추가 호출이 없으면 search 메서드를 실행해요.
  search(query: string): void {
    console.log(`[Search] 검색 요청: ${query}`);
    // 실제 검색 API 호출 로직...
  }
}

const searchService = new SearchService();
console.log("--- 디바운스 테스트 시작 ---");
searchService.search("a");
searchService.search("ap");
searchService.search("app"); // 500ms 이내에 계속 호출되므로, 이전 호출은 무시돼요.

setTimeout(() => {
  searchService.search("apple"); // 600ms 후 호출되므로, "app" 호출 후 500ms 뒤에 실행돼요.
}, 600);

setTimeout(() => {
  searchService.search("banana"); // "apple" 호출 후 500ms 이내에 호출되므로, "apple"은 무시돼요.
}, 700);

setTimeout(() => {
  console.log("--- 디바운스 테스트 종료 ---");
}, 1500);

/* 예상 실행 결과
--- 디바운스 테스트 시작 ---
(약 500ms 후) [Search] 검색 요청: app
(약 500ms 후) [Search] 검색 요청: banana
--- 디바운스 테스트 종료 ---
*/
```

`@Debounce(500)`처럼 인자를 받는 Decorator는 Decorator 팩토리 패턴을 사용해요.<br />
이는 Decorator 함수를 반환하는 함수를 의미하며, 이를 통해 Decorator에 동적인 설정을 전달할 수 있답니다.

### 2️⃣ 클래스 Decorator: 메타데이터 추가
클래스 Decorator는 클래스 자체에 메타데이터를 추가하거나 클래스를 확장하는 데 사용돼요.<br />
NestJS와 같은 프레임워크에서는 `@Controller`, `@Injectable` 같은 Decorator를 사용하여 클래스의 역할을 정의하고, 런타임에 이 정보를 활용하여 의존성 주입이나 라우팅을 설정하죠.<br />
여기서는 간단히 클래스에 기본 경로(base path) 메타데이터를 추가하는 예시를 보여드릴게요.<br />
이 예시에서는 `reflect-metadata` 라이브러리가 필요해요. 먼저 설치해 주세요: `npm install reflect-metadata` 또는 `yarn add reflect-metadata`.

```tsx showLineNumbers {1, 3-4, 15, 23, 27}
import "reflect-metadata"; // 메타데이터를 사용하기 위해 가장 먼저 임포트해야 해요.

const routeMetadataKey = Symbol("route"); // 메타데이터의 고유 키를 정의해요.
const methodRouteMetadataKey = Symbol("method_route");

// Controller Decorator: 클래스에 기본 경로 메타데이터를 추가해요.
function Controller(path: string) {
  return function <T extends { new (...args: any[]): {} }>(constructor: T) {
    // Reflect.defineMetadata를 사용하여 클래스에 메타데이터를 정의해요.
    Reflect.defineMetadata(routeMetadataKey, path, constructor);
    // 클래스를 확장하여 추가적인 로직을 넣을 수도 있어요.
    // 예를 들어, 모든 컨트롤러 인스턴스에 공통 속성을 주입한다거나요.
    return class extends constructor {}; // 원본 클래스를 확장한 클래스를 반환해요.
  };
}

// Get Decorator: 메서드에 HTTP GET 경로 메타데이터를 추가해요.
function Get(path: string) {
  return function (target: any, propertyKey: string, descriptor: PropertyDescriptor) {
    // 메서드에 메타데이터를 정의해요. 실제 라우팅 프레임워크에서는 이 정보를 바탕으로 라우트를 등록하죠.
    Reflect.defineMetadata(methodRouteMetadataKey, path, target, propertyKey);
    console.log(`[Decorator] ${target.constructor.name}.${propertyKey} -> GET ${path} 라우트 등록 예정`);
  };
}

@Controller("/products") // ProductController에 기본 경로 /products를 설정했어요.
class ProductController {
  @Get("/") // getAllProducts 메서드에 GET / 라우트를 설정했어요.
  getAllProducts() {
    return { data: [{ id: 1, name: "Laptop" }] };
  }

  @Get("/:id") // getProductById 메서드에 GET /:id 라우트를 설정했어요.
  getProductById(id: number) {
    return { data: { id, name: `Product-${id}` } };
  }
}

// 실제 애플리케이션에서는 Reflect.getMetadata를 통해
// 클래스 및 메서드의 메타데이터를 가져와 라우터를 구성하겠죠.
const controllerPath = Reflect.getMetadata(routeMetadataKey, ProductController);
console.log(`ProductController의 기본 경로: ${controllerPath}`); // 출력: /products

// 메서드의 메타데이터도 가져올 수 있어요.
const getAllProductsPath = Reflect.getMetadata(methodRouteMetadataKey, ProductController.prototype, "getAllProducts");
console.log(`getAllProducts 메서드의 경로: ${getAllProductsPath}`); // 출력: /

// ProductController 인스턴스를 생성하면 Get 데코레이터의 로그가 출력돼요.
const productController = new ProductController();
productController.getAllProducts();
```

이처럼 Decorator를 사용하면 클래스와 메서드에 추가적인 정보를 선언적으로 부여할 수 있으며, 이 정보는 런타임에 `reflect-metadata` 라이브러리를 통해 조회하여 다양한 로직에 활용될 수 있어요.<br />
이는 프레임워크 개발이나 복잡한 시스템 아키텍처를 설계할 때 매우 강력한 도구가 된답니다.

## 💡 JavaScript Decorator의 미래와 주의사항

### 0️⃣ Stage 3 프로포절: JavaScript 표준으로
현재 타입스크립트에서 사용되는 Decorator는 구 버전의 프로포절을 기반으로 하고 있어요.<br />
JavaScript 표준화를 위한 Decorator 프로포절은 현재 Stage 3 단계에 있으며, 타입스크립트의 기존 Decorator와는 몇 가지 중요한 차이점이 있답니다.<br />
주요 변경점으로는 Decorator 함수의 시그니처가 변경되고, 적용 대상에 대한 접근 방식이 더 명확하고 안전하게 개선될 예정이에요.<br />
미래에는 별도의 타입스크립트 설정 없이도 순수 JavaScript 환경에서 Decorator를 사용할 수 있게 될 거예요. 하지만 그때까지는 타입스크립트의 `experimentalDecorators` 옵션이 필요해요.

### 1️⃣ 사용 시 주의할 점
Decorator는 강력한 도구이지만, 잘못 사용하면 오히려 코드의 복잡성을 높일 수 있어요.<br />

*   **복잡성 증가**: 과도하게 많은 Decorator를 사용하거나, Decorator 내부 로직이 복잡해지면 코드의 흐름을 파악하기 어려워질 수 있어요.<br />
*   **디버깅의 어려움**: Decorator는 추상화 계층을 추가하기 때문에, 예상치 못한 버그가 발생했을 때 디버깅이 까다로울 수 있답니다.<br />
*   **성능 오버헤드**: Decorator 내부 로직이 무겁거나 런타임에 많은 연산을 수행한다면, 애플리케이션의 초기 로딩 시간이나 런타임 성능에 영향을 줄 수 있으니 주의해야 해요.<br />
*   **표준화 변경 가능성**: 아직 Stage 3 단계이므로, 최종 JavaScript 표준 스펙은 현재와 약간 다르게 변경될 가능성이 있다는 점을 염두에 두셔야 해요.

## 📝 정리하며: Decorator, 현명하게 활용해요

### 0️⃣ 핵심 요약
*   **Decorator**는 클래스, 메서드 등에 선언적으로 기능을 추가하거나 수정하는 **메타프로그래밍** 기법이에요.<br />
*   코드의 **중복을 제거**하고, **관심사 분리**를 통해 **코드 가독성**과 **재사용성**을 높이는 데 기여해요.<br />
*   **타입스크립트** 환경에서 Angular, NestJS 등 많은 프레임워크와 라이브러리에서 강력하게 활용되고 있어요.<br />
*   현재 **JavaScript Stage 3 프로포절**이며, 곧 표준 기능으로 편입될 예정이에요.<br />
*   하지만 **과도한 사용은 코드 복잡성**을 높이고 **디버깅을 어렵게** 만들 수 있으니, 신중하고 현명하게 활용하는 것이 중요해요.

### 1️⃣ 다음 스텝
Decorator는 한 번에 모든 것을 이해하기보다는 실제 코드를 작성하고 적용해보면서 익히는 것이 가장 효과적이에요.<br />
오늘 배운 내용을 바탕으로 자신만의 Decorator를 만들어 보거나, 기존 프레임워크에서 Decorator가 어떻게 사용되는지 코드를 분석해보는 것을 추천해요.<br />
또한, 최신 JavaScript 표준화 동향을 꾸준히 살펴보는 것도 중요하답니다.
