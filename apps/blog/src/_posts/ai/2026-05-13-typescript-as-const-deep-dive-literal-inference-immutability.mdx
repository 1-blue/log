## 🤔 TypeScript `as const`, 왜 중요할까요?

TypeScript를 사용하면서 타입 안정성을 확보하는 것은 너무나 중요해요. 하지만 때로는 TypeScript의 기본 타입 추론 방식이 우리가 의도한 것보다 넓게 타입을 추론해서 예상치 못한 버그를 유발하거나, 코드를 이해하기 어렵게 만들 때가 있어요.<br />

<br />
특히 상수(constant)를 정의하거나 설정 객체를 만들 때, TypeScript가 기본적으로
추론하는 타입은 우리가 원하는 '정확한 리터럴 타입'이 아닌, 더 넓은 '원시 타입'이
되는 경우가 많아요. 이런 상황에서 `as const`는 마치 마법처럼 동작하며 코드의
타입 안정성을 극대화해 준답니다.

### 0️⃣ `as const` 없이 경험하는 타입 추론의 아쉬움

먼저 `as const`가 없을 때 어떤 아쉬움이 있는지 간단한 예시로 살펴볼까요?<br />
우리가 애플리케이션의 상태를 나타내는 문자열 상수를 정의한다고 가정해 봐요.

```tsx showLineNumbers
const STATUS_PENDING = "PENDING";
const STATUS_SUCCESS = "SUCCESS";

let currentStatus = STATUS_PENDING; // currentStatus의 타입은 string으로 추론돼요.

currentStatus = "FAIL"; // 아무런 타입 에러 없이 할당 가능해요.
// 만약 "FAIL"이 유효하지 않은 상태라면, 런타임에서 문제가 발생할 수 있어요.

const userConfig = {
  name: "블루",
  age: 10,
};

userConfig.name = "레드"; // 허용돼요.
// 만약 userConfig가 불변이어야 한다면, 이 역시 문제가 될 수 있어요.
```

<Blockquote type="info">
  위 코드에서 `STATUS_PENDING`은 `"PENDING"`이라는 문자열 리터럴이지만,
  TypeScript는 이를 더 넓은 `string` 타입으로 추론해요. 마찬가지로 `userConfig`
  객체의 속성들도 `string`, `number`와 같은 일반적인 타입으로 추론되죠.
  <br />
  이러한 넓은 타입 추론은 유연성을 제공하지만, 개발자가 의도하지 않은 값의
  변경을 막지 못해서 잠재적인 런타임 오류로 이어질 수 있어요.
</Blockquote>

### 1️⃣ 실무에서 `as const`가 필요한 순간들

그렇다면 실무에서는 언제 `as const`가 필요할까요? 주로 다음과 같은 상황에서 빛을 발해요.<br />

<br />
1. **설정 객체(Configuration Objects) 정의:** 애플리케이션 전반에 걸쳐 사용되는
불변의 설정값을 정의할 때, 각 속성의 값을 정확한 리터럴 타입으로 만들고 싶을 때
사용해요.
<br />
2. **상수 배열 또는 튜플:** 특정 순서와 값을 가지는 상수 리스트를 정의하고, 그
값이 변경되지 않도록 보장하고 싶을 때 유용해요.
<br />
3. **액션 타입(Action Types) 정의:** Redux와 같은 상태 관리 라이브러리에서 액션
타입을 정의할 때, 문자열 리터럴 타입을 정확하게 추론시켜 타입 안정성을 높일 수
있어요.
<br />
4. **제한된 옵션 목록:** 드롭다운 메뉴나 특정 컴포넌트의 프로퍼티로 사용될 수
있는 제한된 문자열 또는 숫자 리터럴 목록을 정의할 때 활용해요.
<br />
<br />
결론적으로 `as const`는 코드의 의도를 타입 시스템에 명확하게 전달하여, 개발자의
실수를 줄이고 코드의 신뢰성을 높이는 데 필수적인 도구라고 할 수 있어요.

## 🚀 `as const`의 핵심 원리와 동작 방식

`as const`는 TypeScript의 타입 추론 동작을 변경하는 특별한 구문이에요. 특정 값 뒤에 `as const`를 붙이면, TypeScript는 해당 값에 대해 가능한 한 가장 좁은(specific) 타입을 추론하게 돼요. 또한, 이 값은 **불변(Readonly)**으로 취급된답니다.

### 0️⃣ 리터럴 타입 추론 강화

일반적으로 TypeScript는 변수에 할당된 리터럴 값을 더 넓은 타입으로 추론해요. 예를 들어, `"hello"`는 `string`으로, `123`은 `number`로 추론하죠. 하지만 `as const`를 사용하면 이러한 추론 방식이 바뀌어요.

```tsx showLineNumbers {1-2}
const greeting = "hello"; // greeting의 타입은 string
const GREETING = "hello" as const; // GREETING의 타입은 "hello" (리터럴 타입)

const num = 123; // num의 타입은 number
const NUM = 123 as const; // NUM의 타입은 123 (리터럴 타입)

// 리터럴 타입은 해당 값 외의 다른 값을 할당할 수 없게 만들어요.
// GREETING = "world"; // Error: Cannot assign to 'GREETING' because it is a read-only property.
// NUM = 456; // Error: Cannot assign to 'NUM' because it is a read-only property.
```

<Blockquote type="tip">
  `as const`를 사용하면 변수의 타입이 해당 리터럴 값으로 고정되기 때문에, 다른
  값을 할당하려는 시도를 타입스크립트가 미리 감지해서 에러로 알려줘요. 이는
  런타임 에러를 방지하는 데 아주 효과적이에요.
</Blockquote>

### 1️⃣ 불변성(Readonly) 부여

`as const`의 또 다른 중요한 역할은 객체나 배열에 **재귀적으로 불변성을 부여**하는 것이에요. 즉, 객체의 모든 속성이나 배열의 모든 요소가 `readonly`로 선언된 것처럼 동작하게 만들죠.

```tsx showLineNumbers {5}
const user = {
  name: "블루",
  age: 10,
  hobbies: ["코딩", "독서"],
};
// user의 타입은 { name: string; age: number; hobbies: string[] }

const IMMUTABLE_USER = {
  name: "블루",
  age: 10,
  hobbies: ["코딩", "독서"],
} as const;
// IMMUTABLE_USER의 타입은 { readonly name: "블루"; readonly age: 10; readonly hobbies: readonly ["코딩", "독서"] }

// IMMUTABLE_USER.name = "레드"; // Error: Cannot assign to 'name' because it is a read-only property.
// IMMUTABLE_USER.hobbies.push("운동"); // Error: Property 'push' does not exist on type 'readonly string[]'.

const COLORS = ["red", "green", "blue"]; // string[]
const IMMUTABLE_COLORS = ["red", "green", "blue"] as const; // readonly ["red", "green", "blue"] (튜플 타입)

// COLORS.push("yellow"); // 허용돼요.
// IMMUTABLE_COLORS.push("yellow"); // Error: Property 'push' does not exist on type 'readonly ["red", "green", "blue"]'.
```

<Blockquote type="success">
  `as const`는 객체 내부의 중첩된 객체나 배열에도 `readonly` 속성을 전파해서,
  복잡한 데이터 구조의 불변성을 한 번에 확보할 수 있게 해줘요. 이는 특히 설정
  객체나 상태 정의 시 예상치 못한 데이터 변경을 방지하는 데 매우 유용해요.
</Blockquote>

## 🛠️ `as const` 실전 활용 가이드

이제 `as const`를 실무 코드에 어떻게 적용할 수 있는지 구체적인 예시와 함께 알아볼게요.

### 0️⃣ 상수 객체 정의와 활용

애플리케이션에서 특정 상태나 옵션을 나타내는 상수 객체를 정의할 때 `as const`를 사용하면 타입 안전성을 크게 높일 수 있어요.

```diff-tsx showLineNumbers {1-10}
-const USER_ROLES = {
-  ADMIN: "ADMIN",
-  EDITOR: "EDITOR",
-  VIEWER: "VIEWER",
-};
-
-type UserRole = (typeof USER_ROLES)[keyof typeof USER_ROLES];
-
-function assignRole(role: UserRole) {
-  console.log(`Assigning role: ${role}`);
-}
-
-assignRole("SUPER_ADMIN"); // 타입 에러가 발생하지 않아요! 😨
+const USER_ROLES = {
+  ADMIN: "ADMIN",
+  EDITOR: "EDITOR",
+  VIEWER: "VIEWER",
+} as const;
+
+type UserRole = (typeof USER_ROLES)[keyof typeof USER_ROLES]; // "ADMIN" | "EDITOR" | "VIEWER"
+
+function assignRole(role: UserRole) {
+  console.log(`Assigning role: ${role}`);
+}
+
+assignRole("SUPER_ADMIN"); // Type Error: Argument of type '"SUPER_ADMIN"' is not assignable to parameter of type '"ADMIN" | "EDITOR" | "VIEWER"'. ✨
assignRole(USER_ROLES.ADMIN); // 정상 작동해요.
```

<Blockquote type="info">
  `as const`를 사용하지 않았을 때는 `UserRole`이 `string`으로 추론되어
  `USER_ROLES`에 없는 `"SUPER_ADMIN"`도 허용되었어요. 하지만 `as const`를
  적용하면 `UserRole`이 정확한 리터럴 유니온 타입으로 추론되어, 잘못된 값을
  전달할 경우 즉시 타입 에러를 발생시켜 준답니다.
</Blockquote>

### 1️⃣ 배열 및 튜플의 불변성 확보

상수 배열이나 튜플을 정의할 때도 `as const`는 매우 유용해요. 특히 함수의 인자로 전달될 때 불변성을 보장해야 하는 경우에 말이죠.

```tsx showLineNumbers {1, 6, 12-13}
const PERMISSIONS = ["read", "write", "delete"] as const;

type Permission = (typeof PERMISSIONS)[number]; // "read" | "write" | "delete"

function checkPermission(userPermissions: readonly Permission[]) {
  // userPermissions는 읽기 전용 배열이에요.
  // userPermissions.push("execute"); // Error: Property 'push' does not exist on type 'readonly Permission[]'.
  console.log("User permissions:", userPermissions);
}

const userPerms = ["read", "write"] as const;
checkPermission(userPerms); // 정상 작동해요.

// checkPermission(["read", "update"]); // Error: Type '"update"' is not assignable to type 'Permission'.
```

<Blockquote type="tip">
  `as const`를 통해 `PERMISSIONS`는 `readonly ["read", "write", "delete"]`
  타입이 되고, `Permission` 타입은 이 리터럴들의 유니온 타입으로 정확히
  추론돼요. `checkPermission` 함수는 `readonly Permission[]` 타입을 인자로 받아,
  함수 내부에서 배열의 변경을 시도하는 것을 막아준답니다.
</Blockquote>

### 2️⃣ 함수 파라미터와 제네릭에서의 응용

`as const`는 제네릭 타입과 함께 사용될 때 더욱 강력한 타입 추론을 가능하게 해요. 특히 객체 리터럴을 인자로 받는 함수에서 유용하죠.

```tsx showLineNumbers {1-11, 14, 18}
function createAction<T extends { type: string; payload: unknown }>(action: T) {
  return action;
}

const ADD_TODO_ACTION = createAction({
  type: "ADD_TODO",
  payload: { id: 1, text: "Learn as const" },
});
// ADD_TODO_ACTION의 type은 string으로 추론돼요.

const ADD_TODO_ACTION_AS_CONST = createAction({
  type: "ADD_TODO",
  payload: { id: 1, text: "Learn as const" },
} as const);
// ADD_TODO_ACTION_AS_CONST의 type은 "ADD_TODO" (리터럴 타입)으로 추론돼요!

type ActionType = typeof ADD_TODO_ACTION_AS_CONST.type; // "ADD_TODO"

function handleAction(actionType: ActionType) {
  console.log(`Handling action of type: ${actionType}`);
}

handleAction("ADD_TODO"); // 정상 작동해요.
// handleAction("REMOVE_TODO"); // Type Error: Argument of type '"REMOVE_TODO"' is not assignable to parameter of type '"ADD_TODO"'.
```

<Blockquote type="info">
  `createAction` 함수에 `as const`를 적용한 객체를 전달하면, 제네릭 `T`가 더
  좁은 리터럴 타입으로 추론되어 `ADD_TODO_ACTION_AS_CONST.type`의 타입이 정확히
  `"ADD_TODO"`가 돼요. 이를 통해 `handleAction` 함수에서 잘못된 액션 타입을
  사용하는 것을 컴파일 시점에 방지할 수 있어요.
</Blockquote>

## ⚠️ `as const` 사용 시 주의사항

`as const`는 강력하지만, 몇 가지 주의할 점도 있어요.

### 0️⃣ 타입 가드와 런타임 동작의 분리

`as const`는 컴파일 시점에 타입 추론을 돕는 도구이지, 런타임에 값의 불변성을 강제하는 것은 아니에요. JavaScript 코드는 여전히 해당 값을 변경할 수 있다는 점을 인지해야 해요.

```tsx showLineNumbers {1-7, 10-11}
const CONFIG = {
  API_KEY: "abc",
  DEBUG_MODE: true,
} as const;

// 실제로 CONFIG는 JavaScript 객체이므로 런타임에는 변경될 수 있어요.
// CONFIG.API_KEY = "xyz"; // TypeScript 에러 발생.
// 하지만 Babel이나 다른 트랜스파일러를 통해 타입 체크 없이 JS로 변환되면,
// 런타임에는 CONFIG.API_KEY = "xyz"; 와 같은 코드가 동작할 수 있어요.

// 만약 런타임 불변성을 정말로 보장해야 한다면, Object.freeze()를 사용해야 해요.
const FROZEN_CONFIG = Object.freeze({
  API_KEY: "abc",
  DEBUG_MODE: true,
});
// FROZEN_CONFIG.API_KEY = "xyz"; // 런타임에서 에러는 아니지만, 엄격 모드에서는 TypeError를 발생시키고 값은 변경되지 않아요.
```

<Blockquote type="warning">
  `as const`는 타입 시스템 내에서 불변성을 보장하지만, 실제 JavaScript
  런타임에서는 `Object.freeze()`와 같은 명시적인 조치를 취해야만 객체의 불변성을
  확실히 보장할 수 있어요. TypeScript의 역할은 개발자의 실수를 컴파일 시점에
  잡아주는 것이라는 점을 기억해 주세요.
</Blockquote>

### 1️⃣ 과도한 사용은 지양해요

`as const`는 강력하지만, 모든 변수에 무분별하게 적용하는 것은 좋지 않아요. 특히 변경될 가능성이 있는 변수에 사용하면 오히려 코드를 유연하지 못하게 만들 수 있어요.<br />

<br />
예를 들어, 사용자 입력 값을 저장하는 변수나, 동적으로 변경될 수 있는 상태 값에는
`as const`를 사용하지 않는 것이 좋아요. `as const`는 주로 애플리케이션의 상수,
설정 값, 또는 불변성이 보장되어야 하는 데이터 구조에 사용하는 것이 가장
효과적이랍니다.

## 📝 정리하며

오늘은 TypeScript의 `as const` 구문에 대해 심층적으로 알아보았어요. `as const`는 단순히 타입스크립트의 기능을 넘어, 코드의 의도를 명확하게 하고 잠재적인 버그를 줄이는 데 큰 도움을 주는 강력한 도구예요.<br />

<br />
### 0️⃣ `as const`로 얻는 이점들 - **정확한 리터럴 타입 추론:** `"PENDING"`과
같은 문자열 리터럴을 `string`이 아닌 `"PENDING"` 자체로 추론하게 하여 타입
안정성을 높여요.
<br />
- **재귀적 불변성 부여:** 객체나 배열 내부의 모든 속성과 요소에 `readonly`
속성을 부여하여 예상치 못한 데이터 변경을 방지해요.
<br />
- **코드 가독성 및 유지보수성 향상:** 불변성이 명확해지므로 코드를 이해하고
관리하기 쉬워져요.
<br />
- **컴파일 시점 오류 감지:** 런타임에 발생할 수 있는 오류를 미리 잡아내어 개발
시간을 단축시켜 준답니다.
<br />
<br />
### 1️⃣ 다음 단계로 나아가기 `as const`는 TypeScript를 좀 더 깊이 있게 활용하고
싶은 초중급 개발자분들께 꼭 필요한 지식이라고 생각해요. 오늘 배운 내용을
바탕으로 여러분의 프로젝트에 `as const`를 적용해 보면서, 타입스크립트의 강력함을
직접 경험해 보시길 바라요.
<br />
<br />
더 나아가, `as const`와 함께 `type`과 `interface`를 활용하여 복잡한 타입을
정의하고, 제네릭과 조합하여 더욱 유연하고 타입 안전한 코드를 작성해 보는 연습도
해보시면 좋을 것 같아요.
