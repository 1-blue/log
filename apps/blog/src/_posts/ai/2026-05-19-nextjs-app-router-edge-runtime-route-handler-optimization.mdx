오늘은 Next.js App Router를 사용하시는 분들이라면 꼭 알아두면 좋을 **Edge Runtime**에 대해 이야기해보려고 해요.<br />
특히 Route Handler와 결합했을 때 얻을 수 있는 놀라운 성능 향상과 비용 효율성 극대화 전략에 초점을 맞춰 초중급 개발자분들에게 실질적인 도움이 될 만한 내용을 준비해 봤어요.

## 🤔 왜 Edge Runtime에 주목해야 할까요?

### 0️⃣ 글로벌 서비스의 필수 요소, 낮은 지연 시간

최근 웹 애플리케이션은 전 세계 사용자를 대상으로 하는 경우가 많아졌어요.<br />
사용자가 어디에 있든 빠르고 일관된 응답 속도를 제공하는 것은 사용자 경험에 매우 중요하죠.<br />
기존의 서버리스 함수는 특정 리전에 배포되어 있어서, 지리적으로 멀리 떨어진 사용자에게는 네트워크 지연 시간(latency)이 발생할 수밖에 없었어요.<br />
이러한 문제를 해결하기 위해 등장한 개념이 바로 **Edge Computing**이랍니다.

### 1️⃣ 기존 Node.js 런타임의 한계

Next.js의 기본 서버리스 함수 런타임은 Node.js 기반이에요.<br />
Node.js 런타임은 강력하고 다양한 기능을 제공하지만, 몇 가지 단점도 가지고 있어요.<br />
대표적으로 콜드 스타트(Cold Start) 시간이 비교적 길고, 전 세계에 분산 배치하기 위한 추가적인 설정이나 서비스가 필요하다는 점이에요.<br />
또한, AWS Lambda 같은 서비스에서는 호출 횟수나 실행 시간에 따라 비용이 발생하므로, 전 세계에서 빈번하게 호출되는 API의 경우 비용 부담이 커질 수 있어요.

## 🚀 Edge Runtime, 무엇이 다를까요?

### 0️⃣ V8 런타임 기반의 초경량, 초고속 실행 환경

Edge Runtime은 Node.js 대신 웹 브라우저의 JavaScript 엔진인 **V8 런타임**을 기반으로 동작해요.<br />
V8 엔진은 Chrome, Edge 같은 웹 브라우저에 내장되어 있어서 매우 빠르게 JavaScript 코드를 실행할 수 있도록 설계되었어요.<br />
이러한 특성 덕분에 Edge Runtime은 다음과 같은 장점을 가져요.

- ⚡️ 낮은 콜드 스타트: Node.js 런타임에 비해 훨씬 빠르게 함수를 시작할 수 있어요.<br />
  이는 사용자가 API를 호출했을 때 즉각적인 응답을 받을 수 있다는 의미예요.<br />
- 🌍 글로벌 분산 배치: CDN(Content Delivery Network) 엣지 로케이션에 가까운 곳에 함수가 배포되어 사용자와 가장 가까운 서버에서 응답할 수 있어요.<br />
  덕분에 네트워크 지연 시간이 획기적으로 줄어들어 글로벌 사용자에게 일관된 고성능을 제공할 수 있답니다.<br />
- 💸 비용 효율성: 일반적으로 Node.js 런타임보다 저렴한 비용으로 운영할 수 있어요.<br />
  이는 짧은 실행 시간과 효율적인 리소스 사용 덕분이죠.

<Blockquote type="info">
  Edge Runtime은 Vercel의 Edge Functions, Cloudflare Workers, Deno Deploy 등

  이해하기 쉬울 거예요.
</Blockquote>

### 1️⃣ Edge Runtime의 주요 제한사항

물론, Edge Runtime이 모든 상황에서 만능인 것은 아니에요.<br />
빠른 속도와 효율성을 위해 일부 기능은 제한될 수밖에 없어요.<br />
주요 제한사항은 다음과 같아요.

- 📦 Node.js API 제한: 파일 시스템(fs), `child_process`, `net`, `tls` 등 Node.js 고유의 API를 사용할 수 없어요.<br />
  따라서 이러한 기능을 사용하는 라이브러리는 Edge Runtime에서 동작하지 않아요.<br />
- 📏 번들 크기 제한: 배포 환경에 따라 번들 크기에 엄격한 제한이 있을 수 있어요.<br />
  (Vercel Edge Functions의 경우 1MB 이하를 권장해요.)<br />
- ⏳ 짧은 실행 시간: 복잡하고 긴 연산을 수행하는 작업에는 적합하지 않아요.<br />
  주로 가볍고 빠른 응답이 필요한 API에 활용하는 것이 좋아요.
- 🌐 Web API 기반: Node.js API 대신 `fetch`, `Request`, `Response`와 같은 Web API 표준을 사용해야 해요.

## 🛠️ Next.js App Router에서 Edge Runtime 적용하기

Next.js App Router에서 Route Handler에 Edge Runtime을 적용하는 방법은 매우 간단해요.<br />
`route.ts` 또는 `route.js` 파일에 `export const runtime = 'edge';` 한 줄만 추가하면 돼요.

### 0️⃣ 간단한 Edge Runtime Route Handler 예시

먼저, Edge Runtime의 장점을 살려 가볍게 동작하는 간단한 API를 만들어 볼게요.<br />
이 API는 요청받은 이름을 이용해 환영 메시지를 반환하는 역할을 해요.

```tsx showLineNumbers
// app/api/hello-edge/route.ts

export const runtime = "edge"; // ✨ 이 한 줄이 Edge Runtime을 활성화해요.

export async function GET(request: Request) {
  const { searchParams } = new URL(request.url);
  const name = searchParams.get("name") || "World";

  return new Response(
    JSON.stringify({ message: `Hello, ${name} from the Edge!` }),
    {
      status: 200,
      headers: { "content-type": "application/json" },
    },
  );
}

export async function POST(request: Request) {
  const data = await request.json();
  const name = data.name || "Anonymous";

  return new Response(
    JSON.stringify({ message: `Welcome, ${name} to the Edge POST API!` }),
    {
      status: 200,
      headers: { "content-type": "application/json" },
    },
  );
}
```

위 코드에서 볼 수 있듯이, `export const runtime = 'edge';` 한 줄만으로 해당 Route Handler는 Edge Runtime 환경에서 동작하게 돼요.<br />
`Request`와 `Response` 객체도 Web API 표준을 따르고 있음을 확인할 수 있어요.

### 1️⃣ Node.js API를 사용하는 경우 대처 방법

만약 특정 라이브러리가 Node.js API에 의존한다면 Edge Runtime에서는 사용할 수 없어요.<br />
이런 경우, 해당 기능을 Web API 기반으로 대체하거나, 해당 Route Handler만 Node.js 런타임으로 유지하는 방법을 고려해야 해요.<br />
예를 들어, Node.js의 `crypto` 모듈 대신 Web Crypto API를 사용할 수 있어요.

**Node.js `crypto` 모듈 사용 예시 (Edge Runtime에서 사용 불가):**

```ts showLineNumbers
// Node.js 런타임에서만 동작해요.
import crypto from "crypto";

function generateRandomStringNode() {
  return crypto.randomBytes(16).toString("hex");
}
```

**Web Crypto API 사용 예시 (Edge Runtime에서 사용 가능):**

```ts showLineNumbers
// Edge Runtime에서도 동작해요.
function generateRandomStringWeb() {
  const array = new Uint8Array(16);
  crypto.getRandomValues(array);
  return Array.from(array, (byte) => byte.toString(16).padStart(2, "0")).join(
    "",
  );
}
```

이처럼 Edge Runtime의 제약을 이해하고 적절한 대안을 찾는 것이 중요해요.<br />
작은 유틸리티 함수나 인증/인가 로직처럼 가볍고 자주 호출되는 API에 Edge Runtime을 적용하면 큰 효과를 볼 수 있어요.

## 🌐 실전 활용: 인증 미들웨어로 Edge Runtime 활용하기

Edge Runtime은 인증/인가 로직과 같은 미들웨어 역할에 아주 적합해요.<br />
사용자 요청이 들어왔을 때 가장 먼저 처리되어야 하고, 빠르게 응답해야 하기 때문이에요.<br />
다음은 JWT 토큰을 검증하는 간단한 인증 미들웨어 예시예요.

```tsx showLineNumbers {5-6, 11-12, 17-20}
// app/api/auth-protected-edge/route.ts

export const runtime = "edge";

// 실제 환경에서는 환경 변수나 KMS 등 안전한 방식으로 비밀 키를 관리해야 해요.
const JWT_SECRET = process.env.JWT_SECRET || "your-super-secret-key";

export async function GET(request: Request) {
  const authHeader = request.headers.get("Authorization");

  if (!authHeader || !authHeader.startsWith("Bearer ")) {
    return new Response("Unauthorized: No token provided", { status: 401 });
  }

  const token = authHeader.split(" ")[1];

  try {
    // 실제 JWT 검증 라이브러리 (예: jose)를 사용하면 더욱 견고해요.
    // 여기서는 간단하게 토큰이 'valid-token'인지 확인하는 예시로 대체해요.
    if (token !== "valid-token") {
      throw new Error("Invalid token");
    }

    // 토큰이 유효하면 다음 로직을 진행해요.
    return new Response(
      JSON.stringify({ message: "Access granted!", user: "edge-user" }),
      {
        status: 200,
        headers: { "content-type": "application/json" },
      },
    );
  } catch (error) {
    return new Response(`Unauthorized: ${error.message}`, { status: 401 });
  }
}
```

이 예시에서는 `JWT_SECRET`을 환경 변수에서 가져오고, 토큰이 `valid-token`인지 간단히 확인하는 로직을 보여드렸어요.<br />
실제 프로덕션 환경에서는 `jose` 같은 강력한 JWT 라이브러리를 사용해서 서명 검증을 포함한 복잡한 인증 로직을 구현해야 해요.<br />
하지만 Edge Runtime의 제약사항을 고려하여 라이브러리 선택 시 Edge Runtime 호환성을 꼭 확인해야 한답니다.<br />
이러한 인증 미들웨어를 Edge Runtime으로 배포하면, 사용자 요청이 서버에 도달하기도 전에 엣지 로케이션에서 빠르게 인증을 처리하여 불필요한 서버 리소스 사용을 줄이고 응답 속도를 향상시킬 수 있어요.

## 📝 정리하며

### 0️⃣ 핵심 요약

Next.js App Router에서 Edge Runtime을 Route Handler에 적용하는 것은 글로벌 서비스를 위한 성능과 비용 효율성을 동시에 잡을 수 있는 강력한 전략이에요.<br />
Node.js 런타임의 한계를 극복하고, 사용자에게 더 빠르고 안정적인 경험을 제공하는 데 큰 도움이 된답니다.<br />

- **Edge Runtime의 장점:** 낮은 콜드 스타트, 글로벌 분산 배치, 비용 효율성.<br />
- **Edge Runtime의 제한사항:** Node.js API 제한, 번들 크기 제한, 짧은 실행 시간.<br />
- **적용 방법:** `export const runtime = 'edge';` 한 줄 추가.<br />
- **활용 분야:** 가벼운 API, 인증/인가 미들웨어 등 빠른 응답이 필요한 작업.
