## 🤔 문제/배경

### 0️⃣ Next.js App Router와 전역 상태 관리의 복잡성

Next.js App Router는 Server Components(SC)와 Client Components(CC)라는 새로운 패러다임을 도입하며 웹 개발의 성능과 개발 경험을 한 단계 끌어올렸어요. 하지만 이러한 변화는 기존 React 개발 방식에 익숙했던 개발자들에게 새로운 도전 과제를 안겨주었죠.<br />
특히, 애플리케이션 전반에 걸쳐 공유되어야 하는 사용자 인증 정보, 테마 설정, 장바구니 데이터와 같은 '전역 상태'를 어떻게 관리해야 할지 혼란스러워하는 경우가 많아요. Server Components는 상태를 가질 수 없는데, Client Components는 클라이언트 측에서 렌더링되니 이 둘 사이의 상태 동기화나 초기화가 쉽지 않다고 느끼실 수 있어요.

### 1️⃣ Server Components와 Client Components의 상태 관리 한계

Server Components는 서버에서 렌더링되어 HTML을 생성하고 클라이언트로 보내기 때문에, 클라이언트 측에서 상호작용이 필요한 `useState`, `useEffect`와 같은 React Hooks를 사용할 수 없어요. 즉, Server Components 자체는 상태를 가질 수 없다는 의미예요.<br />
반면 Client Components는 클라이언트 측에서 하이드레이션되고 렌더링되며, 기존 React 컴포넌트처럼 상태를 가질 수 있고 상호작용이 가능해요. 문제는 Server Components에서 가져온 데이터를 Client Components에서 전역 상태로 활용하고 싶을 때 발생해요. Server Components에서 Client Components로 데이터를 props로 전달하는 것은 가능하지만, 여러 Client Components에 걸쳐 복잡하게 props를 전달하거나, Server Components에서 가져온 데이터를 전역 상태 라이브러리에 직접 주입하는 과정에서 헷갈릴 수 있답니다.

  <br />
  Server Components는 기본적으로 상호작용이 없는 정적인 UI를 렌더링하고,

  <br />

## ⚙️ 해결 방법

### 0️⃣ App Router 전역 상태 관리의 핵심 원칙

App Router 환경에서 전역 상태를 효율적으로 관리하기 위한 핵심 원칙은 다음과 같아요.

1.  **"Client Component Root" 패턴 활용**: 전역 상태를 사용하는 모든 Client Components를 최상위 Client Component로 감싸는 패턴이에요. 이 최상위 Client Component는 전역 상태 관리 라이브러리의 Provider 역할을 하게 돼요.<br />
2.  **Server Components에서 초기 데이터 페칭**: Server Components의 강점인 데이터 페칭을 활용하여 초기 전역 상태에 필요한 데이터를 서버에서 가져와요.<br />
3.  **Client Components로 초기 상태 전달**: Server Components에서 가져온 초기 데이터를 Client Component Root로 전달하여 전역 상태 라이브러리를 초기화해요.<br />
4.  **적절한 상태 관리 라이브러리 선택**: 프로젝트의 규모와 복잡성에 따라 React Context API 또는 Zustand, Recoil, Jotai와 같은 외부 상태 관리 라이브러리를 선택해요.

### 1️⃣ Client Component Root 패턴과 Context API 활용

가장 기본적인 전역 상태 관리 방법은 React의 Context API를 활용하는 것이에요. 특히 테마(Theme) 모드와 같이 간단한 전역 상태에 적합해요.<br />
핵심은 `Context.Provider`를 **Client Component**로 만들고, 이 Provider를 `app/layout.tsx`와 같은 **Server Component**에서 렌더링하는 것이에요. 이렇게 하면 Server Component는 Provider 컴포넌트 자체를 클라이언트로 보내고, Provider 내부의 Client Components들은 클라이언트에서 Context를 통해 상태를 공유하게 돼요.

```tsx showLineNumbers
// app/components/theme-provider.tsx
"use client"; // 👈 반드시 'use client' 지시어를 추가해야 해요.

import { createContext, useContext, useState, ReactNode } from "react";

type Theme = "light" | "dark";

interface ThemeContextType {
  theme: Theme;
  toggleTheme: () => void;
}

const ThemeContext = createContext<ThemeContextType | undefined>(undefined);

export function ThemeProvider({ children }: { children: ReactNode }) {
  const [theme, setTheme] = useState<Theme>("light"); // 클라이언트에서 상태 관리

  const toggleTheme = () => {
    setTheme((prevTheme) => (prevTheme === "light" ? "dark" : "light"));
  };

  return (
    <ThemeContext.Provider value={{ theme, toggleTheme }}>
      {children}
    </ThemeContext.Provider>
  );
}

export function useTheme() {
  const context = useContext(ThemeContext);
  if (context === undefined) {
    throw new Error("useTheme must be used within a ThemeProvider");
  }
  return context;
}
```

이제 `app/layout.tsx`에서 이 `ThemeProvider`를 감싸주면 돼요.

```tsx showLineNumbers
// app/layout.tsx (Server Component)
import { ThemeProvider } from "./components/theme-provider";
import "./globals.css";

export default function RootLayout({
  children,
}: {
  children: React.ReactNode;
}) {
  return (
    <html lang="ko">
      <body>
        <ThemeProvider>
          {" "}
          {/* Server Component에서 Client Component인 ThemeProvider를 렌더링해요. */}
          {children}
        </ThemeProvider>
      </body>
    </html>
  );
}
```

### 2️⃣ Zustand를 이용한 효율적인 전역 상태 관리

Context API는 간단한 상태에 적합하지만, 복잡한 로직이나 빈번한 업데이트가 필요한 전역 상태에는 Zustand와 같은 외부 상태 관리 라이브러리가 더 효율적이에요.<br />
Zustand는 가볍고 빠르며, 보일러플레이트 코드가 적어 많은 개발자에게 사랑받고 있어요. App Router 환경에서는 Zustand 스토어 인스턴스를 React Context를 통해 Client Components에 제공하는 패턴을 사용해요.

이 패턴은 Server Components에서 초기 데이터를 받아와 Client Components 내부의 Zustand 스토어를 초기화하는 데 매우 유용해요.

## 🧪 예시

이제 실제로 Zustand를 활용하여 사용자 인증 상태를 관리하는 예시를 살펴볼게요. Server Components에서 사용자 세션을 가져와 Client Components의 전역 상태로 주입하는 과정을 보여드릴 거예요.

### 0️⃣ Client Component Root 패턴 구현 (Zustand)

먼저, Zustand 스토어를 생성하고 이를 Context를 통해 Client Components에 제공하는 Provider를 만들어요. Provider는 `initialState`를 받아 스토어를 초기화할 수 있도록 설계할 거예요.

```tsx showLineNumbers {2-3, 16, 21-23, 29-31, 37-39}
// app/providers/user-store-provider.tsx
"use client"; // 👈 Client Component로 명시해요.

import { createContext, useContext, useRef, ReactNode } from "react";
import { useStore } from "zustand";
import { createStore, StoreApi } from "zustand";

// 1. User State 타입 정의
interface UserState {
  id: string | null;
  name: string | null;
  email: string | null;
  isAuthenticated: boolean;
  login: (id: string, name: string, email: string) => void;
  logout: () => void;
}

// 2. Zustand 스토어 생성 함수
const createUserStore = (initialState: Partial<UserState> = {}) =>
  createStore<UserState>((set) => ({
    id: initialState.id || null,
    name: initialState.name || null,
    email: initialState.email || null,
    isAuthenticated: initialState.isAuthenticated || false,
    login: (id, name, email) => set({ id, name, email, isAuthenticated: true }),
    logout: () =>
      set({ id: null, name: null, email: null, isAuthenticated: false }),
  }));

// 3. 스토어 인스턴스를 위한 React Context
type UserStoreApi = ReturnType<typeof createUserStore>;
export const UserStoreContext = createContext<UserStoreApi | undefined>(
  undefined,
);

// 4. Provider 컴포넌트
export function UserStoreProvider({
  children,
  initialState,
}: {
  children: ReactNode;
  initialState?: Partial<UserState>;
}) {
  const storeRef = useRef<UserStoreApi>();
  if (!storeRef.current) {
    storeRef.current = createUserStore(initialState);
  }

  return (
    <UserStoreContext.Provider value={storeRef.current}>
      {children}
    </UserStoreContext.Provider>
  );
}

// 5. 스토어 사용을 위한 커스텀 훅
export const useUserStore = <T,>(selector: (store: UserState) => T): T => {
  const userStoreContext = useContext(UserStoreContext);

  if (!userStoreContext) {
    throw new Error(`useUserStore must be used within UserStoreProvider`);
  }

  return useStore(userStoreContext, selector);
};
```

### 1️⃣ Zustand 스토어 설계 및 Server Component에서 초기화

이제 `app/layout.tsx` (Server Component)에서 사용자 세션 데이터를 가져와 `UserStoreProvider`에 `initialState`로 전달할 거예요. `getUserSession` 함수는 서버에서만 실행되는 가상의 함수라고 가정해요.

```tsx showLineNumbers {2-3, 9-11}
// app/layout.tsx (Server Component)
import { UserStoreProvider } from "./providers/user-store-provider";
import { getUserSession } from "@/lib/auth"; // 가상의 서버 함수: 사용자 세션 정보를 가져와요.
import "./globals.css";

export default async function RootLayout({
  children,
}: {
  children: React.ReactNode;
}) {
  // Server Component에서 사용자 세션 데이터를 가져와요.
  const initialUser = await getUserSession();

  return (
    <html lang="ko">
      <body>
        {/* 가져온 데이터를 UserStoreProvider의 initialState로 전달해요. */}
        <UserStoreProvider initialState={initialUser}>
          {children}
        </UserStoreProvider>
      </body>
    </html>
  );
}

// lib/auth.ts (예시)
interface UserSession {
  id: string;
  name: string;
  email: string;
  isAuthenticated: boolean;
}

export async function getUserSession(): Promise<Partial<UserSession>> {
  // 실제 환경에서는 쿠키, 토큰 등을 검증하여 사용자 세션 정보를 반환해요.
  // 여기서는 예시를 위해 더미 데이터를 반환해요.
  return new Promise((resolve) => {
    setTimeout(() => {
      const isLoggedIn = Math.random() > 0.5; // 50% 확률로 로그인 상태
      if (isLoggedIn) {
        resolve({
          id: "user-123",
          name: "블루",
          email: "blue@example.com",
          isAuthenticated: true,
        });
      } else {
        resolve({ isAuthenticated: false });
      }
    }, 100);
  });
}
```

### 2️⃣ 실제 컴포넌트에서 상태 활용

이제 어떤 Client Component에서든 `useUserStore` 훅을 사용하여 전역 사용자 상태에 접근하고 업데이트할 수 있어요.

```tsx showLineNumbers {2-3, 9-14, 18-21}
// app/dashboard/client-dashboard.tsx
"use client"; // 👈 Client Component로 명시해요.

import { useUserStore } from "@/app/providers/user-store-provider";

export function ClientDashboard() {
  // useUserStore 훅을 사용하여 전역 상태에서 필요한 값과 액션을 가져와요.
  const { name, isAuthenticated, logout } = useUserStore((state) => ({
    name: state.name,
    isAuthenticated: state.isAuthenticated,
    logout: state.logout,
  }));

  if (!isAuthenticated) {
    return (
      <Blockquote type="warning">
        로그인이 필요합니다. <br />
        로그인 후 대시보드를 이용해 주세요.
      </Blockquote>
    );
  }

  return (
    <div>
      <Blockquote type="success">
        환영합니다, {name}님! 대시보드에 오신 것을 환영해요.
      </Blockquote>
      <button
        onClick={logout}
        style={{
          padding: "10px 20px",
          backgroundColor: "#ef4444",
          color: "white",
          border: "none",
          borderRadius: "5px",
          cursor: "pointer",
          marginTop: "15px",
        }}
      >
        로그아웃
      </button>
    </div>
  );
}
```

```tsx showLineNumbers
// app/dashboard/page.tsx (Server Component)
import { ClientDashboard } from "./client-dashboard";

export default function DashboardPage() {
  return (
    <main style={{ padding: "20px", maxWidth: "800px", margin: "0 auto" }}>
      <h1>✨ 사용자 대시보드</h1>
      <ClientDashboard />{" "}
      {/* Server Component는 Client Component를 렌더링할 수 있어요. */}
    </main>
  );
}
```

이렇게 하면 Server Component인 `app/layout.tsx`에서 사용자 데이터를 서버 측에서 안전하게 가져오고, 이 데이터를 `UserStoreProvider`를 통해 Client Components에 전역 상태로 주입할 수 있어요. `ClientDashboard`와 같은 Client Components는 이제 이 전역 상태를 구독하여 사용자 정보를 표시하고 상호작용할 수 있게 된답니다.<br />
이 패턴을 사용하면 Server Components의 데이터 페칭 이점과 Client Components의 상호작용 능력을 모두 활용하면서, 전역 상태 관리의 복잡성을 효과적으로 해결할 수 있어요.

## 📝 정리

### 0️⃣ 핵심 요약 및 권장 사항

Next.js App Router 환경에서의 전역 상태 관리는 Server Components와 Client Components의 특성을 명확히 이해하는 것에서부터 시작돼요.<br />
핵심은 다음과 같아요.

- **Client Component Root 패턴**: 전역 상태 관리 라이브러리의 Provider는 반드시 `'use client';` 지시어가 있는 Client Component여야 해요.<br />
- **Server Component의 역할**: 초기 데이터를 서버에서 안전하고 효율적으로 가져와 Client Component Root의 `initialState`로 전달하는 역할을 해요.<br />
- **상태 관리 라이브러리 선택**: 간단한 상태는 React Context API로 충분하지만, 복잡한 애플리케이션에서는 Zustand와 같은 외부 라이브러리가 더 나은 성능과 개발 경험을 제공해요.

이러한 전략을 통해 여러분은 Next.js App Router의 강력한 기능을 활용하면서도, 전역 상태 관리의 어려움을 극복하고 견고한 애플리케이션을 구축할 수 있을 거예요.

### 1️⃣ 다음 단계: 더 나아가기

오늘 다룬 내용을 바탕으로 더 나아가 볼 수 있는 몇 가지 아이디어를 드려요.

- **세션 관리**: 사용자 인증 상태를 서버와 클라이언트 모두에서 안전하게 동기화하는 방법을 더 깊이 연구해 보세요. NextAuth.js와 같은 라이브러리가 좋은 예시가 될 수 있어요.<br />
- **데이터 캐싱**: `use` 훅이나 SWR, React Query와 같은 데이터 페칭 라이브러리를 전역 상태와 결합하여 캐싱 전략을 최적화해 보세요.<br />
- **서버 액션과의 연동**: Next.js Server Actions를 통해 서버에서 데이터를 변경하고, 이 변경 사항을 전역 상태에 반영하여 UI를 업데이트하는 패턴을 학습해 보세요. `useOptimistic` 훅이 도움이 될 거예요.

이 글이 Next.js App Router 환경에서 전역 상태 관리에 대한 여러분의 궁금증을 해소하고, 실무에 적용하는 데 도움이 되기를 바라요. 궁금한 점이 있다면 언제든지 질문해주세요!
