## 🤔 자원 관리, 왜 중요할까요?

### 0️⃣ 개발자가 놓치기 쉬운 자원 누수 문제

우리가 개발하는 애플리케이션은 파일 시스템, 네트워크 소켓, 데이터베이스 연결, 메모리 스트림 등 다양한 외부 자원과 상호작용해요.<br />
이러한 자원들은 사용 후 반드시 해제해주어야 하는데요, 만약 해제하지 않고 방치하게 되면 어떻게 될까요?<br />
바로 '자원 누수(Resource Leak)' 문제가 발생해요. 이는 애플리케이션의 성능 저하, 시스템 불안정, 심지어는 서비스 장애로 이어질 수 있는 심각한 문제예요.

예를 들어, 파일 쓰기 작업을 한 후 파일을 닫지 않으면 다른 프로세스가 해당 파일에 접근하지 못하거나, 파일 핸들이 계속 쌓여 시스템 자원을 고갈시킬 수 있어요.<br />
데이터베이스 연결도 마찬가지예요. 연결을 끊지 않으면 연결 풀이 고갈되어 더 이상 새로운 요청을 처리할 수 없게 되죠.

### 1️⃣ 기존 자원 관리 방식의 한계: `try...finally`의 번거로움

이러한 자원 누수를 방지하기 위해 우리는 오랫동안 `try...finally` 패턴을 사용해왔어요.<br />
`try` 블록에서 자원을 사용하고, `finally` 블록에서 예외 발생 여부와 상관없이 자원을 해제하는 방식이죠.<br />
아래 코드를 보시면 어떤 느낌인지 아실 거예요.

```ts showLineNumbers
function processFile(filePath: string) {
  let fileHandle: FileHandle | undefined; // FileHandle는 Node.js fs.promises에서 가져왔다고 가정
  try {
    fileHandle = await open(filePath, "r+"); // 파일 열기
    // 파일 읽기/쓰기 작업 수행
    console.log("파일 작업 중...");
    // ...
  } catch (error) {
    console.error("파일 처리 중 오류 발생:", error);
  } finally {
    if (fileHandle) {
      await fileHandle.close(); // 자원 해제
      console.log("파일 핸들 닫힘.");
    }
  }
}
```

어떠신가요? 코드가 길어지고, 자원 해제 로직이 비즈니스 로직과 섞여 가독성을 해치죠.<br />
만약 여러 자원을 동시에 관리해야 한다면 `finally` 블록은 더욱 복잡해질 거예요. 중첩된 `try...finally`는 생각만 해도 아찔하죠.

## ⚙️ TypeScript 5.2+ `using` 선언의 등장

### 0️⃣ `using` 선언: 자원 자동 해제의 마법

TypeScript 5.2부터 도입된 `using` 선언은 이러한 `try...finally`의 번거로움을 해결하기 위해 등장했어요.<br />
이는 C#의 `using` 선언이나 Java의 `try-with-resources`와 유사한 개념으로, 특정 스코프를 벗어날 때 자동으로 자원을 해제해주는 기능을 제공해요.<br />
이 기능을 사용하려면 `target`을 `ES2022` 이상으로 설정해야 하며, `lib`에 `ES2023` 또는 `ESNext`가 포함되어야 해요.<br />

`using` 선언의 핵심은 `Disposable` 인터페이스와 `AsyncDisposable` 인터페이스에 있어요.<br />
자원을 관리하려는 객체가 이 인터페이스들을 구현하면 `using` 선언을 통해 자동으로 `[Symbol.dispose]` 또는 `[Symbol.asyncDispose]` 메서드가 호출되어 자원이 해제돼요.<br />

<LinkPreviewCard href="https://www.typescriptlang.org/docs/handbook/release-notes/typescript-5-2.html#the-using-declaration" />

### 1️⃣ `Disposable`과 `AsyncDisposable` 인터페이스

`using` 선언은 다음과 같은 두 가지 인터페이스와 함께 작동해요.<br />

- **`Disposable`**: 동기적으로 자원을 해제할 때 사용해요. 객체에 `[Symbol.dispose]()` 메서드가 구현되어 있어야 해요.<br />
- **`AsyncDisposable`**: 비동기적으로 자원을 해제할 때 사용해요. 객체에 `[Symbol.asyncDispose]()` 메서드가 구현되어 있어야 하며, `using` 대신 `await using`으로 선언해야 해요.<br />

이 인터페이스들은 TypeScript 5.2부터 전역으로 사용할 수 있게 되었어요.<br />

```ts showLineNumbers
interface Disposable {
  [Symbol.dispose](): void;
}

interface AsyncDisposable {
  [Symbol.asyncDispose](): PromiseLike<void>;
}
```

## 🧪 `using` 선언 적용 예시

이제 실제로 `using` 선언을 어떻게 활용하는지 다양한 예시를 통해 알아볼게요.

### 0️⃣ 동기 자원 해제: 파일 핸들 시뮬레이션

먼저 동기적으로 자원을 해제하는 경우를 살펴볼게요.<br />
Node.js의 `FileHandle`과 유사한 `MyFileHandle` 클래스를 만들어 `Disposable` 인터페이스를 구현해볼까요?

```ts showLineNumbers {1-16, 20-21, 26-29}
// MyFileHandle.ts
class MyFileHandle implements Disposable {
  private path: string;
  private isOpen: boolean;

  constructor(path: string) {
    this.path = path;
    this.isOpen = true;
    console.log(`[${path}] 파일이 열렸습니다.`);
  }

  read() {
    if (!this.isOpen) throw new Error(`[${this.path}] 파일이 닫혀 있습니다.`);
    return `[${this.path}] 파일 내용 읽기...`;
  }

  // Disposable 인터페이스 구현
  [Symbol.dispose]() {
    if (this.isOpen) {
      console.log(`[${this.path}] 파일이 닫힙니다. (Disposable)`);
      this.isOpen = false;
    }
  }
}

// main.ts
function processMyFile(filePath: string) {
  using file = new MyFileHandle(filePath); // `using` 선언!
  console.log(file.read());
  // 함수 스코프를 벗어나면 자동으로 [Symbol.dispose]() 호출
  console.log("파일 처리 완료.");
}

console.log("--- 동기 자원 처리 시작 ---");
processMyFile("document.txt");
console.log("--- 동기 자원 처리 종료 ---");

// 결과:
// --- 동기 자원 처리 시작 ---
// [document.txt] 파일이 열렸습니다.
// [document.txt] 파일 내용 읽기...
// 파일 처리 완료.
// [document.txt] 파일이 닫힙니다. (Disposable)
// --- 동기 자원 처리 종료 ---
```

위 코드를 보시면 `using file = new MyFileHandle(filePath);` 한 줄로 자원을 선언했어요.<br />
`processMyFile` 함수가 종료되면 (정상 종료든 예외 발생이든 상관없이) 자동으로 `MyFileHandle` 인스턴스의 `[Symbol.dispose]()` 메서드가 호출되어 자원이 깔끔하게 해제되는 것을 볼 수 있어요.<br />
이제 `try...finally` 블록은 필요 없어요! 정말 간편하죠?

### 1️⃣ 비동기 자원 해제: 데이터베이스 연결 시뮬레이션

다음으로 비동기 자원 해제를 다뤄볼게요.<br />
데이터베이스 연결과 같이 비동기적으로 해제해야 하는 자원은 `AsyncDisposable` 인터페이스를 구현하고 `await using`으로 선언해야 해요.

```ts showLineNumbers {1-18, 22-23, 28-31}
// DatabaseConnection.ts
class DatabaseConnection implements AsyncDisposable {
  private dbName: string;
  private isConnected: boolean;

  constructor(dbName: string) {
    this.dbName = dbName;
    this.isConnected = true;
    console.log(`[${dbName}] 데이터베이스에 연결되었습니다.`);
  }

  query(sql: string) {
    if (!this.isConnected)
      throw new Error(`[${this.dbName}] 데이터베이스 연결이 끊어졌습니다.`);
    return `[${this.dbName}] 쿼리 실행: ${sql}`; // 비동기 작업 시뮬레이션
  }

  // AsyncDisposable 인터페이스 구현
  async [Symbol.asyncDispose]() {
    if (this.isConnected) {
      await new Promise((resolve) => setTimeout(resolve, 100)); // 비동기 해제 작업 시뮬레이션
      console.log(
        `[${this.dbName}] 데이터베이스 연결이 해제됩니다. (AsyncDisposable)`,
      );
      this.isConnected = false;
    }
  }
}

// main.ts
async function processDatabase(databaseName: string) {
  await using db = new DatabaseConnection(databaseName); // `await using` 선언!
  console.log(db.query("SELECT * FROM users;"));
  // 함수 스코프를 벗어나면 자동으로 [Symbol.asyncDispose]() 호출
  console.log("데이터베이스 작업 완료.");
}

console.log("--- 비동기 자원 처리 시작 ---");
await processDatabase("my_app_db");
console.log("--- 비동기 자원 처리 종료 ---");

// 결과:
// --- 비동기 자원 처리 시작 ---
// [my_app_db] 데이터베이스에 연결되었습니다.
// [my_app_db] 쿼리 실행: SELECT * FROM users;
// 데이터베이스 작업 완료.
// [my_app_db] 데이터베이스 연결이 해제됩니다. (AsyncDisposable)
// --- 비동기 자원 처리 종료 ---
```

`DatabaseConnection` 클래스는 `AsyncDisposable`을 구현하고, `[Symbol.asyncDispose]()` 메서드에서 비동기 해제 로직을 처리해요.<br />
그리고 `processDatabase` 함수에서는 `await using db = new DatabaseConnection(databaseName);`와 같이 `await` 키워드를 함께 사용하여 비동기 자원을 선언했어요.<br />
함수가 종료되면 비동기적으로 `[Symbol.asyncDispose]()`가 호출되어 데이터베이스 연결이 안전하게 해제되는 것을 확인할 수 있어요.<br />

### 2️⃣ 여러 자원 동시 관리 및 에러 처리

`using` 선언은 여러 자원을 동시에 관리할 때도 빛을 발해요.<br />
여러 `using` 선언이 연속되면, 선언된 순서의 역순으로 자원이 해제돼요. 또한, 중간에 에러가 발생해도 모든 `using` 선언된 자원은 안전하게 해제돼요.

```ts showLineNumbers {13-16}
class LogFile implements Disposable {
  private name: string;
  constructor(name: string) {
    this.name = name;
    console.log(`[${name}] 로그 파일 열림`);
  }
  write(message: string) {
    console.log(`[${this.name}] ${message}`);
  }
  [Symbol.dispose]() {
    console.log(`[${this.name}] 로그 파일 닫힘`);
  }
}

async function complexOperation() {
  console.log("--- 복잡한 작업 시작 ---");
  await using db = new DatabaseConnection("analytics_db"); // AsyncDisposable
  using log = new LogFile("operation.log"); // Disposable

  log.write("데이터베이스 쿼리 시작");
  console.log(db.query("SELECT COUNT(*) FROM logs;"));
  log.write("데이터베이스 쿼리 완료");

  // 의도적으로 에러 발생
  throw new Error("작업 중 치명적인 에러 발생!");

  console.log("--- 복잡한 작업 종료 (여기는 실행되지 않음) ---");
}

try {
  await complexOperation();
} catch (e: any) {
  console.error(`외부에서 에러 처리: ${e.message}`);
}

// 결과:
// --- 복잡한 작업 시작 ---
// [analytics_db] 데이터베이스에 연결되었습니다.
// [operation.log] 로그 파일 열림
// [operation.log] 데이터베이스 쿼리 시작
// [analytics_db] 쿼리 실행: SELECT COUNT(*) FROM logs;
// [operation.log] 데이터베이스 쿼리 완료
// [operation.log] 로그 파일 닫힘
// [analytics_db] 데이터베이스 연결이 해제됩니다. (AsyncDisposable)
// 외부에서 에러 처리: 작업 중 치명적인 에러 발생!
```

보시다시피 `complexOperation` 함수 내에서 에러가 발생했음에도 불구하고, `log`와 `db` 자원이 모두 안전하게 해제되는 것을 확인할 수 있어요.<br />
해제 순서는 `log` (동기) -> `db` (비동기) 순으로, 선언된 순서의 역순으로 해제되는 것을 알 수 있죠. 이는 자원 간의 의존성 문제를 방지하는 데 도움이 돼요.<br />

## 📝 정리

### 0️⃣ `using` 선언의 핵심 요약

TypeScript 5.2+의 `using` 선언은 자원 관리의 패러다임을 바꿀 강력한 기능이에요.<br />

- **자동 자원 해제**: `try...finally` 블록 없이 스코프를 벗어날 때 자동으로 자원을 해제해요.<br />
- **안전성**: 예외 발생 여부와 상관없이 자원이 항상 해제됨을 보장해요.<br />
- **가독성 및 유지보수성**: 자원 해제 로직이 비즈니스 로직과 분리되어 코드가 훨씬 깔끔해져요.<br />
- **동기/비동기 지원**: `Disposable` (동기)와 `AsyncDisposable` (비동기) 인터페이스를 통해 다양한 자원에 적용할 수 있어요.<br />
- **다중 자원 관리**: 여러 `using` 선언 시 선언 역순으로 안전하게 해제돼요.

### 1️⃣ 다음 액션: 여러분의 코드에 적용해 보세요!

이제 여러분의 프로젝트에서 파일 핸들, 데이터베이스 연결, 커스텀 이벤트 리스너 등 다양한 자원을 관리할 때 `using` 선언을 적극적으로 활용해 보세요.<br />
특히 Node.js 환경에서 파일 시스템(`fs.promises`)이나 데이터베이스 드라이버(`pg`, `mysql2` 등)를 사용할 때 이 패턴을 적용하면 더욱 견고하고 유지보수하기 쉬운 코드를 작성할 수 있을 거예요.<br />

`using` 선언은 아직 비교적 새로운 기능이므로, 실제 프로젝트에 적용하기 전에 TypeScript 공식 문서와 런타임 환경(Node.js 등)의 호환성을 다시 한번 확인하는 것을 권장해요.<br />

깔끔하고 안전한 자원 관리로 더 나은 코드를 만들어가는 여러분을 응원합니다! 궁금한 점이 있다면 언제든지 질문해주세요.
