## 🧐 Next.js App Router에서 인증의 중요성과 변화

Next.js App Router는 서버 컴포넌트(Server Components)라는 강력한 개념을 도입하며 웹 개발 패러다임에 큰 변화를 가져왔어요. 이 변화는 인증 시스템 설계에도 많은 영향을 주었는데요.<br />

### 0️⃣ 왜 App Router에서 인증이 복잡해졌나요?

기존 Pages Router에서는 모든 페이지가 기본적으로 서버에서 렌더링되거나 클라이언트에서 Hydration된 후 동작했어요. 하지만 App Router는 서버 컴포넌트가 기본이 되면서, 클라이언트 컴포넌트와 서버 컴포넌트 간의 명확한 구분이 생겼죠.<br />

이로 인해 세션 정보를 어디서, 어떻게 가져와야 하는지에 대한 고민이 깊어졌어요. 서버 컴포넌트에서는 클라이언트 사이드 훅(`useSession` 등)을 사용할 수 없고, 클라이언트 컴포넌트에서는 서버 사이드에서만 접근 가능한 민감한 정보(예: API 키)를 다룰 수 없으니까요.<br />

### 1️⃣ 기존 Pages Router 방식과의 차이점

Pages Router에서는 `getServerSideProps`나 `getInitialProps`에서 `getSession` 함수를 호출하여 서버 사이드에서 세션 정보를 쉽게 가져올 수 있었어요. 클라이언트 사이드에서는 `useSession` 훅을 사용했고요.<br />

하지만 App Router에서는 `getServerSideProps`와 같은 데이터 fetching 함수들이 사라지고, 대신 서버 컴포넌트 내에서 직접 데이터 fetching을 하거나 `Route Handler`를 활용하는 방식으로 바뀌었어요. 이는 인증 정보에 접근하는 방식에도 변화를 요구해요.<br />

### 2️⃣ Auth.js (NextAuth.js)를 선택하는 이유

Auth.js (이전 이름: NextAuth.js)는 Next.js 애플리케이션을 위한 강력하고 유연한 인증 라이브러리예요. OAuth, 이메일/패스워드, Magic Link 등 다양한 인증 방법을 쉽고 안전하게 통합할 수 있도록 도와줘요.<br />

특히 App Router 환경에 최적화된 새로운 버전(v5, `@auth/nextjs`)이 출시되면서, 서버 컴포넌트와 클라이언트 컴포넌트 모두에서 세션을 일관되게 관리할 수 있는 강력한 기능을 제공하고 있어요. 직접 인증 시스템을 구축하는 것보다 훨씬 빠르고 안전하게 구현할 수 있다는 장점이 있어요.<br />

## 🛠️ Auth.js 기본 설정 및 Provider 추가

그럼 이제 Next.js App Router 프로젝트에 Auth.js를 설정하는 방법을 알아볼까요?<br />

### 0️⃣ 프로젝트 초기 설정

먼저 Next.js 프로젝트를 생성하고 Auth.js 패키지를 설치해 주세요.<br />

```bash showLineNumbers
npx create-next-app@latest my-auth-app --typescript --eslint
cd my-auth-app
npm install @auth/nextjs
```

### 1️⃣ 환경 변수 설정 (`.env.local`)

Auth.js는 보안을 위해 몇 가지 환경 변수를 필요로 해요. 특히 `AUTH_SECRET`은 중요하니 안전하게 생성해야 해요. `openssl rand -base64 32` 명령어로 생성할 수 있어요.<br />

```bash showLineNumbers
openssl rand -base64 32
```

생성된 값을 `.env.local` 파일에 다음과 같이 추가해 주세요.<br />

```txt showLineNumbers
AUTH_SECRET="YOUR_GENERATED_SECRET"
AUTH_URL="http://localhost:3000" # 개발 환경 URL
GITHUB_ID="YOUR_GITHUB_CLIENT_ID"
GITHUB_SECRET="YOUR_GITHUB_CLIENT_SECRET"
```

<Blockquote type="warning">
  `AUTH_SECRET`은 절대로 외부에 노출되어서는 안 돼요. 프로덕션 환경에서는 더욱
  강력한 보안 관리가 필요해요.
  <br />
  `AUTH_URL`은 배포 환경에 맞춰 변경해야 해요. (예: `https://your-domain.com`)
</Blockquote>

### 2️⃣ Auth.js 핸들러 (`[...nextauth]`) 구성

App Router에서는 `app/api/auth/[...nextauth]/route.ts` 경로에 Auth.js 핸들러를 생성해야 해요. 이 파일은 모든 인증 요청을 처리하는 역할을 해요.<br />

```tsx showLineNumbers
// app/api/auth/[...nextauth]/route.ts
import NextAuth from "next-auth";
import GitHub from "next-auth/providers/github";

export const { handlers, auth, signIn, signOut } = NextAuth({
  providers: [
    GitHub({
      clientId: process.env.GITHUB_ID as string,
      clientSecret: process.env.GITHUB_SECRET as string,
    }),
  ],
  secret: process.env.AUTH_SECRET,
  // pages: {
  //   signIn: '/auth/signin',
  //   error: '/auth/error',
  // },
  callbacks: {
    async jwt({ token, user }) {
      if (user) {
        token.id = user.id;
      }
      return token;
    },
    async session({ session, token }) {
      if (session.user) {
        session.user.id = token.id as string; // 세션에 사용자 ID 추가
      }
      return session;
    },
  },
});

export const GET = handlers.GET;
export const POST = handlers.POST;
```

위 코드에서 `callbacks`는 JWT와 세션에 추가 정보를 넣거나 커스터마이징할 때 사용해요. 여기서는 사용자 ID를 세션에 포함하도록 설정했어요.<br />

### 3️⃣ 인증 Provider (예: GitHub) 추가

위 코드에서 보셨듯이, `providers` 배열에 원하는 인증 Provider를 추가하면 돼요. GitHub 외에도 Google, Facebook, Credentials 등 다양한 Provider를 지원해요. 각 Provider는 클라이언트 ID와 시크릿을 요구하며, 이는 해당 서비스의 개발자 콘솔에서 발급받을 수 있어요.<br />

GitHub OAuth 앱을 설정할 때, `Authorization callback URL`은 `http://localhost:3000/api/auth/callback/github` (개발 환경 기준)으로 설정해야 해요.<br />

## 🧑‍💻 클라이언트 컴포넌트에서 세션 관리하기

클라이언트 컴포넌트에서는 `SessionProvider`와 `useSession` 훅을 사용하여 세션 정보를 쉽게 관리할 수 있어요.<br />

### 0️⃣ `SessionProvider` 설정

Auth.js는 클라이언트 컴포넌트에서 세션에 접근할 수 있도록 `SessionProvider`를 제공해요. 이 Provider는 애플리케이션의 최상단(`app/layout.tsx` 등)에 위치해야 해요.<br />

```tsx showLineNumbers {7-9, 14}
// app/providers.tsx (클라이언트 컴포넌트)
"use client";

import { SessionProvider } from "next-auth/react";
import React from "react";

export default function AuthProvider({
  children,
}: {
  children: React.ReactNode;
}) {
  return <SessionProvider>{children}</SessionProvider>;
}

// app/layout.tsx (서버 컴포넌트)
import AuthProvider from "./providers";

export default function RootLayout({
  children,
}: {
  children: React.ReactNode;
}) {
  return (
    <html lang="ko">
      <body>
        <AuthProvider>{children}</AuthProvider>
      </body>
    </html>
  );
}
```

`SessionProvider`는 클라이언트 컴포넌트여야 하므로, 별도의 `providers.tsx` 파일을 만들고 `"use client";` 지시어를 추가하는 것이 일반적인 패턴이에요.<br />

### 1️⃣ `useSession` 훅을 이용한 세션 접근

`SessionProvider`로 감싸진 모든 클라이언트 컴포넌트에서는 `useSession` 훅을 사용하여 현재 사용자 세션 정보에 접근할 수 있어요.<br />

```tsx showLineNumbers {2, 6, 8, 10, 11}
// app/components/AuthStatus.tsx (클라이언트 컴포넌트)
"use client";

import { useSession } from "next-auth/react";

export default function AuthStatus() {
  const { data: session, status } = useSession();

  if (status === "loading") {
    return <p>세션 정보를 불러오는 중이에요...</p>;
  }

  if (session) {
    return (
      <div>
        <p>{session.user?.name}님, 환영해요!</p>
        <p>이메일: {session.user?.email}</p>
      </div>
    );
  }

  return <p>로그인이 필요해요.</p>;
}
```

### 2️⃣ 로그인/로그아웃 UI 구현 (`signIn`, `signOut`)

`next-auth/react`에서 제공하는 `signIn`과 `signOut` 함수를 사용하여 로그인 및 로그아웃 기능을 구현할 수 있어요.<br />

```tsx showLineNumbers {2, 6, 12, 13, 17, 18}
// app/components/AuthButtons.tsx (클라이언트 컴포넌트)
"use client";

import { signIn, signOut, useSession } from "next-auth/react";

export default function AuthButtons() {
  const { data: session } = useSession();

  if (session) {
    return (
      <button
        onClick={() => signOut()}
        className="rounded bg-red-500 p-2 text-white"
      >
        로그아웃
      </button>
    );
  }

  return (
    <button
      onClick={() => signIn("github")}
      className="rounded bg-blue-500 p-2 text-white"
    >
      GitHub로 로그인
    </button>
  );
}
```

### 3️⃣ `useSession`의 `status`를 활용한 로딩 및 인증 상태 처리

`useSession` 훅은 `status` 값을 반환해요. 이 값은 `"loading"`, `"authenticated"`, `"unauthenticated"` 중 하나로, 세션 상태에 따라 UI를 다르게 보여줄 때 유용해요.<br />

```tsx showLineNumbers {6, 8-10, 12-14, 16-18}
// app/components/ProtectedRouteClient.tsx (클라이언트 컴포넌트)
"use client";

import { useSession } from "next-auth/react";
import { useRouter } from "next/navigation";

export default function ProtectedRouteClient({
  children,
}: {
  children: React.ReactNode;
}) {
  const { status } = useSession();
  const router = useRouter();

  if (status === "loading") {
    return <p>인증 상태 확인 중이에요...</p>;
  }

  if (status === "unauthenticated") {
    router.push("/api/auth/signin"); // 로그인 페이지로 리다이렉트
    return null;
  }

  return <>{children}</>;
}
```

## 🚀 서버 컴포넌트에서 안전하게 세션 접근하기

Auth.js v5부터는 서버 컴포넌트에서 세션에 접근하는 방식이 더욱 간결해지고 안전해졌어요. 더 이상 `getServerSession`을 직접 호출할 필요 없이, Auth.js에서 내보내는 `auth()` 함수를 사용하면 돼요.<br />

### 0️⃣ `getServerSession` 대신 `auth()` 함수 사용 (Auth.js v5+)

이전 버전의 NextAuth.js에서는 `getServerSession`을 사용하여 서버 사이드에서 세션에 접근했어요. 하지만 Auth.js v5 (`@auth/nextjs`)에서는 `app/api/auth/[...nextauth]/route.ts` 파일에서 내보낸 `auth` 함수를 직접 임포트해서 사용할 수 있어요.<br />

```tsx showLineNumbers {3, 6-8}
// app/dashboard/page.tsx (서버 컴포넌트)
import { auth } from "@/app/api/auth/[...nextauth]/route"; // Auth.js 핸들러에서 내보낸 auth 함수 임포트
import { redirect } from "next/navigation";

export default async function DashboardPage() {
  const session = await auth();
  if (!session) {
    redirect("/api/auth/signin"); // 로그인되지 않았다면 로그인 페이지로 리다이렉트
  }

  return (
    <main>
      <h1>대시보드</h1>
      <p>{session.user?.name}님, 대시보드에 오신 것을 환영해요!</p>
      <p>이메일: {session.user?.email}</p>
    </main>
  );
}
```

<Blockquote type="tip">
  `auth()` 함수는 서버 컴포넌트나 Route Handler에서만 호출해야 해요. 클라이언트
  컴포넌트에서는 `useSession` 훅을 사용해야 해요.
</Blockquote>

### 1️⃣ 서버 컴포넌트에서 세션 정보 활용 예시

위 대시보드 예시처럼, `auth()` 함수를 통해 얻은 세션 객체를 사용하여 사용자 이름, 이메일, ID 등 필요한 정보를 서버 컴포넌트 내에서 직접 활용할 수 있어요. 이는 민감한 데이터를 클라이언트에 노출하지 않고 서버에서 처리해야 할 때 매우 유용해요.<br />

### 2️⃣ 미들웨어 (Middleware)를 이용한 라우트 보호

특정 경로에 대한 접근을 인증된 사용자에게만 허용하고 싶다면, Next.js 미들웨어(`middleware.ts`)를 활용하는 것이 효과적이에요. Auth.js는 미들웨어와 통합하기 위한 편리한 방법을 제공해요.<br />

```tsx showLineNumbers {2, 4-7, 9-11}
// middleware.ts
import { auth } from "@/app/api/auth/[...nextauth]/route";

export default auth((req) => {
  if (!req.auth && req.nextUrl.pathname.startsWith("/dashboard")) {
    const newUrl = new URL("/api/auth/signin", req.nextUrl.origin);
    return Response.redirect(newUrl);
  }
  // 다른 경로에 대한 추가적인 로직을 여기에 추가할 수 있어요.
});

export const config = {
  matcher: ["/dashboard/:path*"], // /dashboard 또는 그 하위 경로에만 미들웨어 적용
};
```

위 `middleware.ts` 파일은 `/dashboard` 경로로 접근하는 요청에 대해 사용자가 인증되었는지(`req.auth`) 확인해요. 인증되지 않았다면 로그인 페이지로 리다이렉트 시키는 역할을 해요.<br />

<Blockquote type="info">
  `middleware.ts` 파일은 `app/` 디렉토리와 같은 레벨에 위치해야 해요. (예:
  `src/middleware.ts` 또는 `middleware.ts`)
</Blockquote>

## 🚦 실전 예시: 로그인/로그아웃 페이지 및 보호된 대시보드

이제 위에서 배운 내용을 바탕으로 간단한 인증 플로우를 구현해 볼게요.<br />

### 0️⃣ 로그인 페이지 (클라이언트 컴포넌트)

`app/auth/signin/page.tsx` 파일을 만들고, AuthButtons 컴포넌트를 사용해서 로그인 버튼을 표시해요.<br />

```tsx showLineNumbers
// app/auth/signin/page.tsx
import AuthButtons from "@/app/components/AuthButtons";

export default function SignInPage() {
  return (
    <div className="flex min-h-screen flex-col items-center justify-center">
      <h1 className="mb-4 text-2xl font-bold">로그인이 필요해요</h1>
      <AuthButtons />
    </div>
  );
}
```

### 1️⃣ 대시보드 페이지 (서버 컴포넌트)

`app/dashboard/page.tsx` 파일은 서버 컴포넌트로, `auth()` 함수를 사용하여 세션 정보를 가져와요. 인증되지 않은 사용자라면 로그인 페이지로 리다이렉트 시킬 거예요.<br />

```tsx showLineNumbers
// app/dashboard/page.tsx
import { auth } from "@/app/api/auth/[...nextauth]/route";
import { redirect } from "next/navigation";
import AuthButtons from "@/app/components/AuthButtons";

export default async function DashboardPage() {
  const session = await auth();

  if (!session) {
    redirect("/api/auth/signin");
  }

  return (
    <main className="flex min-h-screen flex-col items-center justify-center p-4">
      <h1 className="mb-6 text-3xl font-bold">대시보드</h1>
      <p className="mb-2 text-lg">환영합니다, {session.user?.name}님!</p>
      <p className="text-md mb-8 text-gray-600">
        이메일: {session.user?.email}
      </p>
      <AuthButtons />
    </main>
  );
}
```

### 2️⃣ `middleware.ts`를 활용한 경로 보호

위에서 설명한 `middleware.ts` 파일을 통해 `/dashboard` 경로에 대한 접근을 보호할 수 있어요. 사용자가 `/dashboard`로 직접 접근하려 할 때, 인증되지 않았다면 `app/auth/signin` 페이지로 리다이렉트 시킬 거예요.<br />

이러한 구조를 통해 클라이언트와 서버 양쪽에서 안전하고 효율적인 인증 흐름을 구축할 수 있어요.<br />

## 💡 추가 팁 및 주의사항

Auth.js를 더욱 효과적으로 사용하기 위한 몇 가지 팁과 주의사항을 알려드릴게요.<br />

### 0️⃣ `Next-Auth.js`에서 `Auth.js`로의 마이그레이션 (v4 -> v5)

만약 기존에 `next-auth` (v4)를 사용하고 계셨다면, `auth` 함수를 사용하는 `@auth/nextjs` (v5)로 마이그레이션하는 것을 고려해 보세요. v5는 App Router에 대한 지원이 강화되었고, API가 더 간결해졌어요. 공식 문서의 마이그레이션 가이드를 참고하시면 도움이 될 거예요.<br />

<LinkPreviewCard href="https://authjs.dev/getting-started/migrating-to-v5" />

### 1️⃣ JWT 및 데이터베이스 세션 전략

Auth.js는 기본적으로 JWT (JSON Web Tokens)를 사용하여 세션을 관리해요. 하지만 데이터베이스 어댑터를 추가하여 세션을 데이터베이스에 저장하는 방식도 지원해요. 데이터베이스 세션은 사용자 계정 비활성화 시 즉시 세션을 무효화해야 하는 경우 등에 유용해요.<br />

```tsx showLineNumbers {3-4}
// app/api/auth/[...nextauth]/route.ts (with database adapter)
import NextAuth from "next-auth";
import { PrismaAdapter } from "@auth/prisma-adapter"; // 예시: Prisma 어댑터
import { PrismaClient } from "@prisma/client";

const prisma = new PrismaClient();

export const { handlers, auth, signIn, signOut } = NextAuth({
  adapter: PrismaAdapter(prisma),
  // ... other configurations
});
```

### 2️⃣ 보안 고려사항 (CSRF, 환경 변수 등)

Auth.js는 CSRF(Cross-Site Request Forgery) 공격에 대한 보호 기능을 기본적으로 제공해요. 하지만 환경 변수 (`AUTH_SECRET`, `GITHUB_ID`, `GITHUB_SECRET` 등)는 절대로 클라이언트 사이드에 노출되지 않도록 철저히 관리해야 해요. `.env.local` 파일은 Git에 커밋하지 않도록 `.gitignore`에 추가하는 것을 잊지 마세요.<br />

## 📝 정리하며

오늘은 Next.js App Router 환경에서 Auth.js를 사용하여 사용자 인증 시스템을 구축하는 방법을 자세히 알아보았어요. 서버 컴포넌트와 클라이언트 컴포넌트 간의 세션 관리 차이점과 `auth()` 함수, `useSession` 훅, 그리고 미들웨어를 활용하는 실용적인 접근법을 익히셨을 거예요.<br />

### 0️⃣ 핵심 요약

- **App Router의 인증 변화**: 서버 컴포넌트의 도입으로 세션 관리에 새로운 접근 방식이 필요해요.<br />
- **Auth.js (NextAuth.js)**: Next.js에 최적화된 강력한 인증 라이브러리로, 다양한 Provider와 유연한 설정이 가능해요.<br />
- **클라이언트 컴포넌트**: `SessionProvider`로 감싸고 `useSession` 훅을 사용하여 세션 정보에 접근하고 `signIn`/`signOut` 함수로 인증 흐름을 제어해요.<br />
- **서버 컴포넌트**: `app/api/auth/[...nextauth]/route.ts`에서 내보낸 `auth()` 함수를 `await`하여 서버 사이드에서 안전하게 세션 정보를 가져와요.<br />
- **미들웨어**: `middleware.ts` 파일에서 `auth()` 함수를 사용하여 특정 경로에 대한 접근을 인증 여부에 따라 제어할 수 있어요.<br />
