## 🤔 왜 Mapped Types와 `as` 절이 중요한가요?

### 0️⃣ 타입 변환의 필요성

프론트엔드 개발을 하다 보면 서버에서 받아온 데이터 형태를 클라이언트의 UI 로직에 맞게 변환해야 하는 경우가 많아요. 예를 들어, API 응답의 키 이름을 변경하거나, 특정 필드의 타입을 옵셔널로 만들거나, 모든 필드를 읽기 전용으로 만들어야 할 때가 있죠.<br />
이런 상황에서 일일이 수동으로 타입을 정의하는 것은 비효율적이고 오류 발생 가능성이 높아요. TypeScript는 이러한 문제에 대한 우아한 해결책을 제공하는데, 그 핵심에 바로 Mapped Types가 있답니다.

### 1️⃣ 기존 Mapped Types의 한계와 `as` 절의 등장

초기 Mapped Types는 기존 타입의 모든 속성을 순회하며 새로운 타입을 생성하는 강력한 기능이었어요. `Partial<T>`, `Readonly<T>` 같은 내장 유틸리티 타입들이 대표적인 예시죠.<br />
하지만 기존 Mapped Types는 키의 이름을 직접적으로 변환하는 기능에는 한계가 있었어요. 예를 들어, `userId` 키를 `id`로 바꾸거나, `name` 키를 `userName`으로 바꾸는 등의 작업은 불가능했죠.<br />
이러한 한계를 극복하기 위해 TypeScript 4.1부터 `as` 절이 도입되었어요. `as` 절을 사용하면 Mapped Types 내에서 객체의 키를 동적으로 변환할 수 있게 되었고, 이는 TypeScript의 타입 시스템을 훨씬 더 유연하고 강력하게 만들었답니다.

## ⚙️ Mapped Types 기본기 다지기

### 0️⃣ Mapped Types란 무엇인가요?

Mapped Types는 기존 타입의 각 속성을 순회하면서 새로운 타입을 생성하는 제네릭 타입이에요. 마치 JavaScript의 `map` 함수가 배열의 각 요소를 변환하여 새로운 배열을 만드는 것과 유사하다고 생각하시면 돼요.<br />
가장 기본적인 형태는 다음과 같아요.

```ts showLineNumbers
type MyMappedType<T> = {
  [K in keyof T]: T[K]; // T의 모든 키(K)를 순회하며 T[K] 타입을 가진 새로운 속성 생성
};

interface User {
  id: number;
  name: string;
  email: string;
}

type PartialUser = Partial<User>; // 내장 Mapped Type: 모든 속성을 옵셔널로 만듦
// { id?: number; name?: string; email?: string; }

type ReadonlyUser = Readonly<User>; // 내장 Mapped Type: 모든 속성을 읽기 전용으로 만듦
// { readonly id: number; readonly name: string; readonly email: string; }

type NullableUser = {
  [K in keyof User]: User[K] | null; // 모든 속성을 null 허용 타입으로 변환
};
// { id: number | null; name: string | null; email: string | null; }
```

위 코드에서 보듯이 `[K in keyof T]` 구문이 핵심이에요. `keyof T`는 `T` 타입의 모든 키를 유니온 타입으로 가져오고, `in` 연산자는 이 키들을 순회하며 새로운 속성을 정의할 수 있게 해줘요.<br />

<Blockquote type="info">
`keyof any`는 `string | number | symbol`을 반환해요. 객체 리터럴 타입의 키는 `string` 또는 `number` 리터럴 타입이 될 수 있고, `symbol`은 `Symbol()`로 생성된 심볼을 키로 사용할 때 나타날 수 있어요.
</Blockquote>

### 1️⃣ `as` 절을 이용한 키 리매핑 (Key Remapping)

이제 `as` 절을 활용하여 키 자체를 변환하는 방법을 알아볼게요. `as` 절은 `[K in keyof T as NewKeyType]` 형태로 사용되며, `NewKeyType` 부분에 새로운 키의 타입을 정의할 수 있어요.<br />
이때 `NewKeyType`은 `string | number | symbol`의 서브타입이어야 해요. 주로 `Template Literal Types`와 함께 사용되어 유연한 키 변환을 가능하게 한답니다.

#### 🅰️ 기본 문법과 `Template Literal Types` 활용

예를 들어, 특정 객체의 모든 키에 접두사를 붙여 새로운 타입을 만들고 싶을 때 `as` 절을 사용할 수 있어요.

```ts showLineNumbers {5-7, 10-14}
interface UserInfo {
  id: number;
  name: string;
}

type WithPrefix<T> = {
  [K in keyof T as `data_${string & K}`]: T[K]; // 'data_' 접두사 추가
};

type PrefixedUserInfo = WithPrefix<UserInfo>;
/*
{ // 결과 타입
  data_id: number;
  data_name: string;
}
*/

const user: PrefixedUserInfo = {
  data_id: 1,
  data_name: "블루",
};

console.log(user);
```

위 코드에서 `string & K`는 `K`가 `string` 타입임을 명시해주는 역할을 해요. `keyof T`는 `string | number | symbol` 유니온 타입을 반환할 수 있기 때문에, `Template Literal Types`와 함께 사용하려면 `string` 타입으로 제한해주는 것이 안전하답니다.<br />

#### 🅱️ `Capitalize` 및 `Uncapitalize` 유틸리티 타입 활용

TypeScript는 키 변환에 유용한 내장 유틸리티 타입인 `Capitalize`, `Uncapitalize`, `Uppercase`, `Lowercase`를 제공해요. 이를 `as` 절과 함께 사용하면 더욱 강력한 키 변환이 가능하죠.

```ts showLineNumbers {5-7, 10-14, 17-21}
interface Product {
  id: number;
  name: string;
  price: number;
}

type Getters<T> = {
  [K in keyof T as `get${Capitalize<string & K>}`]: () => T[K]; // 'get' 접두사와 첫 글자 대문자화
};

type ProductGetters = Getters<Product>;
/*
{ // 결과 타입
  getId: () => number;
  getName: () => string;
  getPrice: () => number;
}
*/

type Setters<T> = {
  [K in keyof T as `set${Capitalize<string & K>}`]: (value: T[K]) => void; // 'set' 접두사와 첫 글자 대문자화
};

type ProductSetters = Setters<Product>;
/*
{ // 결과 타입
  setId: (value: number) => void;
  setName: (value: string) => void;
  setPrice: (value: number) => void;
}
*/
```

이처럼 `Capitalize<string & K>`를 사용하면 키의 첫 글자를 대문자로 만들 수 있어요. 이는 getter/setter 패턴을 타입으로 정의할 때 매우 유용하답니다.

## 🧪 실용적인 타입 변환 패턴 익히기

### 0️⃣ 특정 접두사/접미사 추가 및 제거

실무에서는 특정 도메인 객체에 접두사를 붙이거나, 반대로 불필요한 접미사를 제거해야 할 때가 많아요. `as` 절과 `Template Literal Types`, 그리고 조건부 타입(`extends`)을 조합하면 이러한 작업을 타입 레벨에서 처리할 수 있어요.

```ts showLineNumbers {5-9, 12-16, 19-23}
type RemovePrefix<T extends string, Prefix extends string> = 
  T extends `${Prefix}${infer Rest}` ? Rest : T;

interface SystemSettings {
  SYSTEM_THEME: 'dark' | 'light';
  SYSTEM_LANGUAGE: 'ko' | 'en';
  USER_ID: string; // SYSTEM_ 접두사가 없는 키
}

type CleanSettings = {
  [K in keyof SystemSettings as RemovePrefix<string & K, 'SYSTEM_'>]: SystemSettings[K];
};
/*
{ // 결과 타입
  THEME: 'dark' | 'light';
  LANGUAGE: 'ko' | 'en';
  USER_ID: string; // SYSTEM_ 접두사가 없으면 그대로 유지
}
*/

const settings: CleanSettings = {
  THEME: 'dark',
  LANGUAGE: 'ko',
  USER_ID: 'user123',
};

console.log(settings);
```

`RemovePrefix` 유틸리티 타입은 조건부 타입과 `infer` 키워드를 활용하여 `Prefix`가 붙어있는 문자열에서 `Prefix`를 제거하고 나머지(`Rest`)를 반환해요. 만약 `Prefix`가 없다면 원본 문자열을 그대로 반환하죠. 이를 `as` 절에서 사용하면 동적으로 키를 변환할 수 있답니다.

<Blockquote type="tip">
`infer` 키워드는 조건부 타입 내에서 타입을 추론하여 새로운 타입 변수로 사용할 수 있게 해주는 강력한 기능이에요. 문자열 조작뿐만 아니라 배열, 객체 등 다양한 타입에서 특정 부분을 추출할 때 유용하게 쓰여요.
</Blockquote>

### 1️⃣ 값의 타입에 따라 키 변환하기

특정 타입의 값에 대해서만 키를 변환하고 싶을 때도 있어요. 예를 들어, 객체에서 함수 타입의 속성만 추출하여 `on` 접두사를 붙이고 싶을 때 유용해요.

```ts showLineNumbers {5-12, 15-20}
interface ComponentProps {
  id: string;
  onClick: (event: MouseEvent) => void;
  onHover: () => void;
  isActive: boolean;
}

type EventHandlers<T> = {
  [K in keyof T as K extends `on${infer EventName}` // 'on' 접두사가 있는 키만 선택
    ? `${Uncapitalize<EventName>}Handler` // 'on' 접두사 제거 후 'Handler' 접미사 추가
    : never // 'on' 접두사가 없으면 제외
  ]: T[K];
};

type MyComponentEventHandlers = EventHandlers<ComponentProps>;
/*
{ // 결과 타입
  clickHandler: (event: MouseEvent) => void;
  hoverHandler: () => void;
}
*/

const handlers: MyComponentEventHandlers = {
  clickHandler: (e) => console.log(e.type),
  hoverHandler: () => console.log('hovered'),
};

console.log(handlers);
```

이 패턴에서는 조건부 타입(`K extends \`on${infer EventName}\``)을 사용하여 `on`으로 시작하는 키만 선택하고, `never` 타입을 반환하여 나머지 키는 제외하고 있어요. `never`는 어떤 타입도 할당할 수 없는 타입으로, Mapped Types에서 특정 속성을 제거할 때 사용된답니다.

### 2️⃣ 중첩된 객체 타입 변환 (Deep Transformation)

가장 복잡하지만 실무에서 유용하게 사용될 수 있는 패턴은 중첩된 객체에 대한 재귀적인 타입 변환이에요. Mapped Types는 재귀적으로 자신을 호출하여 깊이 있는 구조를 처리할 수 있답니다.

```ts showLineNumbers {5-11, 14-23}
type DeepReadonly<T> = T extends object
  ? {
      readonly [K in keyof T]: DeepReadonly<T[K]>; // 객체면 재귀적으로 호출
    }
  : T; // 객체가 아니면 그대로 유지

interface Config {
  app: {
    name: string;
    version: string;
  };
  database: {
    host: string;
    port: number;
  };
}

type ReadonlyConfig = DeepReadonly<Config>;
/*
{ // 결과 타입
  readonly app: {
    readonly name: string;
    readonly version: string;
  };
  readonly database: {
    readonly host: string;
    readonly port: number;
  };
}
*/

// ReadonlyConfig.app.name = "New App"; // Error: Cannot assign to 'name' because it is a read-only property.

const config: ReadonlyConfig = {
  app: { name: "My App", version: "1.0.0" },
  database: { host: "localhost", port: 5432 },
};

console.log(config);
```

`DeepReadonly` 타입은 먼저 `T extends object`를 통해 현재 타입이 객체인지 확인해요. 객체라면 `[K in keyof T]: DeepReadonly<T[K]>`를 통해 모든 속성을 `readonly`로 만들고, 그 속성 값이 다시 객체라면 `DeepReadonly`를 재귀적으로 호출하여 깊이 있는 변환을 수행하죠. 객체가 아니라면 원시 타입을 그대로 반환한답니다.

<Blockquote type="warning">
재귀적인 Mapped Types는 타입 시스템에 큰 부담을 줄 수 있어요. 너무 깊은 중첩이나 무한 루프에 빠지지 않도록 주의해야 해요. TypeScript 컴파일러는 재귀 깊이에 대한 제한이 있답니다.
</Blockquote>

## 💡 주의사항 및 활용 팁

### 0️⃣ 오버헤드와 가독성

Mapped Types와 `as` 절은 매우 강력하지만, 너무 복잡하게 사용하면 타입 추론에 시간이 오래 걸리거나 코드의 가독성이 떨어질 수 있어요. 특히 재귀적인 타입이나 복잡한 조건부 타입을 많이 사용할 경우 더욱 그렇답니다.<br />
가독성을 위해 여러 유틸리티 타입으로 분리하여 작성하거나, 주석을 충분히 달아주는 것이 좋아요.

### 1️⃣ 유틸리티 타입 라이브러리 활용

많은 고급 타입 변환 패턴은 이미 `ts-toolbelt`와 같은 유틸리티 타입 라이브러리에 구현되어 있어요. 이러한 라이브러리를 활용하면 직접 복잡한 타입을 구현할 필요 없이 안정적이고 성능이 검증된 타입을 사용할 수 있답니다.<br />
하지만 내부 동작 원리를 이해하고 사용하는 것이 중요하므로, 학습 목적으로는 직접 구현해보는 것도 좋은 경험이 될 거예요.

<LinkPreviewCard href="https://github.com/millsp/ts-toolbelt" />

### 2️⃣ 타입 추론 문제 해결

때로는 복잡한 Mapped Types를 사용했을 때 TypeScript 컴파일러가 의도한 대로 타입을 추론하지 못하는 경우가 발생할 수 있어요. 이럴 때는 `as const` 어서션이나 명시적인 타입 어서션(`as Type`)을 활용하여 컴파일러에게 힌트를 주거나, 타입을 좀 더 단순하게 분리하여 문제를 해결할 수 있답니다.

이러한 고급 타입 기술은 라이브러리 개발이나 복잡한 비즈니스 로직의 타입을 정의할 때 빛을 발해요. 단순히 `interface`나 `type`을 선언하는 것을 넘어, 타입을 동적으로 생성하고 조작하는 능력은 여러분의 TypeScript 실력을 한 단계 성장시키는 중요한 열쇠가 될 거예요.<br />
오늘 배운 내용을 바탕으로 실제 프로젝트에 적용해보면서 자신만의 유틸리티 타입을 만들어보고, TypeScript의 매력에 더 깊이 빠져보시길 바라요!
