## 🤔 왜 국제화(i18n)가 중요한가요?

### 0️⃣ 글로벌 서비스의 필수 요소예요

현대 웹 서비스는 더 이상 특정 지역 사용자만을 위한 것이 아니에요.<br />
전 세계 사용자를 대상으로 서비스를 제공하려면 각 사용자의 모국어로 콘텐츠를 제공하는 것이 매우 중요해요.<br />
국제화(Internationalization, i18n)는 바로 이런 다국어 지원을 가능하게 하는 개발 과정을 의미해요.<br />
사용자가 친숙한 언어로 서비스를 이용할 수 있도록 하면 사용자 경험(UX)이 크게 향상되고, 서비스의 접근성과 시장 확장성도 자연스럽게 높아져요.

### 1️⃣ App Router 환경에서 i18n의 변화를 이해해야 해요

Next.js 13+ 버전에서 도입된 App Router는 기존 Pages Router와는 다른 방식으로 동작해요.<br />
특히 서버 컴포넌트(Server Components)의 도입은 데이터 페칭 및 렌더링 방식에 큰 변화를 가져왔고, 이는 국제화 구현 방식에도 영향을 미쳐요.<br />
Pages Router에서는 주로 `next.config.js`의 `i18n` 설정을 사용했지만, App Router에서는 미들웨어(Middleware)와 동적 라우팅(Dynamic Routing)을 활용하는 것이 일반적이에요.<br />
이 글에서는 App Router의 특성을 최대한 활용하여 효율적이고 견고한 i18n 시스템을 구축하는 방법을 알려드릴 거예요.

## ⚙️ Next.js App Router i18n 핵심 전략

Next.js App Router에서 국제화를 구현하는 데에는 여러 방법이 있지만, `next-intl` 라이브러리를 활용하는 것이 가장 일반적이고 효율적인 방법 중 하나예요.<br />
`next-intl`은 App Router의 서버 컴포넌트와 클라이언트 컴포넌트 모두에서 원활하게 동작하며, 다양한 국제화 기능을 편리하게 제공해요.

### 0️⃣ 기본 개념: 언어 감지, 라우팅, 텍스트 관리예요

국제화 시스템을 구축할 때 고려해야 할 핵심 요소들은 다음과 같아요.<br />

- **언어 감지 (Locale Detection):** 사용자의 브라우저 설정, IP 주소, 또는 이전에 저장된 쿠키 등을 기반으로 사용자의 선호 언어를 감지하는 기능이에요.<br />
- **라우팅 (Routing):** URL에 언어 코드를 포함시켜 특정 언어 버전의 페이지로 라우팅하는 방식이에요. (예: `/en/about`, `/ko/about`)<br />
- **텍스트 관리 (Message Management):** 애플리케이션 내의 모든 텍스트를 언어별로 분리하여 관리하고, 필요한 곳에서 불러와 사용하는 기능이에요.

### 1️⃣ `next-intl` 라이브러리를 선택하는 이유예요

`next-intl`은 Next.js App Router에 최적화된 국제화 라이브러리예요.<br />

- **App Router 지원:** 서버 컴포넌트와 클라이언트 컴포넌트 모두에서 번역 기능을 사용할 수 있도록 설계되어 있어요.<br />
- **타입스크립트 지원:** 메시지(번역 텍스트)에 대한 강력한 타입스크립트 지원을 통해 개발 시 오류를 줄이고 생산성을 높여줘요.<br />
- **미들웨어 통합:** Next.js 미들웨어와 연동하여 언어 감지 및 라우팅을 손쉽게 처리할 수 있어요.<br />
- **유연한 번역 형식:** JSON 파일을 기반으로 번역 메시지를 관리하며, ICU Message Format을 지원하여 복수형, 성별 등 복잡한 번역 규칙을 처리할 수 있어요.

### 2️⃣ `next-intl` 설치 및 기본 설정이에요

먼저 `next-intl` 라이브러리를 설치해 주세요.

```bash showLineNumbers

# 또는 yarn add next-intl
# 또는 pnpm add next-intl
```

설치 후, 프로젝트 루트에 `i18n.ts` 파일을 생성하고 기본 설정을 추가해 줄게요.<br />
이 파일은 각 로케일(locale)에 해당하는 번역 메시지를 동적으로 로드하는 역할을 해요.

```tsx showLineNumbers

export default getRequestConfig(async ({ locale }) => ({
```

프로젝트 루트에 `messages` 디렉토리를 만들고, 각 언어별 JSON 파일을 생성해 주세요.<br />

## 🛠️ 단계별 구현 가이드

이제 본격적으로 App Router에 `next-intl`을 적용해 볼까요?

### 0️⃣ 미들웨어를 활용한 언어 감지 및 리다이렉션이에요

Next.js 미들웨어는 요청이 처리되기 전에 실행되는 코드예요.<br />
이를 활용하여 사용자의 선호 언어를 감지하고, 해당 언어의 URL로 리다이렉션할 수 있어요.<br />
프로젝트 루트에 `middleware.ts` 파일을 생성하고 다음 코드를 추가해 주세요.

```tsx showLineNumbers {7-10, 14-16}
import createMiddleware from "next-intl/middleware";

export default createMiddleware({
  // A list of all locales that are supported
  locales: ["en", "ko"],

  // Used when no locale matches
  defaultLocale: "en",
  localePrefix: "as-needed",
});

export const config = {
  // Match only internationalized pathnames
  matcher: ["/", "/(ko|en)/:path*"],
};
```

- `locales`: 지원하는 모든 로케일 목록을 지정해요.<br />
- `defaultLocale`: URL에 로케일이 명시되지 않았을 때 사용될 기본 로케일을 지정해요.<br />
- `localePrefix: 'as-needed'`: 기본 로케일(여기서는 `en`)의 경우 URL에 접두사를 붙이지 않고, 다른 로케일(`ko`)에만 접두사를 붙이도록 설정해요. (예: `/about` 대신 `/ko/about`).<br />
- `matcher`: 미들웨어가 적용될 경로를 정규식으로 지정해요. `/(ko|en)/:path*`는 `/ko/` 또는 `/en/`으로 시작하는 모든 경로와 루트 경로(`/`)에 미들웨어를 적용하라는 의미예요.

### 1️⃣ App Router에서 로케일 라우팅 설정하기예요

App Router에서는 `[locale]`이라는 동적 세그먼트를 사용하여 로케일 라우팅을 구현해요.<br />
이렇게 하면 각 로케일에 해당하는 페이지를 쉽게 관리할 수 있어요.<br />

`app/[locale]/layout.tsx` 파일을 생성하여 모든 페이지에 `next-intl`의 `NextIntlClientProvider`를 적용해 주세요.

```tsx showLineNumbers {13-17}
import { NextIntlClientProvider } from "next-intl";
import { getRequestConfig } from "next-intl/server";

type Props = {
  children: React.ReactNode;
  params: { locale: string };
};

export default async function LocaleLayout({
  children,
  params: { locale },
}: Props) {
  const messages = (await import(`../../messages/${locale}.json`)).default;

  return (
    <html lang={locale}>
      <body>
        <NextIntlClientProvider messages={messages}>
          {children}
        </NextIntlClientProvider>
      </body>
    </html>
  );
}
```

- `getRequestConfig`는 서버에서 번역 메시지를 가져오는 역할을 해요.<br />
- `NextIntlClientProvider`는 클라이언트 컴포넌트에서 번역 메시지에 접근할 수 있도록 컨텍스트를 제공해요.<br />

또한, `app/layout.tsx` 파일은 삭제하거나, 전역적인 설정을 담당하도록 비워두고 `app/[locale]/layout.tsx`가 실제 레이아웃 역할을 하도록 해주세요.<br />

### 2️⃣ 서버 컴포넌트에서 다국어 텍스트 사용하기예요

`next-intl`은 서버 컴포넌트에서도 번역 기능을 쉽게 사용할 수 있도록 `useTranslations` 훅의 서버 버전과 `getTranslator` 함수를 제공해요.<br />
하지만 `next-intl/server`에서 제공하는 `getTranslator`를 사용하는 것이 더 명확하고 권장되는 방법이에요.<br />

`app/[locale]/page.tsx`:

```tsx showLineNumbers {4, 7-9, 13}
import { getTranslator } from "next-intl/server";
import Link from "next/link";

export default async function IndexPage({
  params: { locale },
}: {
  params: { locale: string };
}) {
  const t = await getTranslator(locale, "Index");

  return (
    <div>
      <h1>{t("title")}</h1>
      <p>{t("description")}</p>
      <Link href="/about">{t("changeLanguage")}</Link>
    </div>
  );
}
```

- `getTranslator(locale, 'Index')`를 통해 `Index` 네임스페이스에 해당하는 번역 함수 `t`를 가져와요.<br />
- `t('title')`과 같이 키를 사용하여 번역된 텍스트를 출력할 수 있어요.

### 3️⃣ 클라이언트 컴포넌트에서 다국어 텍스트 사용하기예요

클라이언트 컴포넌트에서는 `next-intl`의 `useTranslations` 훅을 사용해요.<br />

먼저 `app/[locale]/components/LocaleSwitcher.tsx` 같은 클라이언트 컴포넌트를 만들어 볼게요.<br />

```tsx showLineNumbers {1, 3, 5, 10-14, 21-25}
"use client";

import { useTranslations } from "next-intl";
import { useRouter, usePathname } from "next/navigation";
import { useLocale } from "next-intl";

export function LocaleSwitcher() {
  const t = useTranslations("Index");
  const router = useRouter();
  const pathname = usePathname();
  const currentLocale = useLocale();

  const handleLocaleChange = (e: React.ChangeEvent<HTMLSelectElement>) => {
    const newLocale = e.target.value;
    // 현재 경로에서 로케일 부분만 변경하여 새 경로를 생성
    const newPath = `/${newLocale}${pathname.substring(3)}`; // 예: /ko/about -> /en/about
    router.push(newPath);
  };

  return (
    <select onChange={handleLocaleChange} value={currentLocale}>
      <option value="en">English</option>
      <option value="ko">한국어</option>
    </select>
  );
}
```

그리고 이 클라이언트 컴포넌트를 서버 컴포넌트인 `app/[locale]/page.tsx`에서 불러와 사용하면 돼요.

`app/[locale]/page.tsx` (수정):

```tsx showLineNumbers {2, 14}
import { getTranslator } from "next-intl/server";
import { LocaleSwitcher } from "./components/LocaleSwitcher"; // 클라이언트 컴포넌트 임포트
import Link from "next/link";

export default async function IndexPage({
  params: { locale },
}: {
  params: { locale: string };
}) {
  const t = await getTranslator(locale, "Index");

  return (
    <div>
      <h1>{t("title")}</h1>
      <p>{t("description")}</p>
      <Link href="/about">{t("changeLanguage")}</Link>
      <LocaleSwitcher /> {/* 클라이언트 컴포넌트 사용 */}
    </div>
  );
}
```

### 4️⃣ 동적 라우팅 및 URL 매개변수 처리예요

동적 라우팅 (`app/[locale]/[slug]/page.tsx`와 같은 형태)에서도 `params.locale`을 통해 현재 로케일을 얻을 수 있어요.<br />

`app/[locale]/about/page.tsx`:

```tsx showLineNumbers {4, 7-9}
  return (
    <div>

      <p>{t("content")}</p>
```

### 5️⃣ SEO를 위한 `alternate` 태그 추가예요

다국어 사이트의 SEO는 매우 중요해요.<br />
검색 엔진이 각 언어 버전의 페이지를 올바르게 인식하도록 `rel="alternate"` 링크 태그를 `<head>`에 추가해야 해요.<br />
`next-intl`은 이를 위한 유틸리티를 제공하지 않으므로, Next.js의 Metadata API를 활용하여 직접 추가해 줄 수 있어요.<br />

`app/[locale]/layout.tsx`에 `generateMetadata` 함수를 추가해 볼게요.

```tsx showLineNumbers {3, 10-23, 31}
import { NextIntlClientProvider } from "next-intl";
import { getRequestConfig } from "next-intl/server";
import type { Metadata } from "next";

type Props = {
  children: React.ReactNode;
  params: { locale: string };
};

export async function generateMetadata({
  params: { locale },
}: Props): Promise<Metadata> {
  const messages = (await import(`../../messages/${locale}.json`)).default;
  const t = (key: string) => messages.Index[key as keyof typeof messages.Index];

  return {
    title: t("title"),
    description: t("description"),
    alternates: {
      canonical: `/${locale}`,
      languages: {
        en: "/en",
        ko: "/ko",
        "x-default": "/en", // 기본 언어 (폴백)
      },
    },
  };
}

export default async function LocaleLayout({
  children,
  params: { locale },
}: Props) {
  const messages = (await import(`../../messages/${locale}.json`)).default;

  return (
    <html lang={locale}>
      <body>
        <NextIntlClientProvider messages={messages}>
          {children}
        </NextIntlClientProvider>
      </body>
    </html>
  );
}
```

- `generateMetadata` 함수는 서버에서 실행되며, 페이지의 메타데이터를 동적으로 생성해요.<br />
- `alternates.languages` 객체에 각 로케일별 URL과 `x-default` (기본 폴백 언어)를 지정하여 검색 엔진에 힌트를 제공해요.<br />
- 이렇게 설정하면 검색 엔진이 특정 언어 사용자를 위한 올바른 페이지를 찾을 수 있도록 도와준답니다.

## 💡 실전 팁 및 고려사항

성공적인 국제화 구현을 위해 몇 가지 추가 팁을 알려드릴게요.

### 0️⃣ 번역 파일 관리 전략이에요

프로젝트 규모가 커지면 번역 파일의 양도 많아지고 관리하기 어려워질 수 있어요.<br />

- **네임스페이스 분리:** `Index`, `About`처럼 페이지나 컴포넌트 단위로 번역 메시지를 네임스페이스로 분리하면 관리하기 용이해요.<br />
- **번역 관리 서비스 활용:** Crowdin, Lokalise, Transifex와 같은 전문 번역 관리 서비스를 사용하면 번역 프로세스를 효율적으로 관리하고 팀원들과 협업할 수 있어요.<br />
- **ICU Message Format:** 복수형, 성별, 날짜/시간 형식 등 복잡한 번역 규칙은 ICU Message Format을 활용하여 처리할 수 있어요. `next-intl`은 이를 지원해요.<br />

<LinkPreviewCard href="https://next-intl-docs.vercel.app/docs/usage/messages" />

### 1️⃣ 폴백 로케일 및 누락된 번역 처리예요

번역 파일에 특정 키가 누락되었을 때 어떻게 처리할지 전략을 세워야 해요.<br />
`next-intl`은 기본적으로 누락된 키에 대해 경고를 발생시키고, 해당 키를 그대로 출력해요.<br />

`i18n.ts` 파일에서 `defaultMessage` 옵션을 사용하여 누락된 번역에 대한 폴백 메시지를 지정할 수도 있어요.<br />

```tsx showLineNumbers {6-9}
import { getRequestConfig } from "next-intl/server";

export default getRequestConfig(async ({ locale }) => ({
  messages: (await import(`../messages/${locale}.json`)).default,
  // 누락된 번역 메시지에 대한 폴백 처리
  // defaultMessage: ({id, defaultMessage}) => defaultMessage || id,
  // defaultMessage: '번역을 찾을 수 없습니다'
}));
```

하지만 가장 좋은 방법은 번역 파일이 완벽하게 채워지도록 관리하는 것이겠죠?

### 2️⃣ 성능 최적화를 고려해야 해요

번역 메시지 파일이 매우 커지면 초기 로딩 성능에 영향을 줄 수 있어요.<br />

- **코드 스플리팅:** `getRequestConfig`에서 `import()`를 사용하여 필요한 로케일 파일만 동적으로 로드함으로써 번들 크기를 최적화하고 있어요. 이것이 `next-intl`의 기본 동작이에요.<br />
- **메시지 캐싱:** 서버 컴포넌트에서 `getTranslator`를 호출할 때, Next.js의 리퀘스트 캐시(Request Cache)를 활용하여 동일한 요청 내에서 중복 로드를 방지해요. 따라서 불필요한 메시지 로딩을 걱정할 필요는 없어요.

## 📝 정리하며

### 0️⃣ 핵심 요약이에요

오늘은 Next.js App Router 환경에서 `next-intl` 라이브러리를 활용하여 국제화(i18n)를 구현하는 방법을 자세히 살펴보았어요.<br />

- **`next-intl` 설치 및 기본 설정:** `i18n.ts`와 `messages` 폴더를 구성했어요.<br />
- **미들웨어 활용:** `middleware.ts`를 통해 언어를 감지하고 로케일 기반 라우팅을 구현했어요.<br />
- **`app/[locale]/layout.tsx`:** `NextIntlClientProvider`로 메시지를 제공하고 `generateMetadata`로 SEO를 위한 `alternate` 태그를 추가했어요.<br />
- **서버/클라이언트 컴포넌트:** `getTranslator`와 `useTranslations` 훅을 사용하여 번역 텍스트를 출력했어요.<br />

이제 여러분의 Next.js 애플리케이션에 다국어 지원 기능을 자신 있게 추가할 수 있을 거예요.
