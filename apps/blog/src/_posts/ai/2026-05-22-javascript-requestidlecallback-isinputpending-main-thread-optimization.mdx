웹 애플리케이션을 개발하다 보면 사용자 인터페이스(UI)가 갑자기 멈추거나, 입력에 대한 반응이 느려지는 현상을 겪어보셨을 거예요.<br />
이런 현상은 주로 메인 스레드가 무거운 작업으로 인해 블로킹될 때 발생하는데요. 사용자 경험(UX)을 크게 저해하는 요인이 되죠.<br />
오늘은 이러한 문제를 해결하고 UI 반응성을 극대화할 수 있는 강력한 JavaScript API, `requestIdleCallback`과 `isInputPending`에 대해 심도 있게 알아보려 해요.

## 🚦 메인 스레드 블로킹, 왜 문제일까요?

### 0️⃣ 웹 브라우저의 핵심, 메인 스레드

웹 브라우저는 기본적으로 단일 메인 스레드에서 대부분의 작업을 처리해요.<br />
DOM 조작, 스타일 계산, 레이아웃, 페인팅, JavaScript 실행, 이벤트 처리 등 사용자에게 보여지는 모든 시각적 업데이트와 상호작용이 이 메인 스레드에서 이루어지죠.<br />
그래서 메인 스레드가 바빠지면 다른 중요한 작업들이 지연되거나 멈추게 돼요. 마치 하나의 길에 너무 많은 차가 동시에 지나가려 할 때 교통 체증이 발생하는 것과 같은 이치예요.

### 1️⃣ 사용자 경험 저하로 이어지는 문제들

메인 스레드가 블로킹되면 어떤 문제가 발생할까요?<br />

- **느린 UI 반응성:** 사용자의 클릭이나 키보드 입력에 대한 반응이 늦어져요. 예를 들어, 버튼을 눌렀는데 아무 일도 일어나지 않거나 한참 뒤에 반응하죠.<br />
- **버벅이는 애니메이션:** 스크롤링이나 애니메이션이 부드럽지 않고 끊기는 현상(jank)이 발생해요. 초당 60프레임(FPS)을 유지해야 부드러운 움직임을 제공할 수 있는데, 메인 스레드 블로킹은 이를 방해해요.<br />
- **Core Web Vitals 악영향:** Google의 Core Web Vitals 지표 중 FID(First Input Delay)나 INP(Interaction to Next Paint)에 부정적인 영향을 미쳐요. 이는 SEO에도 영향을 줄 수 있어요.

이런 문제들은 사용자에게 부정적인 인상을 주고, 결국 애플리케이션 이탈로 이어질 수 있답니다.<br />
그래서 개발자는 메인 스레드를 효율적으로 관리하고, 무거운 작업을 적절히 분산시키는 전략을 고민해야 해요.

## 🛠️ `requestIdleCallback`으로 유휴 시간 활용하기

### 0️⃣ `requestIdleCallback`이란?

`requestIdleCallback`은 브라우저의 메인 스레드가 유휴(idle) 상태일 때, 즉 할 일이 없을 때 특정 함수를 실행하도록 스케줄링하는 API예요.<br />
이 API는 `requestAnimationFrame`과 유사하지만, `requestAnimationFrame`이 다음 프레임 렌더링 직전에 실행되어 시각적인 업데이트에 최적화되어 있다면, `requestIdleCallback`은 브라우저가 사용자 입력이나 중요한 작업을 모두 처리한 후 남는 시간에 실행되도록 설계되었어요.<br />
주로 중요도가 낮은 백그라운드 작업이나 분석 데이터 전송, DOM 변경 배치 처리 등에 활용된답니다.

<Blockquote type="tip">
  `requestIdleCallback`은 모든 브라우저에서 지원하지 않을 수 있어요. 특히
  Safari에서는 부분적으로 지원되거나 지원되지 않을 수 있으니, 사용 시
  폴리필(polyfill)이나 기능 감지(feature detection)를 고려하는 것이 좋아요.
</Blockquote>

### 1️⃣ `requestIdleCallback` 사용법

`requestIdleCallback`은 콜백 함수와 옵션 객체를 인자로 받아요.<br />
콜백 함수는 `IdleDeadline` 객체를 인자로 받는데, 이 객체는 `timeRemaining()` 메서드와 `didTimeout` 속성을 가지고 있어요.

- `timeRemaining()`: 현재 프레임에서 작업할 수 있는 남은 시간을 밀리초 단위로 반환해요.<br />
- `didTimeout`: 콜백이 타임아웃으로 인해 실행되었는지 여부를 나타내는 불리언 값이에요.

```ts showLineNumbers
interface IdleDeadline {
  readonly didTimeout: boolean;
  timeRemaining(): DOMHighResTimeStamp;
}

declare function requestIdleCallback(
  callback: (deadline: IdleDeadline) => void,
  options?: { timeout: number },
): number;

declare function cancelIdleCallback(handle: number): void;
```

옵션 객체에는 `timeout` 속성을 지정할 수 있어요.<br />
`timeout`은 브라우저가 `requestIdleCallback`을 일정 시간 안에 반드시 실행해야 한다고 알려주는 역할을 해요.<br />
만약 지정된 시간 안에 유휴 시간이 발생하지 않으면, 브라우저는 강제로 콜백을 실행하고 `deadline.didTimeout`은 `true`가 돼요.

### 2️⃣ 실전 예제: 무거운 작업 분할 처리

가상의 무거운 계산 작업을 `requestIdleCallback`을 이용해 분할 처리하는 예시를 살펴볼까요?<br />
이 예제에서는 `requestIdleCallback`을 반복적으로 호출하여 작업을 작은 단위로 쪼개어 처리하는 패턴을 보여드려요.

```tsx showLineNumbers
import React, { useState, useEffect, useRef } from "react";

interface HeavyTaskProps {
  dataSize: number;
}

const HeavyTaskProcessor: React.FC<HeavyTaskProps> = ({ dataSize }) => {
  const [progress, setProgress] = useState(0);
  const [isProcessing, setIsProcessing] = useState(false);
  const taskHandleRef = useRef<number | null>(null);
  const dataRef = useRef<number[]>([]);

  useEffect(() => {
    // 초기 데이터 생성
    dataRef.current = Array.from({ length: dataSize }, (_, i) => i);
  }, [dataSize]);

  const startProcessing = () => {
    setProgress(0);
    setIsProcessing(true);
    processChunk(0);
  };

  const processChunk = (startIndex: number) => {
    if (startIndex >= dataRef.current.length) {
      setIsProcessing(false);
      console.log("Heavy task completed!");
      return;
    }

    // requestIdleCallback이 지원되지 않을 경우 fallback
    if (!("requestIdleCallback" in window)) {
      console.warn(
        "requestIdleCallback not supported, falling back to setTimeout.",
      );
      let endIndex = Math.min(startIndex + 100, dataRef.current.length);
      for (let i = startIndex; i < endIndex; i++) {
        // 가상 무거운 작업: 각 데이터 항목에 대해 복잡한 계산 수행
        let result = 0;
        for (let j = 0; j < 10000; j++) {
          result += Math.sqrt(dataRef.current[i] * Math.random());
        }
      }
      setProgress(Math.floor((endIndex / dataRef.current.length) * 100));
      setTimeout(() => processChunk(endIndex), 0);
      return;
    }

    taskHandleRef.current = requestIdleCallback(
      (deadline) => {
        let currentIndex = startIndex;
        // deadline.timeRemaining()이 0보다 크거나 didTimeout이 true가 될 때까지 작업
        while (
          (deadline.timeRemaining() > 0 || deadline.didTimeout) &&
          currentIndex < dataRef.current.length
        ) {
          // 가상 무거운 작업: 각 데이터 항목에 대해 복잡한 계산 수행
          let result = 0;
          for (let j = 0; j < 10000; j++) {
            result += Math.sqrt(dataRef.current[currentIndex] * Math.random());
          }
          currentIndex++;
        }

        setProgress(Math.floor((currentIndex / dataRef.current.length) * 100));

        // 남은 작업이 있다면 다음 유휴 시간에 다시 스케줄링
        if (currentIndex < dataRef.current.length) {
          processChunk(currentIndex);
        } else {
          setIsProcessing(false);
          console.log("Heavy task completed!");
        }
      },
      { timeout: 100 },
    ); // 최대 100ms 안에는 실행되도록 보장
  };

  const cancelProcessing = () => {
    if (taskHandleRef.current) {
      cancelIdleCallback(taskHandleRef.current);
      taskHandleRef.current = null;
      setIsProcessing(false);
      console.log("Heavy task cancelled!");
    }
  };

  return (
    <div>
      <h2>requestIdleCallback 예제</h2>
      <p>데이터 크기: {dataSize}</p>
      <p>진행률: {progress}%</p>
      <button onClick={startProcessing} disabled={isProcessing}>
        {isProcessing ? "처리 중..." : "무거운 작업 시작"}
      </button>
      <button
        onClick={cancelProcessing}
        disabled={!isProcessing}
        style={{ marginLeft: "10px" }}
      >
        작업 취소
      </button>
      {isProcessing && (
        <p>작업이 백그라운드에서 진행 중이에요. UI는 반응성을 유지할 거예요.</p>
      )}
    </div>
  );
};

export default HeavyTaskProcessor;
```

<Blockquote type="info">
  이 예제는 `requestIdleCallback`의 동작 방식을 보여주기 위한 것으로, 실제
  애플리케이션에서는 웹 워커(Web Workers)와 같은 전용 스레드를 사용하는 것이 더
  효율적인 경우도 많아요.
  <br />
  하지만 메인 스레드에서 처리해야 하는 작업이거나 웹 워커로 넘기기 복잡한 경우
  `requestIdleCallback`은 좋은 대안이 될 수 있답니다.
</Blockquote>

## ⚡ `isInputPending`으로 입력 반응성 우선하기

### 0️⃣ `isInputPending`이란?

`isInputPending`은 현재 처리되지 않은 사용자 입력(키보드, 마우스 등) 이벤트가 대기 중인지 여부를 알려주는 API예요.<br />
이 API는 메인 스레드에서 실행되는 긴 작업 도중에 사용자의 입력이 들어왔는지를 빠르게 감지하여, 작업의 우선순위를 조절하고 UI 반응성을 개선하는 데 사용돼요.<br />
예를 들어, 복잡한 계산을 수행하고 있는데 사용자가 스크롤을 하거나 버튼을 클릭했다면, `isInputPending`은 이를 감지하고 현재 작업을 잠시 중단한 후 입력 이벤트를 먼저 처리하도록 할 수 있어요.

<Blockquote type="warning">
  `isInputPending`은 아직 실험적인(experimental) API이며, 모든 브라우저에서
  광범위하게 지원되지 않을 수 있어요. 특히 Firefox나 Safari에서는 지원되지 않을
  수 있으니, 프로덕션 환경에서는 주의 깊게 사용해야 해요.
</Blockquote>

### 1️⃣ `isInputPending` 사용법

`isInputPending`은 `navigator.scheduling` 객체에 속해 있어요.<br />
인자 없이 호출하면 현재 보류 중인 입력이 있는지 `true`/`false`를 반환해요.<br />
옵션 객체를 통해 `isInputPending`이 감지할 입력 유형을 필터링할 수도 있어요.

```ts showLineNumbers
interface Navigator {
  readonly scheduling: Scheduling;
}

interface Scheduling {
  isInputPending(options?: { includeContinuous: boolean }): boolean;
}
```

- `includeContinuous`: `true`로 설정하면 연속적인 입력(예: 스크롤, 마우스 이동)도 감지해요. 기본값은 `false`로, 이 경우 이산적인 입력(예: 클릭, 키보드 입력)만 감지해요.

### 2️⃣ 실전 예제: 무거운 작업 중 입력 감지

`requestIdleCallback` 예제와 유사하게, 무거운 작업을 수행하는 도중에 `isInputPending`을 활용하여 사용자 입력이 발생하면 작업을 잠시 멈추고 입력을 우선 처리하는 예시를 보여드릴게요.<br />
이 패턴은 특히 긴 루프나 반복적인 계산 작업에서 유용해요.

```tsx showLineNumbers
import React, { useState, useRef } from "react";

const InputAwareHeavyTask: React.FC = () => {
  const [isProcessing, setIsProcessing] = useState(false);
  const [progress, setProgress] = useState(0);
  const taskRef = useRef<{ isCancelled: boolean } | null>(null);

  const startHeavyComputation = () => {
    setIsProcessing(true);
    setProgress(0);
    taskRef.current = { isCancelled: false };
    runComputation(0);
  };

  const runComputation = (iteration: number) => {
    if (taskRef.current?.isCancelled) {
      setIsProcessing(false);
      console.log("Computation cancelled by user.");
      return;
    }

    if (iteration >= 100) {
      // 총 100번의 큰 작업 반복
      setIsProcessing(false);
      console.log("Heavy computation finished!");
      return;
    }

    // 매 반복마다 isInputPending을 체크하여 사용자 입력이 있는지 확인
    // navigator.scheduling이 없거나 isInputPending이 없으면 체크하지 않음
    if (
      navigator.scheduling &&
      navigator.scheduling.isInputPending &&
      navigator.scheduling.isInputPending({ includeContinuous: true })
    ) {
      console.log("User input pending! Pausing computation to handle input.");
      // 사용자 입력이 감지되면 현재 작업을 잠시 중단하고 다음 이벤트 루프 틱에서 다시 시작
      setTimeout(() => runComputation(iteration), 0);
      return;
    }

    // 실제 무거운 계산 (예시로 단순화)
    let sum = 0;
    for (let i = 0; i < 10000000; i++) {
      sum += Math.random();
    }
    console.log(`Iteration ${iteration} completed, sum: ${sum}`);

    setProgress(Math.floor(((iteration + 1) / 100) * 100));

    // 다음 반복은 다음 이벤트 루프 틱에서 실행하여 UI 업데이트 기회 제공
    setTimeout(() => runComputation(iteration + 1), 0);
  };

  const cancelComputation = () => {
    if (taskRef.current) {
      taskRef.current.isCancelled = true;
    }
  };

  return (
    <div>
      <h2>isInputPending 예제</h2>
      <p>진행률: {progress}%</p>
      <button onClick={startHeavyComputation} disabled={isProcessing}>
        {isProcessing ? "계산 중..." : "무거운 계산 시작"}
      </button>
      <button
        onClick={cancelComputation}
        disabled={!isProcessing}
        style={{ marginLeft: "10px" }}
      >
        계산 취소
      </button>
      {isProcessing && (
        <p>계산이 진행 중이지만, 사용자 입력 시 즉시 반응할 거예요.</p>
      )}
      <input
        type="text"
        placeholder="여기에 입력해보세요"
        style={{ marginTop: "20px", padding: "10px", display: "block" }}
      />
    </div>
  );
};

export default InputAwareHeavyTask;
```

이 예제를 실행하고 무거운 계산이 진행되는 동안 `<input>` 필드에 텍스트를 입력해보시면, 계산이 잠시 멈추고 입력이 부드럽게 처리되는 것을 확인할 수 있을 거예요.<br />
`isInputPending` 덕분에 사용자의 상호작용이 지연되지 않고 즉각적으로 반응하는 것이죠.

## 💡 `requestIdleCallback`과 `isInputPending`의 시너지

이 두 API는 각각 다른 목적을 가지고 있지만, 함께 사용하면 메인 스레드 최적화에 강력한 시너지를 낼 수 있어요.<br />

- `requestIdleCallback`: 중요도가 낮은 작업을 브라우저의 유휴 시간에 스케줄링하여 메인 스레드 블로킹을 회피해요.<br />
- `isInputPending`: 진행 중인 무거운 작업 도중에 사용자 입력이 발생했는지 감지하여, 입력에 대한 즉각적인 반응을 보장해요.

즉, `requestIdleCallback`으로 작업을 분산 처리하면서, 분산된 각 작업 청크 내부에서 `isInputPending`을 주기적으로 체크하여 사용자 입력에 대한 우선순위를 부여하는 방식으로 활용할 수 있답니다.<br />
이를 통해 애플리케이션의 전반적인 UI 반응성과 사용자 경험을 크게 향상시킬 수 있어요.

## 📝 정리하며

오늘은 웹 성능 최적화의 핵심 요소 중 하나인 메인 스레드 블로킹 문제를 해결하기 위해 `requestIdleCallback`과 `isInputPending` 두 가지 강력한 JavaScript API를 자세히 살펴보았어요.<br />

- `requestIdleCallback`은 브라우저의 유휴 시간을 활용하여 중요도가 낮은 작업을 비동기적으로 처리함으로써 메인 스레드의 부담을 줄여줘요.<br />
- `isInputPending`은 진행 중인 작업 도중에 사용자 입력이 발생했는지 감지하여, UI 반응성을 최우선으로 확보할 수 있도록 도와줘요.

이 두 API를 적절히 활용하면, 무거운 작업을 수행하는 웹 애플리케이션에서도 사용자에게 부드럽고 반응성 좋은 경험을 제공할 수 있을 거예요.<br />
물론, 이 외에도 웹 워커(Web Workers)나 `setTimeout(..., 0)`을 이용한 작업 분할, `useTransition`/`useDeferredValue` (React의 경우) 등 다양한 최적화 기법들이 있으니, 여러분의 프로젝트 상황에 맞춰 가장 적절한 방법을 선택하시길 권해드려요.

복잡한 웹 애플리케이션을 만들 때 성능 최적화는 선택이 아닌 필수랍니다.<br />
오늘 배운 내용을 바탕으로 더 빠르고 반응성 좋은 웹을 만들어나가시길 바라요!
