## 🤔 비동기 JavaScript, 왜 다시 봐야 할까요?

### 0️⃣ Promise와 async/await, 정말 잘 쓰고 계신가요?

대부분의 개발자분들이 `Promise`와 `async/await`의 기본적인 사용법은 알고 계실 거예요.<br />
하지만 비동기 작업이 복잡해지고 여러 작업이 얽히기 시작하면 예상치 못한 동작이나 에러에 직면하는 경우가 많아요.<br />
예를 들어, 여러 API 요청을 동시에 보내고 싶을 때, 혹은 특정 시간 안에 응답이 오지 않으면 취소하고 싶을 때 어떻게 처리해야 할까요?<br />
이런 상황에서 단순히 `await`만으로는 부족하다는 것을 느끼실 거예요.

### 1️⃣ 비동기 코드의 흔한 함정들

비동기 코드를 작성할 때 자주 마주치는 문제점들이 있어요.<br />
대표적으로는 다음과 같은 것들이 있죠.

- **콜백 지옥 (Callback Hell)의 재림:** `async/await`를 사용하더라도, 잘못된 구조로 코드를 작성하면 여전히 콜백 지옥과 유사한 가독성 문제를 겪을 수 있어요.<br />
  예를 들어, `then` 체인을 과도하게 사용하거나, 비동기 작업 내에서 또 다른 비동기 작업을 중첩시키는 경우에요.
- **예상치 못한 에러 처리:** 비동기 작업 중 발생하는 에러를 놓치거나, 적절하게 전파되지 않아 애플리케이션이 멈추는 상황이 발생하기도 해요.<br />
  `try...catch` 블록의 위치나 `Promise.prototype.catch`의 역할에 대한 명확한 이해가 부족할 때 흔히 발생하죠.
- **성능 저하:** 여러 비동기 작업을 순차적으로만 처리하여 불필요하게 대기 시간이 길어지는 경우도 있어요.<br />
  병렬 처리가 가능한 상황임에도 불구하고 `await`를 남용하면 애플리케이션의 응답 속도가 느려질 수 있어요.

이러한 문제들을 해결하고 더 견고하고 효율적인 비동기 코드를 작성하기 위해선 `Promise`와 `async/await`에 대한 깊이 있는 이해가 필수적이에요.

## 🚀 Promise와 async/await, 깊이 파고들기

### 0️⃣ Promise의 생명 주기와 콜백 지옥 탈출

`Promise`는 비동기 작업의 최종 완료 또는 실패를 나타내는 객체예요.<br />
`Promise`는 세 가지 상태를 가지고 있어요.

- **Pending (대기):** 비동기 작업이 아직 수행 중인 초기 상태예요.
- **Fulfilled (이행):** 비동기 작업이 성공적으로 완료되었고, 결과 값을 반환한 상태예요.
- **Rejected (거부):** 비동기 작업이 실패했고, 에러를 반환한 상태예요.

이 상태들은 한 번 결정되면 변하지 않아요. 즉, `Fulfilled` 또는 `Rejected` 상태가 되면 `Settled` (정착) 되었다고 부르며, 더 이상 상태가 변하지 않아요.<br />
`Promise`의 가장 큰 장점은 콜백 지옥에서 벗어나 코드를 선형적으로 작성할 수 있게 해준다는 점이에요.

<LinkPreviewCard href="https://developer.mozilla.org/ko/docs/Web/JavaScript/Reference/Global_Objects/Promise" />

```javascript showLineNumbers
function fetchData(url) {
  return new Promise((resolve, reject) => {
    fetch(url)
      .then((response) => {
        if (!response.ok) {
          throw new Error(`HTTP error! status: ${response.status}`);
        }
        return response.json();
      })
      .then((data) => resolve(data))
      .catch((error) => reject(error));
  });
}

// 사용 예시
fetchData("https://api.example.com/data")
  .then((data) => {
    console.log("데이터를 성공적으로 가져왔어요:", data);
  })
  .catch((error) => {
    console.error("데이터 가져오기 실패했어요:", error);
  });
```

위 코드에서 `fetch` 자체가 `Promise`를 반환하기 때문에, `fetchData` 함수 내에서 새로운 `Promise`를 생성하는 것은 불필요해요.<br />
이것은 `Promise`를 잘못 사용하는 흔한 예시 중 하나예요.<br />
올바른 `Promise` 체이닝을 활용하면 훨씬 간결하게 작성할 수 있어요.

```javascript showLineNumbers {1-6}
function fetchDataCorrectly(url) {
  return fetch(url).then((response) => {
    if (!response.ok) {
      throw new Error(`HTTP error! status: ${response.status}`);
    }
    return response.json();
  });
}

// 사용 예시 (이전과 동일)
fetchDataCorrectly("https://api.example.com/data")
  .then((data) => {
    console.log("데이터를 성공적으로 가져왔어요:", data);
  })
  .catch((error) => {
    console.error("데이터 가져오기 실패했어요:", error);
  });
```

<Blockquote type="tip">
  프로미스를 반환하는 함수를 사용할 때는 굳이 새로운 `new Promise()`를 만들
  필요가 없어요.
  <br />
  기존 프로미스를 체이닝하여 사용하면 코드의 복잡성을 줄이고 가독성을 높일 수
  있답니다.
</Blockquote>

### 1️⃣ async/await의 마법: 동기 코드처럼 비동기 다루기

`async/await`는 `Promise`를 더욱 쉽게 사용할 수 있도록 ES2017에 도입된 문법이에요.<br />
`async` 함수는 항상 `Promise`를 반환하고, `await` 키워드는 `async` 함수 내부에서만 사용할 수 있으며, `Promise`가 `Fulfilled` 또는 `Rejected` 상태가 될 때까지 함수의 실행을 일시 중지시켜요.<br />
이는 비동기 코드를 마치 동기 코드처럼 순차적으로 읽을 수 있게 해주어 가독성을 극대화시켜줘요.

```javascript showLineNumbers
async function fetchUserData(userId) {
  try {
    const response = await fetch(`https://api.example.com/users/${userId}`);
    if (!response.ok) {
      throw new Error(`HTTP error! status: ${response.status}`);
    }
    const user = await response.json();
    console.log("사용자 데이터를 성공적으로 가져왔어요:", user);
    return user;
  } catch (error) {
    console.error("사용자 데이터 가져오기 실패했어요:", error);
    throw error; // 에러를 다시 던져서 호출자에게 알릴 수 있어요
  }
}

// 사용 예시
(async () => {
  // IIFE (즉시 실행 함수)로 async 함수 호출
  try {
    const user = await fetchUserData(1);
    console.log("최종적으로 받은 사용자:", user.name);
  } catch (error) {
    console.error("최종 처리 중 에러 발생:", error.message);
  }
})();
```

<Blockquote type="info">
  `await`는 `Promise`가 정착될 때까지 기다리지만, 다른 비동기 작업이 이벤트
  루프에서 계속 실행될 수 있도록 논블로킹 방식으로 작동해요.
  <br />
  이는 JavaScript의 단일 스레드 특성을 유지하면서도 비동기 작업을 효율적으로
  처리할 수 있게 해주는 핵심 메커니즘이에요.
</Blockquote>

## ✨ 실전 비동기 패턴과 고급 활용

### 0️⃣ 여러 비동기 작업 병렬 처리: `Promise.all`과 `Promise.allSettled`

여러 비동기 작업을 동시에 실행하고 그 결과를 기다려야 할 때가 많아요.<br />
이때 `Promise.all`과 `Promise.allSettled`를 사용하면 효율적으로 처리할 수 있어요.

- **`Promise.all(iterable)`:**<br />
  - 모든 `Promise`가 성공적으로 이행될 때까지 기다려요.<br />
  - 하나라도 거부되면 즉시 `Rejected` 상태가 되고, 나머지 `Promise`의 결과는 무시돼요.<br />
  - 모든 `Promise`가 이행되면, 각 `Promise`의 결과 값들을 담은 배열을 반환해요.

```javascript showLineNumbers
async function fetchMultipleData() {
  const urls = [
    "https://api.example.com/data1",
    "https://api.example.com/data2",
    "https://api.example.com/data3",
  ];

  try {
    const responses = await Promise.all(
      urls.map((url) => fetch(url).then((res) => res.json())),
    );
    console.log("모든 데이터를 성공적으로 가져왔어요:", responses);
    // responses는 [data1, data2, data3] 형태의 배열이 돼요.
  } catch (error) {
    console.error("데이터 중 하나라도 실패했어요:", error);
  }
}

fetchMultipleData();
```

<Blockquote type="warning">
  `Promise.all`은 "all or nothing" 전략을 따르기 때문에, 의존성이 강한 여러
  작업들을 동시에 처리할 때 유용해요.
  <br />
  하지만 하나라도 실패하면 전체가 실패하므로, 개별 작업의 실패가 전체 흐름에
  영향을 주지 않아야 하는 상황에서는 적합하지 않을 수 있어요.
</Blockquote>

- **`Promise.allSettled(iterable)`:**<br />
  - 모든 `Promise`가 이행(Fulfilled)되든, 거부(Rejected)되든 상관없이 모든 `Promise`가 정착될 때까지 기다려요.<br />
  - 각 `Promise`의 상태와 결과(또는 에러)를 객체 형태로 반환하는 배열을 제공해요.<br />
  - `[{ status: 'fulfilled', value: result }, { status: 'rejected', reason: error }]` 형태예요.

```javascript showLineNumbers
async function fetchMultipleDataWithSettled() {
  const urls = [
    "https://api.example.com/dataA",
    "https://api.example.com/non-existent-url", // 실패할 URL
    "https://api.example.com/dataB",
  ];

  const results = await Promise.allSettled(
    urls.map((url) =>
      fetch(url)
        .then((res) => res.json())
        .catch((err) => ({ error: err.message })),
    ),
  );

  console.log("모든 데이터 요청 결과:", results);

  results.forEach((result, index) => {
    if (result.status === "fulfilled") {
      console.log(`${urls[index]} 성공:`, result.value);
    } else {
      console.error(`${urls[index]} 실패:`, result.reason);
    }
  });
}

fetchMultipleDataWithSettled();
```

<Blockquote type="tip">
  `Promise.allSettled`는 개별 비동기 작업의 성공 여부와 관계없이 모든 결과를
  확인해야 할 때 유용해요.
  <br />
  예를 들어, 여러 위젯의 데이터를 동시에 로드하고, 실패한 위젯만 에러 메시지를
  표시하고 싶은 경우에 활용할 수 있어요.
</Blockquote>

### 1️⃣ 타임아웃 처리와 경쟁 상태: `Promise.race`와 `Promise.any`

특정 시간 내에 응답을 받지 못하면 다음 작업을 진행하거나 에러를 발생시켜야 할 때가 있어요.<br />
이런 '경쟁' 상황에서는 `Promise.race`와 `Promise.any`가 유용해요.

- **`Promise.race(iterable)`:**<br />
  - iterable에 포함된 `Promise` 중 가장 먼저 정착(이행 또는 거부)되는 `Promise`의 결과(또는 에러)를 반환해요.<br />
  - 가장 빠른 `Promise`가 이행되면 `Promise.race`도 이행되고, 가장 빠른 `Promise`가 거부되면 `Promise.race`도 거부돼요.

```javascript showLineNumbers
function timeout(ms) {
  return new Promise((resolve, reject) =>
    setTimeout(() => reject(new Error("타임아웃!")), ms),
  );
}

async function fetchDataWithTimeout(url, ms) {
  try {
    const data = await Promise.race([
      fetch(url).then((res) => res.json()),
      timeout(ms),
    ]);
    console.log("데이터를 성공적으로 가져왔어요 (타임아웃 없음):", data);
    return data;
  } catch (error) {
    console.error(
      "데이터 가져오기 실패 또는 타임아웃 발생했어요:",
      error.message,
    );
    throw error;
  }
}

// 사용 예시
(async () => {
  await fetchDataWithTimeout("https://api.example.com/fast-data", 100); // 100ms 내에 응답
  await fetchDataWithTimeout("https://api.example.com/slow-data", 50); // 50ms 내에 응답 못함 (가상)
})();
```

<Blockquote type="info">
  `Promise.race`는 여러 소스 중 가장 빠른 응답을 취하거나, 타임아웃 처리와 같이
  경쟁 상황에서 유용하게 사용돼요.
  <br />
  하지만 가장 먼저 끝나는 Promise가 에러를 반환하면 전체도 에러가 된다는 점을
  기억해야 해요.
</Blockquote>

- **`Promise.any(iterable)`:**<br />
  - iterable에 포함된 `Promise` 중 가장 먼저 `Fulfilled` (이행)되는 `Promise`의 결과 값을 반환해요.<br />
  - 모든 `Promise`가 `Rejected`되면 `AggregateError`를 발생시켜요.<br />
  - `Promise.race`와 다르게, 가장 먼저 거부되는 `Promise`는 무시되고, 이행되는 `Promise`를 찾을 때까지 기다려요.

```javascript showLineNumbers
async function fetchFromMultipleSources() {
  const sources = [
    fetch("https://api.example.com/slow-source").then((res) => res.json()), // 느리거나 실패할 수 있음
    fetch("https://api.example.com/reliable-source-1").then((res) =>
      res.json(),
    ), // 중간 속도
    fetch("https://api.example.com/reliable-source-2").then((res) =>
      res.json(),
    ), // 가장 빠를 수 있음
  ];

  try {
    const fastestResult = await Promise.any(sources);
    console.log("가장 먼저 성공한 결과:", fastestResult);
  } catch (error) {
    if (error instanceof AggregateError) {
      console.error(
        "모든 소스에서 데이터를 가져오는 데 실패했어요:",
        error.errors,
      );
    } else {
      console.error("예상치 못한 에러 발생:", error);
    }
  }
}

fetchFromMultipleSources();
```

<Blockquote type="tip">
  `Promise.any`는 여러 백업 소스 중 하나라도 성공하면 되는 상황에 적합해요.
  <br />
  예를 들어, CDN을 여러 개 두고 가장 빠른 CDN에서 리소스를 가져오거나, 여러 서버
  중 응답이 빠른 곳에서 데이터를 가져올 때 활용할 수 있어요.
</Blockquote>

### 2️⃣ 에러 핸들링: `try...catch`와 `Promise.prototype.catch`의 조화

비동기 코드에서 에러 처리는 매우 중요해요.<br />
`async/await`와 `Promise`를 사용할 때 에러를 효과적으로 처리하는 방법을 알아볼게요.

- **`async/await`의 `try...catch`:**<br />
  - `async` 함수 내부에서 `await`로 비동기 작업을 기다릴 때 발생하는 에러는 동기 코드처럼 `try...catch` 블록으로 잡을 수 있어요.

```javascript showLineNumbers
async function safeFetchData(url) {
  try {
    const response = await fetch(url);
    if (!response.ok) {
      // HTTP 에러는 여기서 catch 블록으로 전달돼요.
      throw new Error(`HTTP 에러 발생: ${response.status}`);
    }
    const data = await response.json();
    return data;
  } catch (error) {
    console.error(`데이터 요청 중 에러 발생: ${error.message}`);
    // 에러를 처리하거나, 다시 던져서 상위 호출자에게 알릴 수 있어요.
    throw new Error("데이터 처리 실패");
  }
}

// 사용 예시
(async () => {
  try {
    const data = await safeFetchData("https://api.example.com/invalid-url");
    console.log("데이터를 성공적으로 받았어요:", data);
  } catch (error) {
    console.error("최종적으로 데이터를 받지 못했어요:", error.message);
  }
})();
```

- **`Promise.prototype.catch()`:**<br />
  - `Promise` 체인의 마지막에 `catch()`를 붙여서 이전 `Promise`에서 발생한 모든 에러를 처리할 수 있어요.

```javascript showLineNumbers
function fetchDataAndProcess(url) {
  return fetch(url)
    .then((response) => {
      if (!response.ok) {
        throw new Error(`HTTP 에러 발생: ${response.status}`);
      }
      return response.json();
    })
    .then((data) => {
      // 데이터 처리 로직 (여기서도 에러가 발생할 수 있어요)
      if (data.status === "error") {
        throw new Error("서버에서 에러 상태를 반환했어요");
      }
      return data;
    })
    .catch((error) => {
      // 이전 모든 then 블록에서 발생한 에러를 여기서 잡아요.
      console.error(`데이터 처리 체인에서 에러 발생: ${error.message}`);
      throw error; // 에러를 다시 던져서 다음 catch로 전달하거나, Promise를 Rejected 상태로 유지해요.
    });
}

// 사용 예시
fetchDataAndProcess("https://api.example.com/problematic-data")
  .then((finalData) => console.log("최종 데이터:", finalData))
  .catch((finalError) =>
    console.error("최종 에러 핸들링:", finalError.message),
  );
```

<Blockquote type="info">
  `Promise` 체인 중간에 `catch()`를 사용하면, 해당 `catch()` 이후의 `then()`
  블록은 다시 `Fulfilled` 상태로 시작될 수 있어요.
  <br />
  이는 에러 발생 시 대체 값을 제공하거나 복구 로직을 실행할 때 유용해요.
</Blockquote>

```javascript showLineNumbers
fetch("/api/data")
  .then((response) => response.json())
  .catch((error) => {
    console.warn("데이터 로드 실패, 기본값 사용:", error);
    return { defaultData: [] }; // 에러 발생 시 기본값 반환
  })
  .then((data) => {
    // 이전 catch 블록에서 기본값을 반환했으므로, 이 then 블록은 실행돼요.
    console.log("처리할 데이터:", data);
  });
```

### 3️⃣ 비동기 이터레이터와 제너레이터 (고급 주제로 살짝 언급)

ES2018에 도입된 비동기 이터레이터와 `for await...of` 루프는 비동기 데이터 스트림을 다룰 때 강력한 도구가 돼요.<br />
`async` 제너레이터 함수를 사용하면 비동기 작업의 결과를 `yield`를 통해 하나씩 비동기적으로 생성할 수 있어요.

```javascript showLineNumbers
async function* asyncGenerator() {
  yield Promise.resolve(1);
  yield Promise.resolve(2);
  yield Promise.resolve(3);
}

(async () => {
  for await (const num of asyncGenerator()) {
    console.log(num); // 1, 2, 3 순서대로 출력
  }
})();
```

<Blockquote type="info">
  이 주제는 다소 고급 내용이지만, 실시간 데이터 스트리밍, 대용량 파일 처리 등
  특정 시나리오에서 매우 유용하게 활용될 수 있어요.
  <br />
  필요하다면 더 깊게 탐구해 보시는 것을 추천해요.
</Blockquote>

## ⚠️ 주의사항과 성능 팁

### 0️⃣ `async` 함수 안에서 `await` 누락 시 문제

`async` 함수 내에서 `await` 키워드를 사용하지 않고 `Promise`를 호출하면, 해당 `Promise`는 백그라운드에서 실행되고 함수는 다음 라인으로 즉시 진행돼요.<br />
이는 의도치 않은 비동기 동작을 유발하거나, 에러를 놓치게 만들 수 있어요.

```javascript showLineNumbers {4}
async function processDataIncorrectly() {
  console.log("시작");
  // await을 누락하면 fetchData()는 백그라운드에서 실행되고, 다음 라인이 즉시 실행돼요。
  fetchDataCorrectly("https://api.example.com/some-data");
  console.log(
    "데이터 요청을 보냈어요 (아마도 데이터가 아직 오지 않았을 거예요)",
  );
  // 이 시점에서 fetchData()의 결과는 아직 알 수 없어요。
}

// 올바른 사용법
async function processDataCorrectly() {
  console.log("시작");
  const data = await fetchDataCorrectly("https://api.example.com/some-data");
  console.log("데이터를 받았어요:", data);
}

processDataIncorrectly();
// processDataCorrectly();
```

<Blockquote type="error">
  `await`를 누락하면 비동기 작업의 완료를 기다리지 않고 다음 코드가 실행되므로,
  순서가 중요한 로직에서 문제가 발생할 수 있어요.
  <br />
  또한, 에러가 발생해도 `try...catch` 블록으로 잡히지 않고 Unhandled Promise
  Rejection으로 이어질 수 있어요.
</Blockquote>

### 1️⃣ `Promise` 체이닝의 중요성

`Promise`를 사용할 때 `then`과 `catch`를 체이닝하는 것은 매우 중요해요.<br />
각 `then` 블록은 이전 `then` 블록의 결과 값을 받아서 처리하며, `Promise`를 반환할 수 있어요.<br />
이때 반환된 `Promise`는 다음 `then` 블록에서 `await`처럼 기다려지게 돼요.

```javascript showLineNumbers
// 잘못된 예시: 체이닝이 끊김
function brokenChain() {
  fetch("/api/step1")
    .then((res) => res.json())
    .then((data1) => {
      // 여기서 새로운 Promise를 반환하지 않으면, 다음 then은 이 data1을 받지 못해요。
      fetch(`/api/step2/${data1.id}`).then((res) => res.json());
    })
    .then((data2) => {
      // data2는 undefined가 될 가능성이 높아요。
      console.log("Broken Chain Result:", data2);
    })
    .catch((err) => console.error("Broken Chain Error:", err));
}

// 올바른 예시: 체이닝 유지
function correctChain() {
  fetch("/api/step1")
    .then((res) => res.json())
    .then((data1) => {
      // Promise를 반환하여 체이닝을 유지해요。
      return fetch(`/api/step2/${data1.id}`).then((res) => res.json());
    })
    .then((data2) => {
      // data2는 step2의 결과값을 받아요。
      console.log("Correct Chain Result:", data2);
    })
    .catch((err) => console.error("Correct Chain Error:", err));
}

// brokenChain();
// correctChain();
```

<Blockquote type="tip">
  `Promise` 체이닝에서 `then` 블록 내에서 `Promise`를 반환하면, 그 `Promise`가
  완료될 때까지 다음 `then` 블록이 기다려져요.
  <br />
  이를 통해 복잡한 비동기 흐름을 순차적으로 명확하게 구성할 수 있어요.
</Blockquote>

### 2️⃣ 불필요한 `await` 사용 피하기

모든 `Promise` 앞에 `await`를 붙이는 것이 항상 좋은 것은 아니에요.<br />
특히 서로 의존성이 없는 여러 비동기 작업을 병렬로 실행할 수 있다면, `await`를 남용하는 것은 성능 저하로 이어질 수 있어요.

```javascript showLineNumbers
async function fetchSequentially() {
  console.time("순차 처리");
  const user = await fetch("/api/user").then((res) => res.json());
  const posts = await fetch("/api/posts").then((res) => res.json());
  const comments = await fetch("/api/comments").then((res) => res.json());
  console.timeEnd("순차 처리"); // 예: 300ms
  return { user, posts, comments };
}

async function fetchInParallel() {
  console.time("병렬 처리");
  const [user, posts, comments] = await Promise.all([
    fetch("/api/user").then((res) => res.json()),
    fetch("/api/posts").then((res) => res.json()),
    fetch("/api/comments").then((res) => res.json()),
  ]);
  console.timeEnd("병렬 처리"); // 예: 100ms (가장 오래 걸리는 요청 시간에 근접)
  return { user, posts, comments };
}

// fetchSequentially();
// fetchInParallel();
```

<Blockquote type="info">
  서로 독립적인 비동기 작업은 `Promise.all`과 같은 병렬 처리 메서드를 활용하여
  `await`를 한 번만 사용하면 전체 실행 시간을 크게 단축할 수 있어요.
  <br />
  이는 애플리케이션의 응답성을 향상시키는 중요한 최적화 기법이에요.
</Blockquote>

## 📝 마무리하며

오늘은 JavaScript의 `Promise`와 `async/await`에 대해 깊이 있게 알아보는 시간을 가졌어요.<br />
비동기 처리의 기본 개념부터 `Promise.all`, `Promise.allSettled`, `Promise.race`, `Promise.any`와 같은 고급 패턴, 그리고 실무에서 흔히 발생하는 주의사항까지 함께 살펴보았어요.

`Promise`와 `async/await`는 단순한 문법적 설탕이 아니라, 비동기 코드를 구조화하고 관리하는 강력한 도구들이에요.<br />
이들을 올바르게 이해하고 활용하면 더욱 견고하고 효율적이며 읽기 쉬운 코드를 작성할 수 있을 거예요.

### 0️⃣ 핵심 요약

- `Promise`는 비동기 작업의 최종 성공 또는 실패를 나타내는 객체이며, `Pending`, `Fulfilled`, `Rejected` 세 가지 상태를 가져요.
- `async/await`는 `Promise`를 기반으로 비동기 코드를 동기 코드처럼 읽기 쉽게 만들어주는 문법이에요.
- `Promise.all`은 모든 `Promise`가 성공해야 성공하고, 하나라도 실패하면 전체가 실패하는 "all or nothing" 전략에 적합해요.
- `Promise.allSettled`는 모든 `Promise`의 성공/실패 여부와 관계없이 모든 결과를 확인해야 할 때 유용해요.
- `Promise.race`는 가장 먼저 정착(성공 또는 실패)하는 `Promise`의 결과를 반환하며, 타임아웃 처리 등에 활용돼요.
- `Promise.any`는 가장 먼저 성공하는 `Promise`의 결과를 반환하며, 여러 소스 중 하나만 성공하면 될 때 유용해요.
- `async/await`에서는 `try...catch`로, `Promise` 체인에서는 `catch()`로 에러를 효과적으로 처리할 수 있어요.
- `await` 누락, 잘못된 `Promise` 체이닝, 불필요한 `await` 사용은 피해야 할 흔한 실수들이에요.
