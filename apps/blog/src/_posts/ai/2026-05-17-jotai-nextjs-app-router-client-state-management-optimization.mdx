## 🤔 Next.js App Router와 클라이언트 상태 관리의 도전

Next.js App Router가 등장하면서 우리는 Server Components와 Client Components라는 새로운 패러다임을 맞이하게 되었어요. 이는 서버에서 렌더링 가능한 컴포넌트와 클라이언트에서만 동작하는 컴포넌트를 명확히 구분하여 성능 최적화와 개발 경험 향상을 목표로 하죠. 하지만 이 새로운 아키텍처는 클라이언트 상태 관리에 몇 가지 새로운 고민을 안겨주었어요.

### 0️⃣ 왜 클라이언트 상태 관리가 중요한가요?

아무리 Server Components가 중요하다고 해도, 사용자 인터랙션이 발생하는 부분, 즉 버튼 클릭, 폼 입력, 모달 열기/닫기 등은 여전히 클라이언트에서 상태를 관리해야 해요. 이 상태들이 복잡해지면 컴포넌트 간의 데이터 전달이 어려워지고, 불필요한 리렌더링으로 성능 저하가 발생할 수 있어요. 특히 App Router에서는 Server Components와 Client Components 간의 경계가 명확해서, 클라이언트 상태를 어디에 둘지, 어떻게 효율적으로 공유할지가 더 중요해졌어요.

### 1️⃣ 기존 방식의 한계와 새로운 요구사항

기존에는 React Context API나 Redux, Zustand 같은 라이브러리를 많이 사용해왔어요. 하지만 App Router 환경에서는 다음과 같은 문제에 직면할 수 있어요.<br />

*   **Server Components에서의 상태 관리:** Server Components는 클라이언트 상태를 가질 수 없기 때문에, 상태를 필요로 하는 UI는 반드시 Client Component로 분리해야 해요. 이 과정에서 Server Component와 Client Component 간의 데이터 흐름을 명확히 설계해야 하죠.<br />
*   **Prop Drilling:** Context API를 사용해도 여전히 Provider를 상위 컴포넌트에 배치해야 하고, 이는 때때로 불필요한 리렌더링을 유발하거나, 깊은 컴포넌트 트리를 따라 Props를 전달해야 하는 Prop Drilling 문제를 야기할 수 있어요.<br />
*   **번들 사이즈:** 거대한 상태 관리 라이브러리는 초기 번들 사이즈를 증가시켜 사용자 경험에 부정적인 영향을 줄 수 있어요.

이런 요구사항들을 해결하면서도 개발자 경험을 해치지 않는 라이브러리가 필요했고, 그 중 하나가 바로 **Jotai**예요. Jotai는 '아톰(Atom)'이라는 개념을 사용하여 최소한의 리렌더링과 작은 번들 사이즈를 자랑하는 경량 상태 관리 라이브러리랍니다.

## 💡 Jotai: 아톰 패턴으로 클라이언트 상태를 효율적으로

Jotai는 Recoil에서 영감을 받아 만들어진 상태 관리 라이브러리로, '아톰'이라는 작은 단위로 상태를 관리해요. 각 아톰은 독립적인 상태를 가지며, 필요한 컴포넌트에서만 구독하여 사용하죠. 이는 불필요한 리렌더링을 최소화하고, 상태 로직을 모듈화하기에 아주 적합해요.

### 0️⃣ Jotai의 핵심 아이디어: 아톰(Atom)

Jotai의 핵심은 바로 '아톰'이에요. 아톰은 독립적인 상태 조각으로, 마치 원자처럼 더 이상 분해할 수 없는 최소 단위의 상태를 의미해요. 각 아톰은 고유한 키를 가지며, 이 키를 통해 컴포넌트에서 아톰의 값을 읽거나 업데이트할 수 있어요. 특정 아톰을 구독하는 컴포넌트만 해당 아톰의 값이 변경될 때 리렌더링되므로, 매우 효율적인 상태 관리가 가능해져요.<br />

### 1️⃣ Next.js App Router에 Jotai 적용하기

Jotai를 Next.js App Router 프로젝트에 적용하는 것은 아주 간단해요. 먼저 라이브러리를 설치해 주세요.

```bash showLineNumbers
npm install jotai
# 또는
yarn add jotai
pnpm add jotai
```

Jotai는 `Provider`가 필수는 아니지만, 여러 개의 아톰을 사용하거나 특정 컨텍스트를 공유해야 할 때 `Provider`를 사용하는 것이 좋아요. App Router에서는 `layout.tsx` 파일 내에 `Provider`를 배치하여 전역적으로 상태를 관리할 수 있어요. 이때, `Provider`는 반드시 `'use client'` 지시어가 있는 Client Component 내에서 사용해야 해요.

```tsx showLineNumbers {1, 9-11}
// app/providers.tsx
'use client';

import { Provider } from 'jotai';

export function JotaiProvider({ children }: { children: React.ReactNode }) {
  return <Provider>{children}</Provider>;
}

// app/layout.tsx
import { JotaiProvider } from './providers';

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="ko">
      <body>
        <JotaiProvider>{children}</JotaiProvider>
      </body>
    </html>
  );
}
```

이제 아톰을 정의하고 컴포넌트에서 사용하는 방법을 알아볼까요?

## 🛠️ Jotai 활용 패턴과 실전 예제

Jotai는 단순한 상태 관리뿐만 아니라, 파생된 상태, 비동기 상태, 그리고 다양한 유틸리티를 제공하여 복잡한 시나리오도 효과적으로 다룰 수 있게 해줘요.

### 0️⃣ 기본 아톰 생성 및 사용

가장 기본적인 아톰은 `atom()` 함수를 사용하여 생성해요. `useAtom` 훅을 통해 아톰의 값과 업데이트 함수를 가져올 수 있어요.

```tsx showLineNumbers
// atoms/counter.ts
import { atom } from 'jotai';

export const countAtom = atom(0);
export const textAtom = atom('hello');
```

```tsx showLineNumbers {1, 3, 5, 8-9, 11}
// app/components/Counter.tsx
'use client';

import { useAtom } from 'jotai';
import { countAtom } from '@/atoms/counter';

export function Counter() {
  const [count, setCount] = useAtom(countAtom);

  return (
    <div>
      <p>현재 카운트: {count}</p>
      <button onClick={() => setCount(c => c + 1)}>증가</button>
      <button onClick={() => setCount(c => c - 1)}>감소</button>
    </div>
  );
}
```

```tsx showLineNumbers {1, 3, 5, 8}
// app/page.tsx
'use client'; // Counter 컴포넌트가 Client Component이므로 page도 Client Component여야 해요.

import { Counter } from './components/Counter';

export default function HomePage() {
  return (
    <main>
      <h1>Jotai 카운터 예제</h1>
      <Counter />
    </main>
  );
}
```

이 예제에서 `countAtom`은 전역적으로 공유되는 상태가 되고, `Counter` 컴포넌트는 이 아톰의 값 변화에만 반응하여 리렌더링돼요. 다른 컴포넌트가 `countAtom`을 사용하지 않는다면, `countAtom`이 변경되어도 리렌더링되지 않아요.

### 1️⃣ 파생된 아톰 (Derived Atoms) 활용

기존 아톰의 값을 기반으로 새로운 값을 계산하거나, 여러 아톰의 값을 조합하여 사용할 때 파생된 아톰을 사용해요. 이는 Redux의 Selector와 유사한 역할을 하며, 복잡한 로직을 아톰 내부에 캡슐화할 수 있게 해줘요.

```tsx showLineNumbers {7-10, 12-15}
// atoms/derived.ts
import { atom } from 'jotai';
import { countAtom } from './counter';

// countAtom의 두 배 값을 가지는 파생 아톰
export const doubleCountAtom = atom((get) => get(countAtom) * 2);

// countAtom과 textAtom을 조합하여 메시지를 생성하는 파생 아톰
export const messageAtom = atom((get) => {
  const count = get(countAtom);
  const text = get(textAtom);
  return `${text}, 현재 카운트는 ${count}입니다.`;
});
```

```tsx showLineNumbers {1, 3, 5, 7, 10-11, 13-14}
// app/components/DerivedDisplay.tsx
'use client';

import { useAtomValue } from 'jotai';
import { doubleCountAtom, messageAtom } from '@/atoms/derived';

export function DerivedDisplay() {
  const doubleCount = useAtomValue(doubleCountAtom);
  const message = useAtomValue(messageAtom);

  return (
    <div>
      <p>카운트의 두 배: {doubleCount}</p>
      <p>메시지: {message}</p>
    </div>
  );
}
```

`useAtomValue` 훅은 아톰의 값만 읽어올 때 사용하며, 업데이트 함수가 필요 없을 때 유용해요. 이를 통해 불필요한 함수 생성 및 전달을 막을 수 있어요.

### 2️⃣ 비동기 아톰 (Async Atoms) 처리

데이터 페칭과 같은 비동기 작업도 아톰 내에서 처리할 수 있어요. `atom`의 `read` 함수에서 `Promise`를 반환하면 Jotai가 자동으로 비동기 상태를 관리해줘요. React의 `Suspense`와 함께 사용하면 로딩 상태를 우아하게 처리할 수 있어요.

```tsx showLineNumbers {7-17}
// atoms/asyncData.ts
import { atom } from 'jotai';

interface Todo {
  id: number;
  title: string;
  completed: boolean;
}

export const todosAtom = atom<Promise<Todo[]>>(async () => {
  const res = await fetch('https://jsonplaceholder.typicode.com/todos?_limit=5');
  if (!res.ok) {
    throw new Error('Failed to fetch todos');
  }
  return res.json();
});
```

```tsx showLineNumbers {1, 3, 5, 7, 9, 11, 13, 16-17, 20-21, 23}
// app/components/TodoList.tsx
'use client';

import { useAtomValue } from 'jotai';
import { todosAtom } from '@/atoms/asyncData';
import { Suspense } from 'react';

function TodoListContent() {
  const todos = useAtomValue(todosAtom);

  return (
    <div>
      <h2>할 일 목록</h2>
      <ul>
        {todos.map((todo) => (
          <li key={todo.id} style={{ textDecoration: todo.completed ? 'line-through' : 'none' }}>
            {todo.title}
          </li>
        ))}
      </ul>
    </div>
  );
}

export function TodoList() {
  return (
    <Suspense fallback={<div>할 일 목록 로딩 중...</div>}>
      <TodoListContent />
    </Suspense>
  );
}
```

이처럼 `Suspense`를 활용하면 비동기 데이터를 불러오는 동안 사용자에게 로딩 피드백을 제공할 수 있어요. 에러 처리는 React `ErrorBoundary`와 함께 사용하면 더욱 견고해져요.

## 🚀 Jotai를 이용한 최적화 및 실무 팁

Jotai는 기본적으로 효율적이지만, 몇 가지 팁을 통해 더욱 최적화된 상태 관리를 할 수 있어요.

### 0️⃣ 아톰의 세분화 (Granular Atoms)

상태를 가능한 한 작고 독립적인 아톰으로 세분화하는 것이 Jotai의 핵심이에요. 하나의 큰 객체 상태를 하나의 아톰으로 관리하기보다는, 객체의 각 필드를 별도의 아톰으로 분리하는 것이 좋아요. 이렇게 하면 해당 필드만 변경될 때 관련 컴포넌트만 리렌더링되어 성능 이점을 극대화할 수 있어요.

예를 들어, 사용자 정보를 나타내는 `userAtom`이 있다고 해볼게요.

```tsx showLineNumbers diff-tsx
// 비효율적인 방법: 큰 객체 아톰
- export const userAtom = atom({ name: '블루', email: 'blue@example.com', age: 30 });

// 효율적인 방법: 세분화된 아톰
+ export const userNameAtom = atom('블루');
+ export const userEmailAtom = atom('blue@example.com');
+ export const userAgeAtom = atom(30);
```

`userNameAtom`만 사용하는 컴포넌트는 `userEmailAtom`이나 `userAgeAtom`이 변경되어도 리렌더링되지 않아요. 이는 불필요한 렌더링을 줄이는 데 큰 도움이 돼요.

### 1️⃣ `useAtomValue`와 `useSetAtom` 활용

`useAtom` 훅은 아톰의 값과 업데이트 함수를 모두 반환해요. 만약 컴포넌트에서 아톰의 값만 필요하거나, 값은 필요 없고 업데이트 함수만 필요할 때는 `useAtomValue`나 `useSetAtom`을 사용하는 것이 좋아요. 이는 컴포넌트가 불필요한 종속성을 가지지 않도록 하여 미묘한 최적화 효과를 가져올 수 있어요.

```tsx showLineNumbers {2-3, 5-6}
// app/components/OptimizedDisplay.tsx
'use client';

import { useAtomValue, useSetAtom } from 'jotai';
import { countAtom } from '@/atoms/counter';

export function OptimizedDisplay() {
  // 값만 필요할 때
  const count = useAtomValue(countAtom);

  // 업데이트 함수만 필요할 때
  const increment = useSetAtom(countAtom);

  return (
    <div>
      <p>현재 카운트: {count}</p>
      <button onClick={() => increment(c => c + 1)}>증가 (useSetAtom)</button>
    </div>
  );
}
```

### 2️⃣ 디버깅과 개발자 도구

Jotai는 개발자 도구 확장을 제공하여 아톰의 상태 변화를 추적하고 디버깅하는 데 도움을 줘요. `jotai-devtools` 패키지를 설치하고 `Provider`에 추가하면, React DevTools에서 아톰의 상태를 확인할 수 있어요.

```bash showLineNumbers
npm install jotai-devtools
```

```tsx showLineNumbers {2, 6, 9}
// app/providers.tsx (JotaiProvider 내부에 추가)
'use client';

import { Provider } from 'jotai';
import { DevTools } from 'jotai-devtools'; // 개발 모드에서만 로드하는 것이 좋아요

export function JotaiProvider({ children }: { children: React.ReactNode }) {
  return (
    <Provider>
      {process.env.NODE_ENV === 'development' && <DevTools />}
      {children}
    </Provider>
  );
}
```

이는 복잡한 애플리케이션에서 상태 변화를 이해하고 문제를 해결하는 데 매우 유용해요.

## 📝 정리하며: Jotai와 함께 더 나은 App Router 개발 경험

Next.js App Router와 Jotai는 서로를 보완하며 현대 웹 개발의 복잡한 상태 관리 문제를 효과적으로 해결해 줄 수 있는 강력한 조합이에요. Jotai의 아톰 기반 접근 방식은 불필요한 리렌더링을 줄이고, 코드의 모듈성을 높이며, 개발자에게 직관적인 상태 관리 경험을 제공해요.

Server Components가 주도하는 App Router 환경에서, Jotai는 클라이언트 컴포넌트 내부의 상태를 정교하게 관리하여 애플리케이션의 성능과 유지보수성을 동시에 잡을 수 있게 도와줘요. 특히 작은 번들 사이즈와 유연한 확장성은 Jotai를 더욱 매력적인 선택지로 만들죠.

### 0️⃣ 핵심 요약

*   **Jotai는 아톰 기반의 경량 상태 관리 라이브러리예요.** 필요한 컴포넌트만 아톰을 구독하여 효율적인 리렌더링을 가능하게 해요.<br />
*   **Next.js App Router 환경에서 Client Component와 함께 사용하며, `Provider`를 `layout.tsx`에 배치할 수 있어요.**<br />
*   **기본 아톰, 파생 아톰, 비동기 아톰 등을 통해 다양한 상태 관리 시나리오에 대응할 수 있어요.** `Suspense`와 `ErrorBoundary`와 함께 사용하면 더욱 견고해져요.<br />
*   **아톰 세분화, `useAtomValue`/`useSetAtom` 활용, 개발자 도구 사용은 Jotai를 더욱 효율적으로 사용하는 팁이에요.**

### 1️⃣ 다음 액션: 직접 경험해 보세요!

이 글을 통해 Jotai의 매력을 느끼셨다면, 직접 여러분의 Next.js 프로젝트에 적용해 보시는 것을 강력히 추천해요. 작은 기능부터 시작해서 점진적으로 Jotai를 도입해 보세요. 분명 더 깔끔하고 관리하기 쉬운 클라이언트 상태 관리 경험을 하실 수 있을 거예요. 언제나 공식 문서를 참고하며 최신 정보를 확인하는 것도 잊지 마세요!
