## 🧐 함수 오버로딩, 왜 필요할까요?

TypeScript를 사용하면서 함수가 다양한 타입의 인자를 받아야 할 때, 어떻게 타입을 정의하고 계신가요?<br />
아마도 유니온 타입(Union Type)을 많이 사용하고 계실 텐데요, 이 방식이 항상 최적의 해결책은 아닐 수 있어요.

### 0️⃣ 다양한 인자 타입 처리의 어려움

예를 들어, 숫자 또는 문자열을 받아 처리하는 함수를 만든다고 가정해 봐요. 유니온 타입을 사용하면 다음과 같을 거예요.

```ts showLineNumbers
function processInput(input: string | number): string | number {
  if (typeof input === 'string') {
    return input.toUpperCase(); // 문자열 처리
  } else {
    return input * 2; // 숫자 처리
  }
}

const result1 = processInput('hello'); // result1의 타입은 string | number
const result2 = processInput(10);    // result2의 타입은 string | number

// 문제점: result1이 문자열임을 확신해도, 타입스크립트는 여전히 string | number로 인식해요.
// 그래서 별도의 타입 좁히기(Type Narrowing)가 필요해요.
const len = (result1 as string).length; // 타입 단언 필요
```

위 코드에서 `processInput` 함수는 인자의 타입에 따라 다른 로직을 수행하고, 반환 타입도 달라져요. 하지만 TypeScript는 `result1`이나 `result2`의 타입을 `string | number`로 추론하기 때문에, 개발자는 반환된 값의 정확한 타입을 알기 위해 추가적인 타입 좁히기나 타입 단언을 사용해야 하는 번거로움이 생겨요. 이는 코드의 가독성을 해치고 잠재적인 오류를 유발할 수 있어요.<br />

### 1️⃣ 더 명확하고 안전한 타입 정의의 필요성

우리가 원하는 것은 '만약 문자열을 넣으면 문자열이 나오고, 숫자를 넣으면 숫자가 나온다'는 명확한 계약을 TypeScript에게 알려주는 거예요. 즉, 함수의 **사용자 관점**에서 더 직관적이고 안전한 타입 정의가 필요하다는 의미죠.<br />
함수 오버로딩은 이러한 요구사항을 충족시켜 주는 강력한 도구예요. 여러 개의 함수 시그니처를 정의함으로써, 함수 호출 시점에 TypeScript가 가장 적절한 시그니처를 선택하도록 하여 더 정확한 타입 추론을 가능하게 해줘요.

## 🚀 TypeScript 함수 오버로딩 핵심 개념

함수 오버로딩을 이해하는 데 가장 중요한 두 가지 개념은 바로 '시그니처(Signature)'와 '구현체(Implementation)'예요. 이 둘의 관계를 정확히 알아야 오버로딩을 제대로 활용할 수 있어요.

### 0️⃣ 시그니처(Signature)와 구현체(Implementation)

<Blockquote type="info">
**시그니처(Signature):** 함수가 어떻게 호출될 수 있는지에 대한 '선언'이에요. 함수의 이름, 인자의 타입과 개수, 반환 타입으로 구성되죠. 마치 함수의 '계약서'와 같다고 생각하시면 돼요. TypeScript는 이 시그니처들을 보고 함수 호출의 유효성을 검사하고 타입을 추론해요.<br />

**구현체(Implementation):** 실제로 함수의 로직이 담겨 있는 '본체'예요. 오버로드된 함수는 여러 개의 시그니처를 가질 수 있지만, 구현체는 반드시 단 하나만 존재해야 해요. 이 구현체는 정의된 모든 오버로드 시그니처를 포괄할 수 있는 타입을 가져야 해요.
</Blockquote>

쉽게 말해, 시그니처는 함수의 '사용 설명서'이고, 구현체는 '실제 작동하는 기계'라고 보시면 돼요. 사용 설명서에는 여러 가지 사용법이 적혀 있을 수 있지만, 기계는 하나만 존재하고 그 모든 사용법을 처리할 수 있어야 하는 거죠.

### 1️⃣ 오버로딩 시그니처 정의하기

오버로딩 시그니처는 함수 본문 없이 타입 선언만으로 이루어져요. 함수가 가능한 모든 호출 패턴을 명시하는 역할을 해요.

```ts showLineNumbers
// 오버로딩 시그니처들
function add(a: number, b: number): number; // 숫자 두 개를 받으면 숫자를 반환
function add(a: string, b: string): string; // 문자열 두 개를 받으면 문자열을 반환
```

위 예시처럼 `add` 함수는 두 가지 방식으로 호출될 수 있음을 TypeScript에게 알려주는 거예요. 각 시그니처는 고유한 인자 타입과 반환 타입을 가져요.

### 2️⃣ 오버로드 구현체 작성하기

구현체는 실제 로직을 담고 있으며, **모든 시그니처를 포괄할 수 있는 타입**으로 정의되어야 해요. 보통 유니온 타입이나 `any` 타입을 활용해서 시그니처에서 정의한 모든 경우의 수를 처리할 수 있도록 만들어요.

```ts showLineNumbers {5-9}
// 오버로딩 시그니처들
function add(a: number, b: number): number;
function add(a: string, b: string): string;
// 오버로드 구현체 (모든 시그니처를 포괄하는 타입)
function add(a: any, b: any): any {
  if (typeof a === 'string' && typeof b === 'string') {
    return a + b; // 문자열 연결
  } else if (typeof a === 'number' && typeof b === 'number') {
    return a + b; // 숫자 덧셈
  } 
  // 모든 시그니처에 해당하지 않는 호출은 컴파일러가 막아줄 거예요.
  // 하지만 구현체 자체는 모든 가능한 케이스를 처리할 수 있어야 해요.
  throw new Error('Invalid arguments provided.');
}

const numResult: number = add(1, 2); // numResult는 number 타입
const strResult: string = add('hello', 'world'); // strResult는 string 타입

// add(1, 'world'); // Error: No overload matches this call.
```

구현체 `add(a: any, b: any): any`는 위에서 정의한 두 시그니처 (`number, number`와 `string, string`)를 모두 처리할 수 있는 가장 넓은 타입으로 정의되었어요. 그리고 내부에서는 `typeof`와 같은 타입 가드를 사용하여 실제 인자의 타입에 따라 적절한 로직을 수행하죠.<br />

<Blockquote type="tip">
구현체의 인자 타입이나 반환 타입은 오버로드 시그니처에 명시된 타입보다 **더 넓은(general) 타입**이어야 해요. 예를 들어, 시그니처가 `string`과 `number`를 받는다면, 구현체는 `string | number`나 `any`를 받아야 하는 식이죠.
</Blockquote>

## 🛠️ 실전 예제로 배우는 함수 오버로딩

이제 몇 가지 실용적인 예제를 통해 함수 오버로딩이 어떻게 실제 코드에서 유용하게 사용될 수 있는지 살펴볼게요.

### 0️⃣ 문자열/숫자를 받아 특정 형식으로 변환하는 함수

`formatValue` 함수를 만들어 문자열이 오면 대문자로, 숫자가 오면 두 배로 변환해 볼게요.

```tsx showLineNumbers {2-3, 5-11}
// 1. 오버로딩 시그니처 정의
function formatValue(value: string): string;
function formatValue(value: number): number;
// 2. 구현체 작성 (모든 시그니처를 포괄)
function formatValue(value: string | number): string | number {
  if (typeof value === 'string') {
    return value.toUpperCase();
  } else if (typeof value === 'number') {
    return value * 2;
  }
  throw new Error('Unsupported value type.');
}

// 사용 예시
const formattedString = formatValue('typescript'); // formattedString: string
const formattedNumber = formatValue(123);        // formattedNumber: number

console.log(formattedString); // "TYPESCRIPT"
console.log(formattedNumber); // 246

// formatValue(true); // Error: No overload matches this call.
```

`formatValue` 함수는 문자열을 받으면 `string`을, 숫자를 받으면 `number`를 반환한다고 명확히 알려주고 있어요. 덕분에 반환 값에 대해 별도의 타입 단언 없이 바로 문자열 메서드나 숫자 연산을 사용할 수 있게 되죠.

### 1️⃣ 객체 속성으로 오버로딩 활용하기

특정 객체에서 속성 값을 가져오는 `getProperty` 함수를 오버로딩으로 구현해 볼게요. 특히, 배열의 인덱스 접근 시에도 유용하게 사용할 수 있어요.

```tsx showLineNumbers {2-5, 7-14}
// 1. 오버로딩 시그니처 정의
function getProperty<T, K extends keyof T>(obj: T, key: K): T[K];
function getProperty(arr: string[], index: number): string; // 배열 특화 오버로드
function getProperty(arr: number[], index: number): number; // 배열 특화 오버로드

// 2. 구현체 작성
function getProperty(obj: any, key: any): any {
  if (Array.isArray(obj) && typeof key === 'number') {
    return obj[key]; // 배열 인덱스 접근
  } else if (typeof obj === 'object' && obj !== null && key in obj) {
    return obj[key]; // 객체 속성 접근
  }
  throw new Error('Invalid arguments or property not found.');
}

// 사용 예시
const user = { name: '블루', age: 10 };
const userName = getProperty(user, 'name'); // userName: string
const userAge = getProperty(user, 'age');   // userAge: number

console.log(userName); // "블루"
console.log(userAge);  // 10

const colors = ['red', 'green', 'blue'];
const firstColor = getProperty(colors, 0); // firstColor: string
console.log(firstColor); // "red"

const numbers = [10, 20, 30];
const secondNumber = getProperty(numbers, 1); // secondNumber: number
console.log(secondNumber); // 20

// getProperty(user, 'email'); // Error: Argument of type '"email"' is not assignable to parameter of type '"name" | "age"'.
// getProperty(colors, 'length'); // Error: Argument of type '"length"' is not assignable to parameter of type 'number'.
```

이 예제에서는 객체의 키에 접근하는 일반적인 제네릭 시그니처와 더불어, `string[]` 또는 `number[]` 배열에 `number` 인덱스로 접근하는 특정 시그니처를 추가했어요.<br />
이를 통해 `getProperty` 함수가 다양한 데이터 구조에 대해 더 정확한 타입 추론을 제공하게 되었죠.

### 2️⃣ 클래스 메서드 오버로딩

클래스 메서드에서도 함수 오버로딩을 동일하게 적용할 수 있어요. `Calculator` 클래스의 `add` 메서드를 오버로딩하여 숫자 덧셈과 문자열 연결을 처리해 볼게요.

```tsx showLineNumbers {3-4, 6-12}
class Calculator {
  // 1. 오버로딩 시그니처
  add(a: number, b: number): number;
  add(a: string, b: string): string;
  // 2. 구현체
  add(a: any, b: any): any {
    if (typeof a === 'number' && typeof b === 'number') {
      return a + b;
    } else if (typeof a === 'string' && typeof b === 'string') {
      return a + b;
    }
    throw new Error('Invalid arguments for add method.');
  }
}

const calc = new Calculator();
const sum = calc.add(5, 3);          // sum: number
const concatenated = calc.add('foo', 'bar'); // concatenated: string

console.log(sum);          // 8
console.log(concatenated); // "foobar"

// calc.add(1, '2'); // Error: No overload matches this call.
```

클래스 메서드도 일반 함수와 마찬가지로 오버로딩 시그니처와 하나의 구현체를 가질 수 있어요. 이를 통해 클래스의 API를 더욱 유연하고 타입 안전하게 설계할 수 있게 돼요.

## ⚠️ 함수 오버로딩 시 주의할 점

함수 오버로딩은 강력한 기능이지만, 몇 가지 주의할 점이 있어요. 이를 간과하면 예상치 못한 타입 오류나 혼란을 겪을 수 있답니다.

### 0️⃣ 구현체의 타입은 모든 시그니처를 포괄해야 해요.<br />

이것은 오버로딩의 가장 중요한 규칙이에요. 구현체의 인자 타입과 반환 타입은 정의된 모든 오버로드 시그니처를 처리할 수 있을 만큼 충분히 넓어야 해요. 만약 구현체가 특정 시그니처를 포괄하지 못하면, TypeScript 컴파일러 오류가 발생할 거예요.

```ts showLineNumbers {3-4, 6-7}
// Error 예시
function process(value: string): string;
function process(value: number): number;
// 구현체가 string만 처리하도록 되어 있어 number 시그니처를 포괄하지 못해요.
function process(value: string): string { // Error: This overload signature is not compatible with its implementation signature.
  return value.toUpperCase();
}
```

위 예시에서 구현체는 `string` 타입만 받도록 되어 있어서 `process(value: number): number;` 시그니처를 만족시키지 못해요. 이 경우, 구현체의 타입을 `value: string | number`와 같이 모든 시그니처를 포괄할 수 있도록 수정해야 해요.

### 1️⃣ 오버로딩 시그니처의 순서가 중요해요.<br />

TypeScript는 오버로드 시그니처를 위에서부터 아래로 순차적으로 평가해요. 따라서 더 구체적인 시그니처를 먼저 배치하고, 더 일반적인 시그니처를 나중에 배치하는 것이 중요해요. 만약 일반적인 시그니처가 먼저 오면, TypeScript는 항상 그 시그니처를 선택해 버려서 구체적인 시그니처가 무시될 수 있어요.

```ts showLineNumbers {2-3, 5-9}
// 올바른 순서 (구체적인 것 -> 일반적인 것)
function greet(name: '블루'): string; // '블루'라는 특정 문자열
function greet(name: string): string; // 모든 문자열
function greet(name: any): any {
  if (name === '블루') {
    return '안녕하세요, 블루님!';
  } else {
    return `안녕하세요, ${name}님!`;
  }
}

const specificGreet = greet('블루'); // specificGreet: string (정확히 '안녕하세요, 블루님!'으로 추론)
const generalGreet = greet('김코딩'); // generalGreet: string

// 잘못된 순서 (일반적인 것 -> 구체적인 것)
// function badGreet(name: string): string; // 이 시그니처가 먼저 오면 항상 이것만 매칭될 수 있어요.
// function badGreet(name: '블루'): string; // 이 시그니처는 절대 도달하지 못할 수 있어요.
// function badGreet(name: any): any { /* ... */ }
```

위 예시처럼 특정 리터럴 타입(`'블루'`)과 일반적인 문자열 타입(`string`)이 섞여 있는 경우, 더 구체적인 리터럴 타입을 먼저 선언해야 TypeScript가 정확하게 매칭할 수 있어요.

### 2️⃣ 복잡한 로직은 피하고, 간결하게 유지해요.<br />

함수 오버로딩은 함수의 API를 명확히 하는 데 도움을 주지만, 구현체 내부 로직이 너무 복잡해지면 오히려 가독성을 해칠 수 있어요. 만약 구현체 내부에서 너무 많은 `if/else if` 문이나 복잡한 타입 가드가 필요하다면, 함수를 여러 개로 분리하거나 다른 디자인 패턴을 고려해 보는 것이 더 좋을 수 있어요.

## 📝 정리하며: 더 견고한 코드 작성을 위해

TypeScript의 함수 오버로딩은 단순한 타입 정의를 넘어, 함수의 계약을 명확히 하고 사용자에게 더 안전하고 직관적인 API를 제공하는 강력한 기능이에요. 시그니처와 구현체의 관계를 정확히 이해하고 올바른 순서로 시그니처를 정의하는 것이 핵심이죠.

### 0️⃣ 핵심 요약

*   **함수 오버로딩**은 하나의 함수가 여러 가지 호출 시그니처를 가질 수 있도록 하여, 인자 타입에 따라 다른 반환 타입을 명시적으로 지정할 수 있게 해줘요.<br />
*   **시그니처(Signature)**는 함수의 호출 계약을 선언하며 여러 개가 존재할 수 있어요. 사용자 관점의 타입 안전성을 높여주죠.<br />
*   **구현체(Implementation)**는 실제 함수의 로직을 담고 있으며, 오직 하나만 존재해야 해요. 모든 시그니처를 포괄할 수 있는 타입을 가져야 해요.<br />
*   **구체적인 시그니처**를 **일반적인 시그니처**보다 먼저 선언해야 정확한 타입 추론이 이루어져요.

### 1️⃣ 다음 액션

이제 여러분의 코드에서 `string | number`와 같은 유니온 타입으로 인해 타입 좁히기가 번거로웠던 함수들을 찾아보세요.<br />
함수 오버로딩을 적용하여 더 명확하고 타입 안전한 API로 개선해 본다면, 코드의 가독성과 유지보수성이 크게 향상되는 것을 경험하실 수 있을 거예요.<br />
